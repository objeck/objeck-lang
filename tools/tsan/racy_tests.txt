# Regression tests that tools/tsan/run_tsan.sh leaves out, one name to a line.
#
# A test goes here only when a ThreadSanitizer run of it can say nothing useful:
# a report that is already understood, that tsan.supp cannot express and that
# tsan_reports.py does not set aside, or a test the instrumented VM cannot pass.
# Each entry says which. The tests still run in every other suite.
#
# NOT here: a program that only races on its own fields (a polled flag, a
# counter, a library's lazily created static). tsan_reports.py recognises that
# report by its shape (both accesses are the interpreter's field instructions)
# and does not count it, so those tests keep running for what else they exercise:
# the collector, the JIT and the thread lifecycle under them. On 2026-11-27 they
# were agent_scope_outlived_parent_test, gc_cond_value_threads,
# interact_spawn_lambda_self, ml_vector_parallel (every query on a shared
# VectorIndex clears its @error), query_expr_concurrent, query_index_concurrent,
# query_thread_errors and query_server_concurrent (Web.HTTP.Server.WebServer
# stores its unchanged @connection_mutex on every accept).
#
# No longer here (2026-11-27): diag_concurrent_analysis and onnx_concurrency (the
# libraries now make their shared proxy and names under a lock) and
# tls_close_races (the socket's connected word is read with its context, under
# tls_context_lock).

# --- too slow under the instrumented VM ---
socket_server_stop_exit_time       # times its own exit from outside (under a second); the instrumented VM takes longer,
                                   # so it fails there whatever the VM does. What it races -- Close() on a listener
                                   # under Accept() -- is run by socket_close_races, which has no clock in it
