Learned today, in addition to section 3:

- **A version bump on master makes the Windows deploy tree lie.** The rebuilt `obc` carries the new `VER_NUM`; the tree's `lang.obl` and the diags DLL (which embeds the compiler) carry the old one, so every test "fails to compile" and `diag_*`/`lsp_*` fail at runtime. - **Reproduce few-core CI on a many-core box with affinity**, not with thread counts: `cmd /c start /affinity F /b /wait obr.exe ...`. The bug never showed unpinned on 32 threads.
- **Experiment in a sandbox copy of `deploy-x64/bin` + `lib`** under the scratchpad while the regression runner reads the real tree; build fixes in a separate `git worktree`. Nothing in the tree moves during a pass that way.
- **The toolchain is VS 18 (2026) Professional**, `C:\Program Files\Microsoft Visual Studio\18\Professional\VC\Auxiliary\Build\vcvarsall.bat`; `vswhere` is not on `PATH`. From PowerShell, drive long runs through a wrapper `.cmd` (`cd /d` + full paths + a `.done` file) started with `Start-Process`; `cmd /c` inherits nothing from `Set-Location`.
- Checked and not a second bug: JIT method inlining is complete but never called, so the post-callback reload restoring the *caller's* `self` inside an inlined body is unreachable. If inlining is ever switched on, that reload must become inlining-aware first.

One more trap, on top of section 3's: **an `obc` compile that writes no output file can still exit 0**, and `obr` then prints `Unable to open file: ...`. Three such lines compare byte-identical to each other, so an "interpreter vs JIT equivalence" check over them reports a perfect match while proving nothing. It happened again here through a shell-quoting slip that mangled the `-dest` path. Always assert the `.obe` exists before running it, and sanity-check that the output has the size and first line you expect.

**Later on 2026-09-10, the register-argument entry** (F7, design section 11, [PR #765](https://github.com/objeck/objeck-lang/pull/765)): every compiled method has two prologues over one body -- the bridge entry at offset 0 for `JitRuntime::Execute`, and a native entry a compiled caller enters with `self` and its frame pointer in registers and the arguments in the caller's outgoing area, the frame record built in the callee's frame, the result in `XMM0`. Bound call 7.0 to 5.5 ns, virtual 8.0 to 6.0 ns, `Fib(32)` 0.072 to 0.043 s, func-ref calls halved. AMD64 only; ARM64 keeps the bridge entry. The one bug the suite found on the way: a method whose result a callback leaves on the operand stack (`Runtime->Copy`, hence `SubString`) has nothing on the JIT's working stack at `RTRN`, and the native exit must pop the operand stack into `XMM0` -- the rule is now in the design and in `vm_jit_equiv.obs` (`CopyResults`). Remaining as before: the ARM64 track on the Mac (now phases 2, 3 and the entry), compiler bug #763, the v2026.9.1 release.

## 0. The bug this plan was written for, and the two rules it left behind

**Found, fixed and merged the same day** ([#746](https://github.com/objeck/objeck-lang/issues/746),
[PR #748](https://github.com/objeck/objeck-lang/pull/748)). A compiled method keeps its own copy of
`self` in its native frame. When a minor collection promotes a young object the collector relocates
the frame's `mem[0]`, but it cannot see that private copy; only the callback path re-read it. A
thread that parked at a loop-header safepoint while *another* thread's collection moved its `self`
therefore kept addressing fields through the old nursery address for the rest of the loop. Reads
returned whatever the recycled nursery held; writes landed in other threads' objects, which is how
one worker corrupted another's list. The poll's slow path now performs the same reload the callback
path does, on both backends, and `core_thread_gc_stress.obs` runs compiled on all five CI legs.

Two rules came out of it, and both outlive the bug.

**A test that opts itself out silently is worse than no test.** This one reported 35-45 corrupted
values on every CI leg the moment it actually ran compiled, and it had never run compiled: both
runners matched the opt-out marker as a *substring*, and the test's own comment -- warning against
adding that marker -- contained it. The comment arrived with 5673cf0d71 (2026-06-11), the commit
fixing the stop-the-world GC bugs the test guards, so those fixes were only ever verified
interpreted, for three months. The runners now match a directive line, every directive must state a
reason, and `tools/cicd/check_jit_optouts.py` enforces both (#745).

**Every path on which compiled code can park must re-read `INSTANCE_MEM` from `frame->mem[0]` before
the next instruction runs.** The callback path always did; the safepoint poll never did, from the
moment the poll first started firing. Any park point added later inherits the obligation. It is
stated in `core/vm/arch/jit/README.md` beside the callback bridge, where whoever adds the next one
will be reading.

Neither rule showed itself on a 32-thread developer box, where the test passes. Pinning to four
cores (`start /affinity F`) is what made it reproduce, and then it reproduced every run.

## 3. Rules that were learned the hard way today (all in memory, repeated here)

- **The regression runner reads the live tree.** No `git checkout`, `rebase`, `pull` or edits
  under `programs/regression` or `core/release` while a pass runs; two runs were spoiled that way.
- **A marker is a directive line.** Never quote `# JIT_DISABLE` in a test comment; say "the JIT
  opt-out marker". `check_jit_optouts.py` now enforces it, and a directive needs a `# reason:`.
- **`obc` errors have no word "error"** — they look like `file:(line,col): message`. Filter
  compiler output by excluding the success lines, or a failed compile looks like success and the
  interpreter/JIT "equivalence" compares two "Unable to open file" lines (that happened).
- Objeck: `label` and `other` are reserved words; an indexed expression cannot sit inside `{$…}`
  interpolation; `(expr)->Method()` does not parse — bind to a local; `[[…],[…]]` is a 2-D array
  (`a[i,j]`), not an array of arrays, and indexing it as one allocated garbage.
- `cmd /c` launched from PowerShell does not inherit `Set-Location`; use full paths.
- `findstr` cannot anchor the end of an LF-ended line (`/E`, `/X`, `$` all fail); `/B` works.
- Merges happen only on the maintainer's explicit word; PRs target `master` (stacked PRs get no
  build legs); design paragraph first; probes that fail before; both regression passes; one
  commit per concern; CHANGELOG entry per user-visible change; never a bare `git stash`, never a
  force-push, never credentials anywhere, never signing in a workflow.

## 4. PR body draft for batch 6b (when its suite is clean)

> Batch 6, part 2: the hottest `Float` locals of a loop live in `XMM6`–`XMM9` on Windows.
> Phase 4d of loop-local pinning, design in `docs/JIT_LOOP_LOCALS_DESIGN.md` section 5a. The same
> planner, entry loads, write-back and exit stubs as the `R13`–`R15` integer pins, with a second
> slot list per region: up to four `Float` locals per loop stay in callee-saved XMM registers for
> the loop's extent. Windows only — POSIX XMMs are caller-saved, so nothing changes there; ARM64's
> `D8`–`D15` are the follow-up. A load of a pinned slot copies the register into a fresh pool XMM,
> a store moves into the pin, `ReleaseXmmRegister` refuses a pinned register, and loads of pinned
> slots never produce `MEM_FLOAT`, so the deferred-load materialization and the float cache never
> touch one. `FloatDot`: 0.048 s → 0.021 s; `Locals` (integer only) unchanged. Six `FloatPins`
> probes in `vm_jit_equiv.obs`, byte-identical across all three modes; flag tests 22/22; the
> regression suite in both modes.
