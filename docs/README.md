# Objeck documentation

Every page in this directory, grouped by who reads it. **New here? Read [ARCHITECTURE_MAP.md](ARCHITECTURE_MAP.md)** for how the parts fit, then the page for the part you are touching. Pages with a code-level audience point back to the map.

Design records carry a **status**, checked against the code when this index was written:

| Status | Meaning |
|---|---|
| **built** | implemented; the page is kept as the record of why it looks the way it does |
| **partly built** | some of it is in the tree; the page says which |
| **proposed** | not built; a plan or a proposal awaiting a decision |
| **deferred** | the maintainer put it off or changed its shape |
| **snapshot** | a dated measurement or assessment; the code has moved since |
| **working** | a living document that is edited as the work goes |

Reference pages (how the system is today) have no status: they are expected to match the code, and the scripts in `tools/cicd/` (`check_doc_lists.py`, `check_docs_deps.py`, `check_doc_links.py` and others) enforce what can be checked mechanically. If a reference page and the code disagree, the code is right and the page is a bug.

## What is not documentation

Several things in this directory are **build inputs or shipped artifacts**, not pages to read here. GitHub renders `.html` as source, so opening them in the file browser shows markup rather than a page: they are not broken, they are simply not meant to be read on GitHub.

> **Looking for the release notes?** Read **[CHANGELOG.md](../CHANGELOG.md)** in the repository root. `readme.html` and `readme.txt` in this directory are *generated forms of the same content*, for the website and the installer.

| | |
|---|---|
| `readme.html`, `readme.txt` | The release notes, rendered for shipping. `deploy_windows.cmd` copies `readme.html` into the install tree, where `style/` sits beside it and it displays properly. The source of truth is [CHANGELOG.md](../CHANGELOG.md) |
| `web/` | The **published site**. This is what GitHub Pages builds: see `.github/workflows/jekyll-gh-pages.yml`, which sets `source: ./docs/web`. Nothing else in this directory is published |
| `style/`, `images/`, `syntax/` | Assets for the above, and editor syntax definitions |
| `api.zip` | Pre-built API docs, unpacked into the install tree by the ARM64 deploy, which cannot run the doc generator while cross-compiling |
| `eula.rtf` | Licence text for the installer |

If you want the rendered documentation rather than the sources, use the published site rather than this directory.
