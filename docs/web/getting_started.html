Installation

Objeck can be installed using the Windows or macOS installers, a .deb package on Ubuntu 24.04, or compressed archives. Supported platforms are Windows (x64 and ARM64), macOS (Apple Silicon) and Linux (x64 and ARM64).

In order to compile programs outside of the 

bin
directory the 
OBJECK_LIB_PATH
environment variable must be set. When this variable is set all library files must be in the directory specified. If the Windows installer is used these variables will be automatically when you launch the Objeck command prompt.

Windows

To manually setting the environment paths in Windows: 

> set OBJECK_LIB_PATH=C:\Users\[account]\objeck-lang\lib
> set PATH=%PATH%;C:\Users\[account]\objeck-lang\bin;C:\Users\[account]\objeck-lang\lib\sdl

Ubuntu 24.04 (.deb)

On Ubuntu 24.04 LTS and distributions built on it (Linux Mint 22, Pop!_OS 24.04), download the .deb for your architecture from the latest release and install it with apt, which also installs the system libraries the toolchain needs. The commands are on PATH in every shell, with nothing to set: 

> sudo apt install ./objeck-ubuntu24.04-*.deb      # the x64 or arm64 file you downloaded
> obc hello && obr hello

OpenCV, SDL2, unixODBC and LAME are recommended rather than required: they are needed only by the libraries that wrap them, and --no-install-recommends leaves them out. sudo apt remove objeck uninstalls. Upgrade by installing the next release's .deb; obu update is disabled for an apt install. Other distributions use the archive below.

macOS and Linux

To manually setting the environment paths in macOS and Linux: 

> export PATH=$PATH:/home/[account]/objeck-lang/bin
> export OBJECK_LIB_PATH=/home/[account]/objeck-lang/lib

Linux and macOS Runtime Dependencies

The pre-built Linux binaries dynamically link system libraries the archive does not ship: mbedTLS (crypto and TLS), readline, SDL2 and OpenGL, OpenCV, unixODBC and LAME. On a clean machine obr does not start until they are installed. On Linux, run the script at the root of the distribution: 

> cd objeck-lang
> ./install_deps.sh

It runs ldd on the tools in bin and the libraries in lib/native, looks up the package for each library that does not load with your package manager (apt, dnf/yum, pacman, zypper), and installs those packages. It asks first; --yes skips the prompt, and --check only reports. Package names differ between distributions (Ubuntu 24.04's libmbedtls14t64 is libmbedtls14 on Debian 12), which is why it looks them up rather than using a fixed list. Releases are built on Ubuntu 24.04 and need glibc 2.38 or newer, so Debian 12 (glibc 2.36) is too old. If your distribution packages different library versions or has an older C library, the script says so. Build from source there.

On macOS, nothing needs installing: the package carries every library it uses, including OpenCV, ONNX Runtime, mbedTLS, ODBC and LAME. The toolchain runs on macOS 13.3 and later; the ONNX binding needs macOS 14.

Compiling Code

The Objeck compiler produces two types of binaries. The first is a VM executable and the second is a library. Libraries can be linked to executables by passing the names of libraries to the compiler when compiling an executable. As a naming convention executables end with *.obe while shared libraries end with *.obl.

Here are a few examples. The first example compiles and runs a program that processes XML. For this program we link in the collections and XML parsing libraries. 

> obc -src examples/2_xml.obs -lib xml
> obr xml_path.obe

The next example compiles and runs program that uses the encryption library. 

> obc -src examples/7_encrypt.obs -lib encrypt
> obr encryption.obe

Basics

Let's first look at literals, variables, comments, control flow and basic data types.

Literals and variables

Literals are defined as they are in most programming languages. In Objeck literals are treated as objects and may have methods associated with them. 

'\u00BD'->PrintLine();
13->Min(3)->PrintLine();
3.89->Sin()->PrintLine();
0xCB0->PrintLine(); # hex
-0b1101->PrintLine(); # bin
0o52->PrintLine(); # oct
1_000_000->PrintLine(); # underscores are ignored
"Hello World"->Size()->PrintLine();

Octal literals take a 0o prefix, as hexadecimal takes 0x and binary 0b. An integer literal of more than one digit may not start with 0: 010 is a compile error that suggests 0o10 (octal 8) or 10, so a leading zero can never silently change a value. 0 on its own and floats such as 0.5 are unaffected.

A u (or U) suffix reads an integer literal across the whole unsigned range and keeps its bit pattern, which is how values above the signed maximum are written. The suffix only changes how the number is read — the value is an ordinary Int, so there is no separate unsigned type. Hexadecimal and binary literals are read the same way, since they already denote bit patterns. 

0xFFFFFFFFFFFFFFFF->PrintLine(); # -1: every bit set
0xFFFFFFFFFFFFFFFFu->PrintLine(); # the same value, written explicitly
18446744073709551615u->PrintLine(); # 2^64-1 in decimal, also -1
mask := 0x00000000FFFFFFFFu; # a full-width mask

A literal that does not fit is rejected at compile time rather than silently clamped.

Because every integer occupies a signed 64-bit slot, >> copies the sign bit into the high end. When a value is being used as a bit pattern rather than as a number, >>> shifts a zero in instead. It sits at the same precedence as >> and is left-associative. 

(-8 >> 3)->PrintLine();  # -1: the sign bit is copied down
(-8 >>> 3)->PrintLine(); # 2305843009213693951: zeros shift in
(-1 >>> 63)->PrintLine(); # 1: only the former sign bit is left
(-1 >>> 64)->PrintLine(); # -1: counts are taken modulo 64, like every shift

Int also carries operations that read both operands as unsigned 64-bit quantities, for the cases where the signed reading of the same bits is the wrong one. 

Int->ToUnsignedString(-1)->PrintLine(); # 18446744073709551615
Int->DivideUnsigned(-1, 3)->PrintLine(); # 6148914691236517205
Int->ModUnsigned(-1, 10)->PrintLine();  # 5
Int->CompareUnsigned(-1, 1)->PrintLine(); # 1: -1 is the largest unsigned value

Here are a few examples of variable declarations and assignments. Variable types can be explicitly defined or implicitly inferred through assignments or casts. If a variable's type is inferred it cannot be redefined later in the program however it can be cast. 

a : Int;
b : Float := 13.5;
c := 7.25; # type inferred as Float
d := (b * 2)->As(Int); # type inferred as Int

Also support for multi-variable assignment and negation. 

a, b : Float := 13.5;
b += -a * 13;
"{$b}"->PrintLine();
a := b := c := 3.15;
"{$a} {$b} {$c}"->PrintLine();
d := a < b ? "less" : "greater"; # conditional operator

Types can also be described and referenced using aliases. 

function : Multiplier(a : FloatRef, b : FloatRef) ~ \Func->Proc {
  return \Func->Proc : (c) =>  a * b * c;
  }
}

alias Func {
  Proc : (FloatRef) ~ FloatRef
}

Control Flow

As with most languages Objeck supports conditional expressions and control flow logic. One nuance is that conditional statements end with semi-colons.

If/else

An "if/else" statement is a basic control statement. 

number := Console->ReadLine()->ToInt();
if(number <> 3) {
 "Not equal to 3"->PrintLine();
} else if(number < 13) {
 "Less than 13"->PrintLine();
} else {
 "Some other number"->PrintLine();
};

Select

Select statements can be used to efficiently map integer and enum values to blocks of code. 

select(c) {
 label Color->Red: { "Red"->PrintLine(); }
 label Color->Green: { "Green"->PrintLine(); }
 label Color->Purple: { "Purple"->PrintLine(); }
 other: { "Another color"->PrintLine(); }
};

select(n) {
 label 9:
 label 19: { n->PrintLine(); } 
 label 0x1b: { (3 * 9 = n)->PrintLine(); }
};

The language supports for the following looping statements

Do/While

A "do/while" loop is a basic post-test loop. 

i := 0;
do {
 i->PrintLine();
 i += 1;
} while(i <> 10);

For

A "for" loop is a controlled loop with an explicated control expression. 

location := "East Bay";
for(i := 0; i < location->Size(); i += 1;) {
 location->Get(i)->PrintLine();
};

For loops also support multiple initialization and update statements separated by commas. 

# multi-statement for loop
for(i := 0, j := 10; i < j; i += 1, j -= 1;) {
  "i={$i}, j={$j}"->PrintLine();
};

Each

An "each" loop is a controlled loop that iterates though all elements in an array or collection. Items can also be iterated in reverse using the "reverse" keyword. 

area_code := Int->New[3];
area_codes := Int->New[3];
area_codes[0] := 5;
area_codes[1] := 1;
area_codes[2] := 0;

sum := 0;
each(i : area_codes) {
 sum += area_codes[i];
};
sum->PrintLine();

Reverse

The "reverse" keyword iterates items in reverse. 

numbers := [1, 2, 3, 4, 5];
reverse(i : numbers) {
	numbers[i]->PrintLine();
};

An "each" or "reverse" loop can also bind to a variable using the assignment operator instead of a colon. 

strings := Generic.Vector->New()<String>;
strings->AddBack("abd");
strings->AddBack("efg");
strings->AddBack("hij");
strings->AddBack("lmn");

reverse(string := strings) {
	string += ", 123";
	each(letter := string) {
		letter->PrintLine();
	};
};

Leaving

The "leaving" keyword is used to execute a block of code at the end of method/function 


function : WriteSocket(bytes : Byte[]) ~ Nil {
	client := TCPSocket->New("localhost", 4660);
	leaving {
		client->Close();
	};

	if(client->IsOpen()) {
		size := bytes->Size();
		size_str := size->ToString();
		client->WriteString(size_str);
		client->WriteBuffer(0, size, bytes)->PrintLine();
	};
}

  function : IsValid(cc : String) ~ Bool {
    isOdd := true; oddSum := 0; evenSum := 0;

Nil-safe operators

?-> calls a method only when the receiver is non-Nil, yielding Nil rather than faulting. ?? supplies a value when its left side is Nil, and evaluates the right side only when it has to. 

# guarded call: Nil instead of a fault if person or the address is Nil
city := person?->GetAddress()?->GetCity();

# default when the left side is Nil
name := lookup ?? "(unknown)";

# a single '?->' guards the whole rest of the chain
text := maybe?->Trim()->ToUpper();

# a chain ending in a value type needs '??', since an Int cannot be Nil
size := maybe?->ToUpper()->Size() ?? -1;

Both build on the Try()/Otherwise() methods: a?->b() is a->Try()->b() and a ?? b is a->Otherwise(b). One consequence worth knowing is that Try() guards against any runtime error in the chain, not only a Nil dereference — so a?->Get(999) yields Nil on an out-of-range index instead of faulting.

The language has support for dynamically allocated arrays, Unicode strings and various containers.

Arrays

Arrays can hold an indexed list of like types. Arrays are dynamically allocated from the heap and their memory managed by the garbage collector. The runtime system supports bounds checking and will cease execution (generating a stack trace) if array bounds are violated.

Allocating and indexing arrays 

# allocate Int array
boxes := Int->New[2,3];
boxes[0,0] := 2;
boxes[0,1] := 4;
boxes[0,2] := 8;
boxes[1,0] := 1;
boxes[1,1] := 2;
boxes[1,2] := 3;
dims := boxes->Size(); # get the dimensions
dims[0]->PrintLine(); # dimension 1
dims[1]->PrintLine(); # dimension 2

# create some strings an iterate over them
directions := String->New[4];
directions[0] := "North";
directions[1] := "South";
directions[2] := "East";
directions[3] := "West";
each(i : directions) {
  directions[i]->PrintLine();
};

Jagged arrays

Int[][] is an array of rows, and each row can have its own length. An array literal whose elements are arrays is a jagged array too. 

rows := Int[]->New[3];
each(i : 3) {
  rows[i] := Int->New[i + 1];
  for(j := 0; j <= i; j += 1;) {
    rows[i][j] := i * 10 + j;
  };
};
each(i : 3) {
  row := rows[i];
  "row {$i} has {$(row->Size())} items, last is {$(row[row->Size() - 1])}"->PrintLine();
};

Strings

Character strings are a collection of Unicode characters backed by the String class. The string class supports a number of operations such as insert, find, substring, type parsing (i.e. String to Float), etc. Variable values can also be inlined into string literals. Strings can be converted into character arrays and UTF-8 byte arrays. The $ character can be used to interpret strings verbatim, ignoring escape characters. 

name := "DJ";
name += ' ';
name += "Premier";
name += $"bell \b \b bell";
name->PrintLine();
name->SubString(2)->PrintLine();
name->Size()->PrintLine();

Code fragment from a sundial program 

"Hour\t\tsun hour angle\t\tdial hour line angle from 6am to 6pm"->PrintLine();
for(h := -6; h <= 6; h+=1;) {
  hra := 15.0 * h;
  hra -= lng - ref;
  hla := (slat* (hra*2*Float->Pi()/360.0)->Tan())
    ->ArcTan() * 360.0 / (2*Float->Pi());
  "HR={$h}\t\tHRA={$hra}\t\tHLA={$hla}"->PrintLine();
};

String Interpolation

Values can be embedded directly into string literals using the {$...} syntax — a cleaner alternative to manual concatenation. The braces may hold any expression: a bare variable, a field, an arithmetic / comparison / logical expression, an array access, or a method call. 

name := "Objeck";
version := 2026;
"Welcome to {$name} v{$version}!"->PrintLine();   # Welcome to Objeck v2026!

i := 41;
a := 3; b := 4;
"next  = {$i + 1}"->PrintLine();                  # next  = 42
"area  = {$a * b}"->PrintLine();                  # area  = 12
"even? = {$i % 2 = 0}"->PrintLine();              # even? = false
"upper = {$name->ToUpper()}"->PrintLine();        # upper = OBJECK

Append :spec to an interpolated expression to control precision, width, alignment, or radix, using Python / .NET–style format specifiers. 

pi := 3.14159; n := 42; v := 255; s := "hi";
"{$pi:.2}"->PrintLine();    # 3.14       precision
"[{$n:5}]"->PrintLine();    # [   42]    minimum width, right-justified
"{$n:05}"->PrintLine();     # 00042      zero-padded
"[{$s:<6}]"->PrintLine();   # [hi    ]   left-justified
"[{$s:>6}]"->PrintLine();   # [    hi]   right-justified
"{$v:x}"->PrintLine();      # 0xff       hexadecimal
"{$v:b}"->PrintLine();      # 11111111   binary

For a positional template — handy when the format string is reused or built at runtime — use String->Format. The placeholders {0}, {1}, … are replaced by the matching argument; {{ and }} produce literal braces. 

String->Format("{0} = {1}", "x", "y")->PrintLine();      # x = y
String->Format("{1} before {0}", "a", "b")->PrintLine(); # b before a

The $ prefix before a string literal instead treats it as a verbatim string, ignoring escape characters like \n and \t. 

path := $"C:\Users\objeck\files";
path->PrintLine(); # prints: C:\Users\objeck\files

Bundles and Use Statements

Bundles are Objeck's module system for organizing related classes, interfaces, and enums into namespaces. The use keyword imports a bundle so its members can be referenced without fully qualified names. 

# without 'use' — fully qualified names required
list := Collection.List->New()<String>;
parser := Data.JSON.JsonParser->TextToElement(text);

# with 'use' — shorter references
use Collection;
use Data.JSON;

list := List->New()<String>;
parser := JsonParser->TextToElement(text);

You can define your own bundles to organize code into logical namespaces. 

bundle App.Models {
  class User {
    @name : String;

    New(name : String) {
      @name := name;
    }

    method : public : GetName() ~ String {
      return @name;
    }
  }
}

The use function form allows importing static functions directly so they can be called without the class prefix. 

use function Int;

# call Int functions directly
value := Abs(-42);
max := Max(10, 20);

Classes and Interfaces

A class is an abstract collection of data with related operations. An interface is a set of operations (a contract) that implementing classes must honor. In Objeck, interfaces are public and classes may be public or private. Member variables are private and must accessed using "getters" and "setters". Classes may also define enum types.

Below is a code example of that demonstrates many of these concepts. There are code examples for other features such as reflection, serialization and more. 

interface Registration {
  method : virtual : public : GetColor() ~ String;
  method : virtual : public : GetMake() ~ String;
  method : virtual : public : GetModel() ~ String;
}
enum EngineType {
  Gas := 200,
  Hybrid,
  Electric,
  Warp
}

  @wheels : Int;
  @color : String;
  @engine_type : EngineType;

    @wheels := wheels;
    @color := color;
    @engine_type := engine_type;
 }
 
 method : public : GetColor() ~ String {
   return @color;
 }
 
 method : public : GetEngine() ~ EngineType {
   return @engine_type;

Vectors are arrays that can be dynamically resized. They support fast indexing, iterating and appending of values. In order to improve performance memory for vectors is preallocated.

Lists are a collection of linear linked nodes. They support the fast insertion and removal of values. Memory for nodes are allocated on-demand however nodes may not be directly indexed as with Vectors.

Query.Structured is a columnar database in the standard library. Closures and Lambda Expressions

First class functions allow programmers to use functions like variables. They can be passed into methods/functions, have methods/functions return functions and be assigned to variables. In addition, Objeck supports closures and lambda expressions . 

class FofG {
  @f : static : (Int) ~ Int;
  @g : static : (Int) ~ Int;

  function : Main(args : String[]) ~ Nil {
    compose := Composer(F(Int) ~ Int, G(Int) ~ Int);
    compose(13)->PrintLine();
  }

  function : F(a : Int) ~ Int {
    return a + 14;
  }
 
  function : G(a : Int) ~ Int {
    return a + 15;
  }
 
  function : native : Compose(x : Int) ~ Int {
    return @f(@g(x));
  }

  function : Composer(f : (Int) ~ Int, g : (Int) ~ Int) ~ (Int) ~ Int {
    @f := f;
    @g := g;
    
    return Compose(Int) ~ Int;
  }
}

Lambda expressions allow programmers to create anonymous functions and assign references to these functions. Such functions can be used for inline calculations and programming logic. In addition to expressions, the language supports lambdas expressions that contain 'if' and 'select' statements and return a value. 

vector := Vector->New()<Func2Ref <FloatRef, FloatRef> >;
# store functions in collections
vector->AddBack(Func2Ref->New(\Func->Double : (v) 
  =>  v * v)<FloatRef, FloatRef>);
# new function from preexisting function at run-time
vector->AddBack(Func2Ref->New(\Func->Double : (v) 
  => Float->SquareRoot(v->Get()))<FloatRef, FloatRef>);
# process collection
each(i : vector) {
  # return value of other functions and pass argument to other function
  Show(vector->Get(i)<Func2Ref>->Get()<FloatRef, FloatRef>);
};

Objeck supports closures by allowing the value of local variables to captured and used in later invocations of code. 

funcs := Vector->New()<FuncRef<IntRef> >;
# create 10 functions capturing i     
for(i := 0; i < 10; i += 1;) {
  funcs->AddBack(FuncRef->New(\() ~ IntRef : () => i * i)<IntRef>);
};
# invoke functions
each(i : funcs) {
  func := funcs->Get(i)->Get()<IntRef>;
  func()->Get()->PrintLine();
};

As of v2026.6.3, lambdas have a simplified form. A bare lambda \(...) => body infers its return type from context and auto-wraps into a FuncRef<R> when it is assigned, returned, passed as an argument, or stored in a collection — no explicit FuncRef->New(...)<R> wrapper or ~ R : annotation is needed. A FuncRef can be called directly with v() (no ->Get()/->Call() step), and the body may be a single expression or a { ... } block of statements ending in a return. 

# bare lambda; return type inferred from the FuncRef<IntRef> target, called directly
f : FuncRef<IntRef> := \() => IntRef->New(5);
f()->Get()->PrintLine();          # 5

# block body: arbitrary statements with a return; auto-wrapped into the collection
funcs := Vector->New()<FuncRef<IntRef> >;
each(i : 5) {
  funcs->AddBack(\() => {
    acc := IntRef->New(0);
    for(k := 0; k < i; k += 1;) { acc->Set(acc->Get() + k); };
    return acc;
  });
};
# call each FuncRef directly
each(i : funcs) {
  f := funcs->Get(i);
  f()->Get()->PrintLine();
};

Lambda parameters types can also be inferred using the modified syntax below. 

map := Map->New()>IntRef, String>;
map->Insert(1, "One");
map->Insert(3, "Three");
map->Insert(5, "Five");
map->Insert(7, "Seven");
map->Insert(9, "Nine");

Named Arguments and Reference Parameters

Pass an argument by name with name: value. Positional arguments come first, named ones follow in any order, and any parameter that has a default value can be skipped. Arguments are still evaluated in the order they are written. Named arguments work for your own methods and constructors and for the standard library, so the standard library's parameter names are part of its public API. 

function : Train(data : String, rate : Float := 0.1, epochs : Int := 10) ~ Nil {
  "{$data}: rate={$rate} epochs={$epochs}"->PrintLine();
}

# arguments by name, in any order; a defaulted parameter can be skipped
Train("sales", epochs: 50);
Train("sales", epochs: 5, rate: 0.5);

A ref parameter is copied in and copied back out, like inout in Swift. Write ref at the call site too. A local variable, a parameter or a field can be passed. 

function : Swap(ref a : Int, ref b : Int) ~ Nil {
  t := a;
  a := b;
  b := t;
}

x := 1;
y := 2;
Swap(ref x, ref y);
"x={$x} y={$y}"->PrintLine(); # x=2 y=1

Error Handling

Objeck provides two mechanisms for handling runtime errors: the leaving keyword for guaranteed cleanup, and the try/otherwise framework for recovering from errors such as Nil dereferences and array bounds violations.

Leaving

The leaving block ensures cleanup code runs when a method or function exits, regardless of how it exits. This is similar to finally in other languages. 

# leaving block ensures cleanup runs when method exits
function : ProcessFile(name : String) ~ Nil {
  reader := System.IO.Filesystem.FileReader->New(name);
  leaving {
    reader->Close();
  };

  content := reader->ReadFile();
  if(content <> Nil) {
    content->PrintLine();
  };
}

Try/Otherwise

The try/otherwise construct catches runtime errors and allows the program to recover gracefully. If an error occurs inside a try block, execution transfers to the otherwise block instead of terminating the program. 

class ErrorExample {
  function : Main(args : String[]) ~ Nil {
    # attempt an operation that may fail
    try {
      value : String;
      value->Size()->PrintLine(); # Nil dereference
    }
    otherwise {
      "Error: recovered from Nil dereference"->PrintLine();
    };

    "Program continues..."->PrintLine();
  }
}

Combining try/otherwise with leaving provides both error recovery and guaranteed resource cleanup.

Typed errors

Derive from Error to define your own errors, raise one with Runtime->Raise, and catch it by type with try { } on(e : Type) { } finally { }. Clauses are tested in order, an error that no clause names carries on after the finally block, and return, break and continue leave through finally. The runtime's own faults are NilError, IndexError, DivideByZeroError, CastError and RuntimeError. 

class ParseError from Error {
  @line : Int;

  New(message : String, line : Int) {
    Parent(message);
    @line := line;
  }

  method : public : GetLine() ~ Int {
    return @line;
  }
}

class ErrorExample {
  function : Parse(line : Int) ~ Int {
    if(line % 2 = 1) {
      Runtime->Raise(ParseError->New("bad row", line));
    };
    return line;
  }

  function : Main(args : String[]) ~ Nil {
    each(i : 4) {
      try {
        "row {$(Parse(i))} ok"->PrintLine();
      }
      on(e : ParseError) {
        "row {$(e->GetLine())}: {$(e->GetMessage())}"->PrintLine();
      }
      finally {
        "checked row {$i}"->PrintLine();
      };
    };
  }
}

Output: row 0 ok, checked row 0, row 1: bad row, checked row 1, and so on. ?-> still recovers from anything, and Runtime->GetLastError() says what it was.

JIT Compilation

Method and function may be JIT compiler to speed up their execution. The Methods/functions are compiled the first time they are called and subsequent calls execute the per-compiled code. To direct the runtime to JIT compile code for a given function/method use the "native" keyword.

Good candidates for JIT compilation are computationally expensive blocks of code with lots of loops. Code that contains numerous floating-point calculations may also benefit from being sped up.

As an example, observe the execution time of this prime number program with and without the use of the native keyword. 

class FindPrime {
   function : Main(args : System.String[]) ~ Nil {
     Run(100000);
   }
 
   function : native : Run(topCandidate : Int) ~ Nil {
     candidate := 2;
     while(candidate <= topCandidate) {
       trialDivisor := 2;
       prime := 1;

       found := true;
       while(trialDivisor * trialDivisor <= candidate & found) {
         if(candidate % trialDivisor = 0) {
           prime := 0;
           found := false;
         }
         else {
           trialDivisor++;
         };
       };

       if(found) {
         candidate->PrintLine();
       };
       candidate++;
     };
   }
}

			return response->SetForwardAlias("auth.html");
		}
		# check name and password
		else if(request->HasParam("name") & request->HasParam("password")) {
			name := request->GetParam("name");
			password := request->GetParam("password");
			if(name->Equals("mega") & password->Equals("1234")) {
				response->AddCookie(Web.HTTP.Cookie->New("authenticated", "true"));
				return response->SetForwardAlias("auth.html");
			};
		};
		
		# show login page
		return response->SetForwardAlias("index.html");
	}

	method : ProcessPost(request : Request, response : Response) ~ Bool {
		return false;
	}
}

Database: ODBC

Objeck provides database access through ODBC, supporting SQL Server, PostgreSQL, MySQL, SQLite, and any ODBC-compliant database. Connect using a data source name (DSN) or a connection string. 

use Database.ODBC;

class DbExample {
  function : Main(args : String[]) ~ Nil {
    # connect using DSN
    conn := Connection->New("my_dsn", "user", "password");

    # or connect using a connection string
    # conn := Connection->New("Driver={PostgreSQL};Server=localhost;Database=mydb;Uid=user;Pwd=pass;");

    if(conn->IsOpen()) {
      # query with a prepared statement
      ps := conn->CreateParameterStatement("SELECT id, name FROM users WHERE age > ?");
      ps->SetInt(1, 21);
      rs := ps->Select();

      if(rs <> Nil) {
        while(rs->Next()) {
          id := rs->GetBigInt("id");
          name := rs->GetVarchar("name");
          "{$id}: {$name}"->PrintLine();
        };
        rs->Close();
      };
      ps->Close();

      # insert with transaction control
      conn->SetAutoCommit(false);
      count := conn->Update("INSERT INTO logs(message) VALUES('hello')");
      if(count > 0) {
        conn->Commit();
      }
      else {
        conn->Rollback();
      };

      conn->Close();
    };
  }
}

> obc -src db_example.obs -lib odbc
> obr db_example

Supported types include Int, BigInt, SmallInt, Double, Real, Varchar, Blob, Date, and Timestamp. See the API documentation for full details.

Programming Environment

Tools to make Objeck programming easier to use.

REPL Shell (obi)

obi is an interactive read–eval–print shell for trying out Objeck without creating a source file. It keeps an in-memory program and recompiles and re-runs it each time you enter a line, so the buffer always reflects everything you've added. Start it by running obi with no arguments. 

> obi
Objeck REPL (2026.10.3)
['/h' help | '/t' guided tutorial | omit ';' to print an expression]
---

New to the language? Type /t for a short, hands-on guided tutorial that steps through expressions, variables, formatting, collections, and control flow one lesson at a time (/t <n> jumps to a step).

How a line is handled depends on whether it ends with a semicolon:

  • End a line with ; — it is kept as part of the program and re-runs with the buffer.
  • Omit the ; — the line is evaluated as an expression and its value is printed once (it is not kept).
  • A := declaration is kept so later lines can use the variable.
> 40 + 2            # expression — printed once
42
> name := "Objeck"  # declaration — kept
> name->ToUpper()   # expression using the variable
OBJECK
> "Hi {$name}!"->PrintLine();   # statement — kept
Hi Objeck!

When a line leaves a brace open, obi keeps prompting with ... until it closes, so blocks and control flow can span several lines. A line that fails to compile is reported and discarded, leaving the buffer runnable. 

> if(name->Size() > 3) {
... "long name"->PrintLine();
... }
long name

Commands start with /; type /h for the full list. The most useful are:

  • /t — guided tutorial (/t <n> to jump)
  • /l — list the current program; /v — show defined variables
  • /s name.obs — save the buffer to a file; /o file.obs — open one
  • /u — set library use statements; /a — set command-line arguments
  • /x — reset the buffer; /q — quit

You can also start from an existing file or run a one-off statement directly: 

> obi --file prog.obs                 # load a file, run it, then drop into the shell
> obi --inline 'Int->New(42)->PrintLine();' --quit   # run one statement and exit

VS Code Debugging

Objeck supports visual debugging in VS Code through the Debug Adapter Protocol (DAP). This provides breakpoints, stepping, variable inspection, and call stack views directly in the editor.

Setup

  1. Install the Objeck VS Code extension: objeck-lsp.vsix is inside the objeck-lsp_<version>.zip of each release (source in tools/lsp)
  2. In VS Code settings, set the Objeck install path:
    • Windows: objk.win.install.dir → your Objeck install directory (e.g. C:\Program Files\Objeck)
    • macOS/Linux: objk.posix.install.dir → your Objeck install directory (e.g. /usr/local/objeck-lang)
  3. Compile your program with debug symbols: 
    > obc -src myprogram.obs -debug

Launch Configuration

Create a .vscode/launch.json in your workspace (or use the "Run and Debug" panel to auto-generate one): 

{
  "version": "0.2.0",
  "configurations": [
    {
      "type": "objeck",
      "request": "launch",
      "name": "Debug Objeck Program",
      "program": "${workspaceFolder}/myprogram.obe",
      "sourceDir": "${workspaceFolder}"
    }
  ]
}

Debugging

  • Click the gutter next to line numbers to set breakpoints (red dots)
  • Press F5 to start debugging
  • Use the debug toolbar: Continue (F5), Step Over (F10), Step Into (F11), Step Out (Shift+F11)
  • Inspect local variables in the Variables panel, and edit an Int/Char/Float local by double-clicking its value
  • View the Call Stack panel to see the current execution context
  • Conditional breakpoints are supported: right-click a breakpoint and add an expression (e.g. i > 3)
  • Function breakpoints (Breakpoints panel → +, e.g. Main->Factorial) and logpoints (right-click gutter → Add Logpoint, with {expr} interpolation) are supported
  • Exception breakpoints: enable Uncaught Runtime Errors in the Breakpoints panel to stop on an uncaught Objeck runtime error (e.g. a Nil dereference)
  • Restart (Ctrl+Shift+F5) re-runs the program in-process
