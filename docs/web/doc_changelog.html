[v2026.10.3] - 2026-11-03

A hardening release: the garbage collector now knows exactly which words of compiled code are references on x64 and ARM64, the loader is fuzzed and verifies programs before it runs them, errors are returned instead of ending the host process, and the HTTP client stops running Windows out of ports.

Upgrading: the .obe and .obl file formats changed (magic 0xffbf for programs, 0xffba for libraries) because an Int[] and an object array are now different heap kinds: recompile your programs and rebuild any library of your own with this toolchain. A program or library built by an earlier version is refused with a message saying so.

Runtime and garbage collector

  • Compiled code tells the collector exactly which words are references (#1496, #1504, #1506, #1511; design in docs/GC_ROOTS_DESIGN.md): a JIT frame now has typed spill slots, so a collection reads exactly the words the code marked as references. An Int equal to a moved object's address, pending in a compiled method, is no longer rewritten. The conditional (and/or) temp is carried through a reference slot too, and the dead AMD64 inliner is gone. Measured 6,171 stress runs on each of five platforms with no failure.
  • An Int[] has its own heap tag (#1510): an Int[] element that happened to equal a moved object's address was rewritten by a minor collection, interpreted and compiled alike (242 of 2,000 in the reproduction). Object, class, string and function arrays keep the scanned tag. This is why the file formats changed.
  • Unresolved call targets and worker-thread exceptions are reported (#1494): a missing class or method in a call chain, and an exception on a worker thread, no longer end the process silently.
  • The native library ABI is versioned (#1492): VMContext carries an ABI version and its own size, and the lib_api.h helpers are inline.

Loader and compiler

  • The loader is fuzzed, and every program is verified before it runs (#1508, #1512; tools/fuzz/loader, docs/SECURITY_MODEL.md): hundreds of millions of executions found and fixed a crash on a repeated class or method id, allocations of up to 16 GB from a corrupt count, an abort on a bad method signature, a silent exit on an unknown opcode, a read past the end of a .obe shorter than four bytes, and leaks on every refused load. A verification pass checks jump targets, local and trap ids, memory contexts, array dimensions, and class, method and field ids, with no measurable startup cost. The loader returns its errors (23 exit(1) calls removed); obr prints the same message and exits 1.
  • A fatal compiler error no longer ends the host (#1507): the compiler back end throws instead of calling exit(1), so the language server stays up when a library fails to load. The command line prints the same text and status (54 failure cases compared byte for byte).
  • One diagnostic record (#1509): parser and analyzer errors share one Diagnostic and sink; the language server reads the fields instead of splitting strings.

Networking

  • HttpClient reuses connections (#1529, fixes #1443, #1503 and #1516; likely also #1461): a request used to open a connection and close it, and the side that closes first holds the local port in TIME_WAIT for about two minutes; on Windows a process making about 130 requests a second used all 16,384 ports and every connect then failed at once. Plain-HTTP connections now wait in a pool (16, reused within 4 s) when the server says keep-alive and the response ends where its own framing says; a GET or DELETE on a reused connection that answers nothing goes once more on a new connection (RFC 9112 9.3.1). POST, PUT and PATCH never reuse a connection, and the new HttpClient->CloseIdleConnections() (called by WebServer->Stop()) closes the waiting ones. Hosted Windows runners: 4 of 4 failing harness runs became 4 of 4 clean, with lingering ports down from 16,180 to 63; the nightly on the merge commit passed on all five platforms.

Libraries

  • A failed request or an empty reply no longer dereferences Nil (#1490, #1527): OpenAI, Gemini, misc and net first, then JSON, XML, RegEx, RSS, JSON-RPC and the web server, with tests.
  • RegEx repeat counts are bounded (#1534): a{99999999999} filled the heap while compiling and never returned. A count is now at most 1000, the low bound may not exceed the high one, and a pattern that expands past 100,000 instructions is not OK and matches nothing.
  • The JSON-RPC client sends a fresh request id and checks the reply (#1534): the id was a shared static that never advanced. A reply that echoes another id is Nil with error -32600.
  • WebDownloader no longer skips URLs (#1535): given seven or more URLs, the position overshot after the first group of three and the seventh was never fetched; its result came back empty with no error.
  • Collection.Pair->Compare compares the other pair's first value (#1526): sorting a vector of pairs ended in 'Invalid object cast'.

Language server

  • Edits analyze faster (#1531, #1532; part of #1236, design in docs/INCREMENTAL_ANALYSIS_DESIGN.md): the diagnostics library inflates each library once per process instead of on every edit and no longer builds library instructions it never uses, and a folder's analysed program is kept until a newer one replaces it. On Windows a hover after an edit in a small workspace went from 165 ms to 53 ms, and a hover in a second folder from about 600 ms to about 60 ms. The cached and uncached servers gave identical answers for every file in more than 6,000 edited texts; OBJECK_LSP_NO_CACHE=1 keeps the uncached server as a reference. obc output is unchanged. Phases 3 and 4 (re-parse only the edited file, repeatable analysis) are not started.

Debugger

  • The debug adapter keeps output whole, orders messages, and refuses what it does not understand (#1487, #1495): partial UTF-8 is carried across reads, sequence numbers are ordered under one lock, an unknown request fails instead of being ignored, you can pause, and breakpoints keep their file and have their own ids. A lock-free fast path cut a breakpoint-heavy run's hook cost from 25.3 s to 0.25 s on four threads.

Testing, CI and documentation

  • The nightly hardening run is scheduled, and the cloud checks run on your machine first (#1489, #1484, #1493, #1502, #1514): actions are pinned by commit, the Linux legs are pinned to Ubuntu 24.04, and tools/cicd/local_linux.sh builds the committed tree, compiles every library from source and fails when the flag tests crash.
  • Four intermittent test failures found their causes (#1505, #1513, #1515): three TLS tests made a certificate valid only from the second it was created (a clock step made it 'not yet valid'), a JSON-RPC test chose a port still held by an earlier connection, and threads_12 was retried and judged by exit status alone.
  • New documents: the architecture assessment (docs/ARCHITECTURE_ASSESSMENT_2026_11.md), the VM trust model (an .obe is native code), docs/COLLECTIONS_GUIDE.md, docs/ERROR_CONVENTIONS.md and docs/ADDING_AN_INTRINSIC.md.
  • Getting-started guides and examples (#1540, docs/guides, programs/examples/guides): eight guides (Query.Structured, the HTTP client and server, JSON/XML/RegEx, collections, AI, the language server, and what is new in 10.3), fifteen runnable programs, an Examples section in the README, and eight matching pages on the site. Every code block and output block in a guide is byte-for-byte a program and its real run, and tools/docs/guides_to_html.py --check fails when a site page is stale.
  • An architecture map and an index of the docs (#1541, docs/ARCHITECTURE_MAP.md, docs/README.md): one page that shows how the compiler, file formats, VM, JIT, garbage collector, libraries, tools and pipeline fit together, an index of every doc with a status checked against the code, and short READMEs for core/shared, tools/cicd and programs/tests. Several docs that disagreed with the code were corrected (the linker's place in the compiler, the removed AMD64 method inliner, the test counts, where VM options are parsed). tools/cicd/check_doc_links.py now checks every relative link and anchor in the Markdown files in CI, and docs/DOC_COVERAGE.md records that 6,610 of 7,299 public library members (91%) have a doc comment.
  • A checkers game with ten AI levels (#1528, #1539, programs/examples/checkers): an SDL2 example with minimax and Monte Carlo opponents from System.AI, a self-play learner, ten piece sets (two of them tech-neo, rubber-duck debuggers against coffee mugs and glitchy ghosts against rebooting robots, on circuit-board boards), a flat or slanted camera, generated music in five styles (hip-hop, modern beats, reggae, techno and classical) with a deep-bass setting, animation and an optional fun mode. The move generator is checked against the published perft numbers, and a 439-check headless test runs in the regression suite.

Upgrading

  • Recompile every .obe and rebuild every .obl of your own: the program and library magic numbers moved to 0xffbf and 0xffba.
  • A malformed .obe is now refused by the verifier with a message; a valid program is never refused.
  • HttpClient may keep a connection open between requests; code that stopped a server and started another on the same port within four seconds and relied on a fresh connection should wait for the old server to exit.

[v2026.10.2] - 2026-10-31

Objeck gains a database in the standard library: Query.Structured is now a columnar engine with SQL joins, grouping, indexes and expressions over typed in-memory tables, files and URLs named in FROM, a crash-safe .otab file format, and sources that read CSV, JSON, XML, text logs, filesystems, zip and tar archives, Excel workbooks, ODBC databases, System.ML results and image detections as tables. The runtime collects in proportion to live data and allocates without searching, Collection.Hash is open-addressed with unboxed IntVector/IntMap/BitSet beside it, calls nest 16,384 deep, DTLS works for the first time, every socket failure says why, servers take IPv4 and IPv6 clients on every platform, and Windows handles non-ASCII arguments, environment variables, paths and console text. System.ML gains kernel and one-class SVMs, six outlier detectors and an autoencoder, a new System.ML.Lab for experiments, result tables and charts, and BERT sentence embeddings over ONNX; Data.JSON decodes escapes when it parses, so a document reads back as it was written; the JIT compiles code it used to hand back to the interpreter and no longer loses a value at a loop's collection safepoint; the collector keeps a conditional's value alive across another thread's collection; and the language server analyzes each edit once, about twice as fast. Probing six libraries and the compiler fixed defects in CSV, JSON, regular expressions, NLP, ML, Ollama, OpenAI, Gemini, SDL2, ODBC, numeric literals, name resolution and array literals. The first AI-foundation pieces arrive: System.NLP.Onnx.TextClassifier runs a Hugging Face text classifier as Python's pipeline does, System.AI.Hub.HubClient downloads models by name into a verified cache, BpeTokenizer matches RoBERTa's and GPT-2's tokenizer id for id, and GetToFile streams any download to disk; a redirect to another host no longer receives the caller's credentials; and objects keep their instance IDs when the collector moves them, so Hash and Map keyed by objects keep their entries.

Upgrading: every .obl is a new format (magic 0xffb9): rebuild any library of your own with this toolchain. The full list of behaviour changes is in the Upgrading section at the end of this entry; the ones most likely to touch a program are an .obe from an earlier release being refused (recompile), Directory->List no longer returning . and .. on Windows, a leading-zero integer literal (010) being a compile error with 0o10 as octal, Byte->CompressBr renamed CompressDeflate, Data.JSON decoding escapes when it parses (stop calling JsonElement->Decode), TF_IDF->New() smoothing and normalizing by default, Byte[]->ToHexString returning a digest, Hash iteration order changing, and a call stack that defaults to 16,384 frames rather than 256.

Query.Structured

  • A columnar engine, designed first and built in phases (#1295, #1298, #1301, #1303, #1325; design and as-built notes in docs/QUERY_DESIGN.md): every column is a typed array (INT, FLOAT, STRING, DATE, BOOL, OBJECT) with a null bitmap, text is dictionary-encoded, and each 65,536-row group carries min/max zone maps so a filter skips groups it cannot match. A query returns a View, a selection of row numbers with nothing copied; Where, Select, OrderBy and Limit chain on it. A where is compiled once into typed predicates (Col("value")->Gt(0.5)->AndAlso(...)), prepared statements take ? placeholders, and a table caches 64 parsed plans. The SQL front end is a new recursive-descent parser with contextual keywords: INNER/LEFT JOIN ... ON through a Catalog, GROUP BY with COUNT/SUM/AVG/MIN/MAX/MEDIAN/STDDEV and HAVING, multi-key ORDER BY ASC|DESC, LIMIT/OFFSET, multi-column DISTINCT, MATCHES over Query.RegEx, and INSERT/UPDATE/DELETE/CREATE TABLE applied in full or not at all. The old API (Table->New(name, String[]), Insert() ~ Row, Query(sql) ~ Table, FromCsv, FromFilesystem, Finder) keeps its signatures and results. Measured at 100,000 rows on the Windows x64 development machine, against the v2026.10.1 library: where value > 0.5 0.558 s to 0.023 s, order by 3.16 s to 0.096 s, Sum 0.051 s to 0.004 s, 10,000 Get(pk) 0.032 s to 0.005 s; a join with a 5,000-row table 0.11 s, GROUP BY into 5,000 groups 0.11 s.
  • Files and URLs are tables (#1303, #1366, #1384, #1391): a quoted path in FROM or JOIN is read by its extension (.csv, .tsv, .json, .jsonl, .xml, .otab, each also .gz), csv('data.txt', delimiter => ';', header => false) and the other function forms set options, a glob reads several files as one table with a _file column, and Catalog->Run(sql) is the stateless one-off form. An http:// or https:// path is fetched through a download cache revalidated with ETag and Last-Modified. The cache is correct across processes that share the temporary folder: each URL has one folder of immutable versions, each written once under a name no other writer uses, and one small note naming the current version with its validators, published by a single atomic rename, so the validators a reader sends always belong to the copy it reads and a 304 means that copy is current. Before, a Windows writer could not replace a copy another process had open (the query failed with cannot write its copy), and two processes that downloaded different versions could leave one's copy beside the other's note, so an older file was served as current; superseded versions are deleted after a five-minute grace period with no lock file, and the old layout is not read, so the first fetch of each URL after upgrading downloads it once more. An archive's member or a workbook's sheet follows the path after a dot, as schema.table does: select * from 'results.zip'.'2026/runs.csv', from 'budget.xlsx'.'Q1 2026', from 'runs/*.tar.gz'.'metrics.csv'. Each catalog caches files by size and modification time, and a file read within a second of its last change is also held with a digest of its bytes, so one rewritten in the same second to the same size is read again (File->ModifiedTime has whole-second resolution, and a finer clock does not help because file systems stamp with a coarse tick); Catalog->SetFileAccess(false) refuses them all, which is what TableServer runs with.
  • Sources (#1298, #1301, #1303, #1329, #1331, #1334, #1350, #1352): a Source declares its tables and fills a catalog, with a ScanHint for the columns, filter and row limit a query needs. In query.obl: CsvSource (whole-column typing, RFC 4180 through Data.CSV), FilesystemSource (flat or recursive, with _id/_parent_id/depth), ObjectSource<T> (a Vector of the program's objects), TextSource (regular-expression capture groups become typed columns; multi-line records; unmatched lines counted), JsonLinesSource, JsonSource and XmlSource (nested repeated parts become child tables joined on _parent_id = _id), HttpJsonSource (records at a dotted path, paged by a next link or an offset), ArchiveSource (zip, tar and gzipped tar read from a file, URL or bytes, with every member in a readable format as a table; nothing is extracted, and .., absolute paths, duplicate or overlapping zip members, zip bombs and CRC mismatches are refused), and XlsxSource (each worksheet as a typed table: shared and inline strings, booleans, error values, dates in both the 1900 and 1904 systems with the Lotus leap-year serial undone, merged cells kept as Excel stores them or filled with SetFillMerged). In their own libraries, so a program that only queries files loads no native module: query_ml.obl's MlResultSource (folds, out-of-fold predictions, threshold sweeps, confusion matrices, bootstrap intervals and per-group recall from System.ML, with MlColumns as the bridge back to a matrix), query_odbc.obl's OdbcSource (a table or query from any ODBC database, typed from the driver's description, with columns, a row limit and a SetWhere condition pushed into the SQL it sends, names always quoted and values always bound), and query_vision.obl's VisionSource (a folder of images and a detector's boxes as images and detections tables, with image headers read in pure Objeck and YoloDetector over API.Onnx).
  • The .otab file (#1315, #1321, #1365; byte-exact specification in docs/OTAB_FORMAT.md, an independent reader in tools/otab/otab_dump.py): table->Save(path[, compression]), Table->Load, ToBytes/FromBytes, and Append, which adds row groups without rewriting the existing ones. Every block and the footer carry a CRC32, a save writes path.part and renames it into place, and OtabFile reads only the footer and then only the columns a Read names, over HTTP range requests as well as from disk. Compression->FAST/SMALL are zlib levels 1 and 9 per block, stored raw where compressing would not shrink. A table opened with TableStore->New(path) or Table->Open(path) is durable: every statement is appended to a change log before the call returns, a torn last record is dropped while a damaged one refuses the open with its offset, Checkpoint() folds the log into a save, and a writer lock holding the process id refuses a second writer and clears a dead one's. Index definitions are kept in format 2, written only for a table that has indexes, so a table without them is byte for byte what v2026.10.1 wrote.
  • Hash and sorted indexes, and a planner that shows its work (#1351, #1364): table->CreateIndex(column, IndexKind->HASH | SORTED), DropIndex, and in SQL CREATE INDEX [name] ON t (col) [USING HASH | SORTED] and DROP INDEX. A hash index serves = and IN; a sorted index serves ranges, BETWEEN, ORDER BY, GROUP BY on one table and Min/Max. An index lookup returns candidate slots and the whole condition is then tested on them in slot order, so results and their order are a scan's by construction, which a differential test holds it to. View->GetPlan(), Statement->Explain(), Table->Explain(sql) and Catalog->Explain(sql) report steps such as where runs: HASH index runs_grp on grp (=). At 1,000,000 rows (Windows x64, -opt s3), equality on an Int 73 ms to 0.02 ms, a 0.1% range 109 ms to 0.7 ms, ORDER BY value LIMIT 10 2.8 s to 0.08 s; building an index takes 0.2 to 0.6 s. Several threads may query one table at once, including right after a write: a stale index, zone map or plan cache is rebuilt under one process-wide lock taken only on that slow path.
  • SQL expressions in every clause (#1367, #1398, #1416, #1417; design in docs/QUERY_DESIGN.md, #1395): + - * / %, unary minus and parentheses over columns, numbers, text, dates, TRUE/FALSE, NULL and ? placeholders work in the select list, in WHERE (on either side of every test, in IN lists and BETWEEN bounds, and in UPDATE and DELETE conditions), ORDER BY, GROUP BY and HAVING, inside aggregates (sum(price * qty)), over aggregates (sum(a) / count(*), max(x) - min(x)) and in JOIN ... ON (on t.n + 1 = u.w, a range join with between, a key plus another test, OR, a join over two earlier tables). A parsed expression is never changed, so cached plans stay shareable between threads; it is bound to a table once per run, constants are folded, and it is evaluated 1,024 rows at a time into typed arrays with no per-row allocation. A column tested against a constant is still reduced to the ordinary filter, so zone maps and hash and sorted indexes serve it as before, and a group or join key that is an expression is computed into a column. / always gives a Float; an empty cell, a non-numeric cell, a zero divisor or an Int overflow gives an empty cell rather than stopping the program, and x % -1 is 0. Refused with a message of their own: an aggregate inside an aggregate, an aggregate in GROUP BY or ON, a GROUP BY entry that reads no column (group by 1), and an ON that names a table joined later. At 1,000,000 rows (Windows x64, -opt s3, best of three), select price * qty went from 585 ms to 146 ms and where price * qty > 100 takes 29 ms (it was a syntax error); a join of 200,000 rows to 1,000 takes 29 ms on t.n = u.w and 62 ms on t.n + 1 = u.w + 1. A differential test holds every form to a row-at-a-time evaluator written from the design's rules, over random tables with NaN, infinities, extreme Ints, empty cells and deleted rows, each also on an indexed twin (9,672 queries over 60 seeds).
  • Bridges and serving (#1325): ToCsv, WriteCsv, ToJson, WriteJson and ToMatrix(names[, fill]) on both View and Table, with Table->FromCsvText, FromJson and FromMatrix; numbers round-trip exactly through Float->ToShortString. TableServer, in query_server.obl so query.obl does not pull in Web.HTTP.Server, answers GET /tables, GET /tables/NAME and GET/POST /query as CSV, JSON or .otab, refuses anything but a SELECT (403), any query naming a file or URL (403) and any result over its row limit (413). RemoteSource queries a published table as a local one, sending its columns, limit and a SetWhere condition so only matching rows cross the network.
  • Safe for threads (#1378, #1389): Table->GetError and Catalog->GetError answer the calling thread's own last error, through two new runtime functions, Thread->GetCurrentId() and Thread->IsAlive(id). A Catalog can be shared: its table map, plan cache and file cache are locked only for a map operation, sixteen file locks give single-flight loading so threads that miss together read a file once, and CREATE TABLE by several threads at once lets exactly one succeed. Writes to a table are still the program's to order. TableServer answers requests at once: it held one mutex for each request from parsing to the last byte sent, which only serialized reads and never guarded the program's own writes. Each request now holds a read share of a writer-preferring lock, TableServer->BeginWrite() and EndWrite() bracket the program's changes to published tables (DML, indexes, columns, Compact) and keep requests away from them, and Publish and Unpublish no longer lock. Eight clients sending one GROUP BY over 20,000 rows went from 48 to 112 requests a second (Windows, 24 logical processors); with the program's writes inside that pair, no request reads a table half changed (in the new test, 18 to 136 reads a run saw a change half done before). Writes over the wire were and are refused with 403.
  • Correctness first (#1291, before the redesign): Average and Sum counted string and Nil cells, order by through a Map keyed on the value lost rows with equal values, where comparing an int column with a float literal aborted the VM, and did not bind tighter than or, order by after where was ignored, LIKE compiled a regex per row, and Delete of the only row crashed. All fixed, with Min, Max and Count(name) added.

AI foundation

The first steps of docs/AI_FOUNDATION_DESIGN.md (#1451): use Hugging Face models from Objeck the way Python does, with no Python installed.

  • TextClassifier (System.NLP.Onnx, #1456): opens a Hugging Face model folder (what save_pretrained writes, with an ONNX export beside it) and classifies text as pipeline("text-classification") does: the tokenizer from tokenizer.json (or vocab.txt and tokenizer_config.json), labels from config.json's id2label, sigmoid or softmax scoring as transformers chooses, only the inputs the export declares, and the maximum length the model and tokenizer allow. Batches are padded to their longest text and truncation is reported on each Prediction. Token ids match Python exactly and scores agree to 1e-4 on three generated models; a real SST-2 model matches Python to six decimals at batch size 1. When DirectML or CoreML cannot open or run an export (both refuse the torch.export-based exports current PyTorch writes), it runs on the CPU instead.
  • HubClient (the new library ai_hub, System.AI.Hub, #1463): Snapshot(repo, files[, revision]) and Download(repo, file[, revision]) fetch from the Hugging Face Hub as from_pretrained does. One API call fixes the commit, so every file of a snapshot comes from the same one; each file's size and SHA-256 (or git blob hash) must match what the Hub reports before it is kept, using the new streaming Cipher.Hash->SHA256File. The cache (OBJECK_HUB_CACHE, default ~/.objeck/hub) uses huggingface_hub's layout; OBJECK_HUB_OFFLINE/HF_HUB_OFFLINE and an unreachable Hub serve from it, Python's own cache is read as a fallback, HF_TOKEN goes to the Hub and never to the file CDN, and names that could escape the cache are refused.
  • BpeTokenizer (System.NLP, #1462): byte-level BPE as RoBERTa and GPT-2 use it, with the GPT-2 pre-split, RoBERTa's special-token layout, longest-first pair truncation, <mask>'s whitespace rule and ByteLevel character offsets. It matches the tokenizers library on all 348 parity encodings, and on DistilRoBERTa's own 50,265-token vocabulary. SubwordTokenizer is the interface it shares with WordPieceTokenizer, and TokenEncoding->GetOffsets() gives each token's span of the text.
  • Downloads of any size (#1459): HttpClient->GetToFile(url, path), HttpsClient->GetToFile(url, path[, pem]), QuickGetToFile and GetDownloadSize() stream a body through a 256 KB buffer to path + ".part" and move it over path only once it is complete, so an interrupted download never leaves a truncated file; any other status leaves path untouched. Get no longer returns no content for a body over 256 MB, and a chunk over 256 KB is read rather than refused.

Runtime

  • Interpreted code no longer has an Int rewritten by a collection (#1466, #1470, #1478, #1452; design in docs/GC_ROOTS_DESIGN.md): a minor collection treated every operand-stack word that looked like a young object's address as a reference, so an Int that equalled one changed value. The VM now computes a reference map for each method, and for interpreted frames the collector skips the words the maps prove are Int or Float; anything not proven keeps the old handling. Typing stops above any frame that compiled code sits under, because a compiled method's pending words are not mapped yet; compiled frames are planned for the next release. OBJECK_GC_ROOTS=conservative restores the old behavior, and OBJECK_GC_ROOTS=audit checks the maps against the live stacks at every collection and prints a summary at exit.
  • An object's instance ID survives the collector moving it (#1472): GetInstanceID() was the object's address, and a minor collection moves young objects, so an object's ID changed when it was promoted. BasicCompare's HashID and Compare are both the ID, so a Hash or Map keyed by BasicCompare objects lost its entries once the keys moved (with the default nursery and enough allocation, 2,000 of 2,000 Hash lookups missed), and an Int holding an ID was an address the collector rewrote wherever it found one (#1452), heap Int[] elements included. The ID is now a number assigned once per object from a counter; the collector moves it with its object and forgets it when the object dies, so a reused address never inherits one.
  • Three traps no longer leave words on the operand stack (#1458): UDPSocketServer bind and close and File->TempName never popped the arguments their bytecode declares, so each call left one or two words behind for good, and the collector, which scans the whole operand stack, kept what they named alive (here the socket server itself).
  • Allocation no longer searches a free list (#1308): the old generation's free-block cache kept one list per power of two holding blocks of any size in that range, so after a major collection freed thousands of small blocks every allocation of a slightly larger size walked the whole list and then allocated fresh anyway. Each list now holds one size class, four per power of two, so a cache hit is one pop. The first read of a 4,000-row text column went from 0.96-1.03 s to 0.023 s, and building 16,000 rows from 2.06 s to 0.20 s (Windows x64). A stack sampler had put every sample in MemoryManager::GetMemory.

  • Calls nest 16,384 frames deep, and a full stack is recoverable (#1377): CALL_STACK_SIZE 256, unchanged since commit c2208e3a0d, ended the shipped Rosetta example man_or_boy.obs with call stack bounds have been exceeded and any recursive-descent parser past about 300 levels. Both backends had it. EllipticEnvelope's distances went from 1.68 s to 0.14 s, and the BERT classifier head's Adam step now compiles. A failed compile now reports the failing instruction, its opcode, the inlined callee and the reason (no free integer register: the working stack holds 0 integer and 1 float register(s)...), and OBJECK_JIT_REPORT=1 audits the register pool at every label.
  • A loop's collection safepoint keeps the values pending across it (#1425): the JIT polls for a stop-the-world collection at every loop header and parks the thread with a plain call to MemoryManager::SafePoint, on the assumption that the working stack is empty there. When the -opt s3 inliner pasted a copy loop into an expression after an earlier operand had been evaluated, that operand was still pending in a caller-saved register, which the call clobbers, and a young object it points to may be moved by another thread's collection while the thread is parked; the next use was a Nil dereference or a segmentation fault in compiled code. Only a multithreaded program whose loop polled during another thread's collection reached it, which is why it was rare (10 times more frequent with a small nursery) and surfaced as an intermittent failure of the new SQL-expression concurrency test. The slow path now spills every register the working stack holds into scratch slots the collector marks and relocates, reloads them after the park, and leaves the method to the interpreter if there are more values than slots; the fast path is unchanged. Known issues

  • A compiled -opt s3 method can keep a dead object alive until it returns: when the compiler inlines a call whose result was spilled across another call, the spill slot is not cleared after the value is reloaded, and the collector scans it, so the object stays reachable while that frame runs. Nothing is freed while still in use. The fix is GC roots phase 3 (docs/GC_ROOTS_DESIGN.md), planned for the next release.
  • On Windows, a burst of local connections can stall one for about 21 seconds (#1443, #1461): when dozens of processes connect to one loopback server at once, a connect occasionally never completes and fails after Windows' SYN retries run out (1 to 2 runs in 20 of a 60-process test, #1443). Not specific to Objeck: the same loss reproduces between plain Python sockets, and a packet capture of that run shows the Windows stack dropping the client's closing packet (FIN) with the reason INET: invalid ACK in SYN_SENT state. The server's end then stays open, and a later connect that reuses the client's port is not answered. Why the stack drops it is not yet known. The listen backlog is larger than the number of clients, and the connection-reset fix in this release does not change the rate. A second Windows-only network test flake (#1461) did not reproduce locally in 30 runs and may share the cause.

Compiler

  • A program could compile to an infinite loop at the default optimization level (#1037): the s3 inliner advanced its label offset only when the same method was inlined a second time. Labels are numbered from each method's own start, so two different callees containing the same construct carry the same numbers -- two helpers each evaluating ->Abs() is enough. Under one shared offset the second body's LBL landed on the first body's and its JMP resolved to the first, which is a backward jump into already-executed code. Correct at -opt s0, s1 and s2, and unaffected by disabling the JIT, so the bad jump was in the bytecode. The offset now advances for every inlined body, and the conflict check -- which compared a candidate only against the caller's labels, and so could not see an inlined-against-inlined clash -- now records inlined labels too. Rebuilding all 32 libraries with the fixed compiler changed exactly one, misc.obl, whose committed bytecode was therefore wrong; the suite passed against it, so no exercised path looped.
  • A generic array parameter did not resolve across a library boundary (#998): Vector[]<T> as a parameter compiled inside a library and callers in that same library reached it, but a program linking the library was told the method did not exist. TypeParser::ParseGenerics ended its loop on the closing > rather than past it, so the parameter path read that > where it scanned for the dimension and left the dimension at 0. ParseType, which decodes return types, already stepped past it -- which is why the same type worked as a return value and failed as a parameter. A reader-only fix: the .obl encoding was always correct.

Runtime

  • A recovered ?-> compared wrongly against Nil when the comparison was written inline (#1067): if(x?->y() = Nil) took the wrong branch once the failing method was hot, while r := x?->y(); if(r = Nil) was correct in every mode -- so the idiom ?-> exists for was the one that broke, and only after warm-up, which means a program could behave correctly in testing and wrongly in production. Recovery itself was never at fault: the handler stored Nil and a local read it back correctly, which is what made the two spellings disagree so confusingly. TryErrorRecovery was ASSIGNING the handler's saved operand-stack position rather than treating it as an unwind target, so a position above it was raised instead of lowered and the comparison read a stale slot. The saved position is now a floor, never a value to assign. programs/regression/try_chain_inline_compare.obs holds both spellings to the same answer, deliberately without a JIT opt-out: the two modes agreeing is the entire property under test, so a marker there would remove the only thing it checks
  • Try() now recovers from an error raised inside compiled code, so the language's error semantics no longer depend on what happened to be JIT-compiled (#925): #900 made Try() recover from a failing cast, but only where the interpreter owned the error. Inside a compiled method the cast was raised in a JIT callback, which is static, holds no interpreter, and so could not see the handler stack -- jit_common.cpp built a THROWAWAY StackInterpreter just to print a stack listing, which was the clearest evidence of it. Whether a guarded chain recovered or aborted therefore depended on how many times the failing method had been called: the same program, run twice, could do either. Demonstrated against the pre-fix build, where try_recovers_cast.obs aborts with exit 1 compiled and passes with exit 0 interpreted. Three changes close it. The handler stack moved from StackInterpreter instance fields to per-thread storage -- a Try() is inherently per-thread, and the hazard was that all four constructors zeroed it while jit_common.cpp builds interpreters at three sites on a thread already running Objeck code, so the naive move would have wiped a live handler the moment compiled code took any callback. StackCallbackBody returns a status instead of calling VmExit, and both backends test it and leave through the epilogue, where the interpreter already recovers a guard stub's status. The status is int64_t, not long: on Win64 long is 32 bits, so -5 reached the return register zero-extended as 0x00000000FFFFFFFB, which the 64-bit compare reads as positive -- the branch never fired and the method carried on past a reported error with nothing pushed. The diagnostic is printed only when no handler is active, so a recovered cast is as silent as in interpreted code and stdout is identical between the two. Compiled recursion is still fatal and is not reachable this way: compiled frames consume the real C stack, so the process dies in the OS with no frame left to return a status from; try_recovers_depth.obs keeps its opt-out and says why. A JIT-to-JIT call whose callee fails now recovers too, which was the third and last gap: EmitNativeCallSite called JitNativeCallError, which printed and exited, so a compiled method calling a compiled method that failed could not recover even though the failing frame had already returned and the handler was intact. The call site now branches to its own teardown with the status still in the return register -- the same exit a bridge callback's status already took, so the two directions share one handler -- and CallCompiled reports its callee's status through an out-parameter instead of exiting. A status no Try() takes reaches the interpreter's own switch, which reports per status and unwinds, so the unguarded case gains a stack listing it never had and JitNativeCallError is deleted rather than left dead. Frame bookkeeping had to be fixed first and is what made the first attempt fail: the native prologue pushes a frame record, the only matching decrement was in the RTRN handler, and a guard stub never reaches RTRN -- so a natively entered method that failed left its record registered and the unwinder walked entries that were not frames. Nothing could see that until now, because recovery pops frames to the handler's depth and swept it away, and the unguarded path exited without unwinding; the pop therefore moves to the head of the teardown, the one point every exit reaches. On ARM64 that placement is forced rather than chosen -- its epilogue computes branch distances as literal constants, so a block inserted above the teardown shifts all ten of them
  • --nursery now reduces memory on Windows instead of being ignored (#841): the young region was reserved and committed at its full 128 MB, so lowering the limit changed where the collector drew its boundary but not what the process charged to the system -- POSIX got this for free, because mmap(MAP_ANONYMOUS) commits lazily. Windows now reserves the full region and commits only the configured limit. The growth half is still open: the AMD64 JIT inlines the nursery bump, so raising the limit at runtime needs a commit check emitted into that fast path on every backend that inlines it.
  • A native library could store an object the collector tracks without a write barrier (#864): a native library may store an object it allocated anywhere, because AllocateObjectNative puts those in the old generation. An object it received is a different matter: storing that reference without a barrier leaves the collector unaware of it, and three sites in the ONNX binding did exactly that. The VM now exposes a barrier for native code to call, docs/native_interface.md documents when it is required, and tools/cicd/check_native_write_barrier.py holds every native store to it as part of CI -- so the next missing barrier is a failed build rather than an intermittent collector crash.

  • One Tensor and one Engine interface, shared by both backends (#1062): API.Onnx and API.Inference each defined their own Tensor, which was deliberate and temporary -- the generic ONNX run shipped before a shared library existed. API.Models (models.obl) now holds Tensor, TensorSpec, EndPoint and an Engine interface that API.Onnx.OnnxEngine and API.Inference.HttpEngine both implement, so calling code names a backend once rather than at every call site. This is a breaking change: every program linking onnx or inference needs -lib models, because library dependencies are not transitive -- including programs that never touch a tensor, which the regression suite established rather than the design. Merging the two tensors also removed a limit that should never have applied: API.Onnx.Tensor converted Int[] to Float[] at construction and refused anything past 2^53 there, imposing the native crossing's constraint on an HTTP server that receives integers as JSON integers with no range limit at all. Integers stay integers now, and AsFloats() refuses at the one boundary that cares.
  • API.Inference: a model server over HTTP (#1051): the sibling of API.Onnx -- the same models, reached over HTTP rather than loaded in-process. For a model that is not an ONNX file you have locally: served from a GPU machine, a TensorFlow model you would rather not convert, or anything already deployed behind Triton, KServe, TorchServe or TF Serving. Two wire protocols, because no single one covers the field: KServe v2 (OPEN_INFERENCE, flat data with shape and datatype stated) and TF Serving v1 (TF_SERVING, where the nesting carries the shape and there is no datatype field). Client->DescribeRequest returns the body the client would send without sending it, which is usually faster than reading a rejection -- the two protocols shape the same tensors very differently and a tensor nested to the wrong depth looks identical in Objeck. A failed call returns Nil with the reason in EndPoint->GetLastError(), and a response body that will not parse is reported verbatim, since both protocols report errors as JSON and anything else means a proxy or a truncated response answered. 49 assertions, none of which need a server.
  • API.Ollama advertised streaming completions and had none (#1027): the bundle comment claimed support while all eight requests the library can make send "stream": false, with no alternative path. code_doc generates the published API pages from that comment, so the claim shipped to users. It now states the actual behaviour -- a request completes before returning, so a long generation produces nothing until it finishes -- which is more useful than silence, since first-token latency is most of the perceived speed of a local model.

Machine Learning

  • Out-of-fold scores, a fold row mapping, and strata keys (#1035): CrossValResult->GetOofScores returns one score per row from the fold model that did not train on it, which is what a threshold has to be chosen from if it is not to leak a row into its own score. FoldSplit->GetTestRows reports which original rows a fold's test matrix holds: Split fills it by walking rows in ascending order while StratifiedKFold returns a shuffled index vector, so pairing a score with the fold vector's k-th index silently scrambles them -- measured on a 3000-row set, a pooled AUC of 0.997 read 0.539 while every per-fold AUC still read 0.99. Evaluate gains an overload taking a stratification key, so folds can preserve the distribution of attack families or any other sub-population rather than only the binary label. LogisticRegression implements ScoreModel, so a linear baseline goes through the same path as the tree classifiers.
  • Metrics at a given threshold, and bootstrap intervals (#1036): Metrics->AtThreshold returns a ThresholdResult -- the four confusion counts with recall, false-positive rate, precision and accuracy read off them -- for one supplied cutoff, the inverse of RecallAtFpr. Metrics->Bootstrap resamples scored instances in pairs through a ScoreMetric interface (AucMetric, RecallAtFprMetric, AveragePrecisionMetric) and returns a ConfInterval. A resample can draw a single class, which leaves AUC undefined; those are discarded rather than averaged in, and the usable count travels with the interval, because an interval built from a fraction of the requested draws is not the interval that was asked for. Metrics->Percentile is exposed for statistics the bundle does not implement.
  • Base-rate precision, label shuffling, and per-group recall (#1038): Metrics->PrecisionAtBaseRate reprojects a measured operating point onto an assumed prevalence, with an overload taking a ThresholdResult; documented as a bound rather than a prediction, since it assumes both rates carry over. Metrics->ShuffleLabels is a seeded permutation for the shuffled-label control, returning a copy so the real labels survive to score against. Metrics->RecallByGroup returns a GroupRecall per group carrying the positive count beside the rate, and reports a group with no positives rather than omitting it. Metrics->UnseenGroups is the set difference for categories never trained on.

  • The release key is published where the repository cannot vouch for it, and a weekly job checks it (#723, phase 4): obu refuses a manifest it cannot verify, and its refusal message sends the reader to the public key -- which, until now, they could only obtain from the repository they were trying to verify. Measured rather than argued: without O_NOFOLLOW the updater suite leaves the symlink's target behind.   • A scaler can now learn statistics once and reapply them (#980): the static StandardScaler could only standardise whatever matrix it was handed, which cannot express the one correct thing to do across a train/test split. [v2026.9.4] - 2026-09-15

A corrective release for the compiler: two optimizer rewrites computed some integer divisions wrong at the default optimization level, with no error. Programs compiled with v2026.9.3 or earlier at -opt s2 or -opt s3 (the default) should be recompiled.

Bug Fixes

  • Integer division by a power of two rounded the wrong way at -opt s2 and -opt s3: strength reduction replaced n / 2^k on a local with an arithmetic right shift. A shift rounds toward negative infinity and integer division truncates toward zero, so a negative dividend that was not an exact multiple came out one too low: -7 / 2 gave -4, -1 / 1024 gave -1.   • 1 / n evaluated to n at -opt s3: a peephole pattern meant for x / 1 matched LOAD_INT_LIT 1; DIV_INT, but the value pushed last is the left operand, so it removed the division from 1 / n instead. The pattern is gone
  • The compiler crashed folding INT64_MIN / -1: constant folding at -opt s1 and above divided the two literals in C++, which faults on x64 (0xC0000095), so obc exited with no message and no output file. The fold is skipped and the division is left to run time, as for a zero divisor
  • Deserializing an object array with a Nil element corrupted the enclosing object: the deserializer wrote each Nil element into the object's next field slot instead of into the array, so the array field itself read back as Nil and every later field shifted. serial_nil_array_element.obs round-trips an object with Nil elements between its fields

Spawned interpreters now attach to the one debugger; the model is all-stop, which is what the stop state already assumed — a thread reaching the hook while another owns the stop waits its turn, and three threads on one breakpoint stop three times with their own frames. Each thread gets a stable small id and its last source position: obd gains a threads command, DAP reports the real list, and the stopped event names the thread that stopped. Conditional breakpoints evaluate against the stopping thread's frame (the fixture proves step = 200 is satisfiable only in worker 2). Three CLI tests in both harnesses, six DAP checks in a new suite

Bug Fixes

  • JIT on ARM64 and Linux x64: a constant character stored into a Char[] overwrote the elements after it (#781) — the char-array store's constant case wrote 8 bytes: ARM64 stored the whole register (its move_imm_mem32 went through the 64-bit store) and AMD64 outside Windows a movq (its move_imm_mem32 was move_imm_mem). Virtual Machine

  • A call between compiled methods costs 16 ns instead of 26 (docs/JIT_CALLING_CONVENTION_DESIGN.md, phase 1) — the bridge every compiled call crosses took two critical sections and cleared a 768-byte frame buffer per call. Frames come from a per-thread pool with no lock now, zeroed on acquire for exactly the local space the method declares (which is what a local that is declared but never assigned relies on to read as 0 or Nil), and a call whose callee is bound at compile time enters the bridge with the method itself rather than an opcode to switch on and look up. Recursion (Fib(32)): 0.22 s to 0.13 s compiled, 0.39 s to 0.25 s interpreted, since the interpreter's calls cross the same pool; a compiled loop calling a field-touching method 0.53 s to 0.34 s. The register-argument convention that removes the rest is phases 2 and 3 of the design
  • A compiled method's entry and exit are a third shorter (AMD64; the design's phase 2) — a method that never uses a float register no longer saves and restores XMM10-XMM15 on Windows (the blocks are patched into a jump over themselves once the body is emitted), the frame is zeroed with straight stores instead of a microcoded LOOP, and the operand-stack arithmetic around parameters, returns and call results is computed once per sequence rather than per value. A compiled call goes from 16.3 ns to 14.4 ns; what remains is the C++ bridge, which the design's phase 3 replaces
  • A compiled method's entry and exit are shorter on ARM64 too (the design's phase 2, its section 12) — the arguments are read below one top pointer and the results popped with one scaled load, the frame is zeroed with stp xzr, xzr pairs instead of a five-instruction loop (nineteen trips for a one-local method), D8-D15 are saved and restored only by a method that takes one, and the prologue's frame-size immediate is computed exactly rather than ORed onto a template that held 96. A compiled call goes from 17.1 ns to 13.4 ns on an M4 Max, Fib(32) from 0.135 s to 0.103 s; jit_entry_shapes.obs covers the shapes the entry and exit take
  • The ARM64 JIT allocates from twelve general registers (F4 on ARM64) — X12-X15 join X0-X7, handed out after them, so a method whose expressions carry a ninth to twelfth temporary compiles instead of falling back whole; the backend does not spill, and the bytecode pushes every term of a chain before its first operation, so a ten-term sum needed ten registers. jit_entry_shapes.obs's eleven-term sums compile now and fell back before (a ten-term version fit Windows x64's ten registers exactly and exposed a miscompile there, #773); the six loop kernels of jit_probe.obs and the call probe are unchanged within noise
  • A compiled call on ARM64 goes straight into the callee (the calling-convention design's phase 3 and native entry, its section 13) — every compiled method gains a second prologue a compiled caller calls with self, its stack pointer and the end of its outgoing area in X0-X2, the frame record built in the callee's own frame and pushed on the call stack; RTRN returns the value in D0; virtual and func-ref sites keep inline caches. The C++ bridge is the slow path. A compiled call goes from 13.8 ns to 7.4 ns on an M4 Max, Fib(32) from 0.107 s to 0.050 s, a virtual call loop from 0.0345 s to 0.016 s
  • ARM64 JIT: a float pending across a libc call no longer sends the method to the interpreter — the libc helpers behind Sin, Cos, Pow, Log and the rest spilled pending integer temporaries around the call but gave up on a pending caller-saved float; each is parked in a free callee-saved D8-D15 register for the call now, two fmovs and no memory. Arith:Mix, the equivalence fixture's one standing fallback on ARM64, compiles, and OBJECK_JIT_REPORT=1 on the fixture is silent there for the first time
  • A compiled method calls a compiled method directly (AMD64; the design's phase 3, first step) — a call between compiled methods went through a C++ bridge: an eleven-argument entry, a frame from the pool, a release. The caller now reads the callee's entry address from one word on the method, builds the callee's frame record on its own stack, pushes it on the call stack and calls the entry itself; a callee without native code yet, or a full call stack, takes the bridge as before, and a callee's error status is reported by JitNativeCallError naming both methods. A compiled call goes from 14.4 ns to 7 ns and Fib(32) from 0.115 s to 0.071 s; on master the call was 26.5 ns and Fib(32) 0.208 s. virtual and func-ref calls still take the bridge. Two tests cover the exits: a directly called callee that dereferences Nil, and recursion past the call stack's limit
  • A virtual call from compiled code costs what a bound one does (AMD64; the design's phase 3, second step) — each virtual call site keeps a small inline cache of receiver class, resolved target and entry; a hit compares the receiver's class word with the last record and calls the entry directly, a miss resolves the override through the receiver's class and fills a record, and a site that sees more classes than it holds stays on the bridge. A monomorphic virtual call goes from 18 ns to 7.5 ns. vm_jit_equiv.obs exercises a six-class site beside a monomorphic one
  • A func-ref call from compiled code takes the same cache (AMD64; the design's phase 3, third step) — a call through a function reference or closure is keyed by the func-ref's packed word, so it too calls its target's entry directly after the first call; about 15 ns per call, the bridge's share, are gone. The patched DYN_MTHD_CALL_JIT opcode, which the interpreter writes at a site when a callee with matching operands compiles, is now emitted as the same call; a method holding one failed to compile before. vm_jit_equiv.obs exercises one site alternating between two references beside one that keeps a single reference
  • Compiled methods take their arguments without the operand stack (AMD64; the design's section 11, the register-argument entry) -- every compiled method now has a second entry that a compiled caller enters with self and the caller's frame pointer in registers and the arguments in the caller's outgoing area, its frame record built in its own frame; the result comes back in XMM0 instead of through the operand stack, and the caller's marshalling, the callee's count traffic and the sections-8-to-10 record building on the caller's stack are gone. The bridge entry stays for the interpreter and for a callee not compiled yet. A bound call goes from 7.0 ns to 5.5 ns and a virtual one from 8.0 ns to 6.0 ns; where the cost is latency rather than instruction count the gain is larger: Fib(32) from 0.072 s to 0.043 s (0.208 s on master before the design), and a func-ref call to less than half. vm_jit_equiv.obs gains probes for every value shape across such a call (Float arguments and results as literals, locals and registers; a call with no arguments; eight arguments; a Nil result; receivers held only by the callee while it allocates; a func-ref result, which keeps the bridge), byte-identical across the three modes
  • The Linux x64 JIT allocates the same eight registers as Windows -- the POSIX backend had four pool registers and three auxiliary ones where Windows had R8-R11 in the pool since batch 3, so an expression with five live values, or a method with a dozen locals, quietly ran in the interpreter on Linux (OBJECK_JIT_REPORT=1 on the equivalence fixture named two of its own probes). R8-R11 join the Linux pool, the prologue no longer pushes them (they are caller-saved, and every path that calls out spills or pushes them), and the write barrier saves the four of them. RealCall 0.140 s to 0.128 s on Linux
  • AMD64 JIT: a quarter less machine code for the same programs -- every memory operand was encoded with a four-byte displacement (the ModRM helper fixed mod=10), so a frame slot or a field took seven bytes where four do; every add, subtract and compare of an immediate against memory took a four-byte immediate; a boolean result took four instructions and a second register (mov 0, mov 1, compare, cmov); the prologue zeroed the frame one word per eleven-byte store. Displacements and immediates that fit in a byte now take one (mod=01, 0x83), a boolean is setcc and movzx, and the frame is zeroed sixteen bytes at a time from a cleared XMM0. The equivalence fixture's 84 methods went from 292,958 to 222,755 bytes of code, byte-identical output in every mode; the call kernels gained a few percent
  • The hottest integer locals of a loop live in registers (AMD64: up to three in R13–R15) — loaded at the loop header, read and written as registers inside, stored back on every exit; OBJECK_JIT_REPORT=1 names each pinned loop and OBJECK_JIT_PIN_MAX / OBJECK_JIT_PIN_SKIP turn it off for bisecting. Design in docs/JIT_LOOP_LOCALS_DESIGN.md

The measured findings of docs/JIT_CODEGEN_ASSESSMENT_2026_09.md (#728), landed in #731, #732 and #733 with the interpreter/JIT equivalence fixture, the flag tests and the regression suite (normal, and with every method JIT-compiled) green, and all five CI legs green on the combined tree:

  • a->Size() is inlined by the JIT (AMD64 and ARM64) — LOAD_ARY_SIZE went through the interpreter callback: push the array onto the VM operand stack, call C++, read the result back, ~35 instructions and a call per evaluation of i < a->Size(). It is a nil check and one load now. An array-summing loop went from 6.0 to 0.75 ns per element (8×); a float dot product 2.7×
  • Division by a constant is a multiply (AMD64 and ARM64) — every constant divisor other than 0 and ±1 (and, on AMD64, powers of two, which already used shifts) now goes through its Granlund–Montgomery magic number: a 3-cycle imul/smulh and a few shifts in place of a 10–20-cycle idiv/sdiv. The recipe was checked against exact division for 480,000 cases including INT64_MIN, INT64_MAX, negative divisors and powers of two before it was emitted, and the equivalence fixture holds divisors of every shape. The assessment's integer loop (two constant divisions per iteration) runs 2.5× faster
  • Constant divisors skip the divide-by-zero check, and AMD64 saves RAX/RDX around a division only when they hold something — they were saved and restored unconditionally
  • The AMD64 allocator has eight general registers — R8–R11 join RAX–RDX (on Linux and macOS they were already reachable through the auxiliary pool). Four registers meant any expression with five live values spilled, or the method fell back to the interpreter: the equivalence fixture's own twelve-term division probe did exactly that, silently. Ten spill slots instead of six in the frame, and the write barrier's slow path saves the whole pool
  • A dense select is compiled as a jump table (AMD64 and ARM64) — JMP_TABLE was in neither backend's whitelist, so any method holding a select ran in the interpreter whole: parsers, tokenizers, state machines and dispatch loops, the code written with select. It is now a bounds check and an indirect jump through a table of 32-bit offsets placed inline after the jump (no data section, PC-relative). A tokenizer-shaped state machine over a 1,160-character buffer, 2,000 rounds: 0.099 s interpreted, 0.002 s compiled. The equivalence fixture gains eight select shapes (dense, gaps to the default, a negative base, Char labels, no other, nested, a break out of a pinned loop, a method-call selector). Design: docs/JIT_SELECT_TABLES_DESIGN.md
  • Main, a thread's Run, and any once-called method with a loop are now compiled — the auto-JIT counted calls, and these are called once, so a hot loop written at top level ran in the interpreter for the life of the program (~50x slower than the same loop in a helper; the documented workaround was a native helper). A method with a loop is compiled on its first entry or call; straight-line methods keep the ten-call threshold; a raised OBJECK_JIT_THRESHOLD (as the LSP server sets) turns both rules off. Found on the way: the loader's classless $Initialization$ routine's call to Main was never patched to the JIT opcode, so a compiled Main was still interpreted for its one call — dispatch now follows the callee's native code. A 2e8-iteration loop: 3.65 s in Main and 3.52 s in a Run before, 0.08 s and 0.13 s after (jit_entry_compiled.obs). Design: docs/JIT_ENTRY_COMPILE_DESIGN.md
  • The hottest Float locals of a loop live in XMM6–XMM9 on Windows — the float half of loop-local pinning: up to four Float locals per loop stay in callee-saved XMM registers for the loop's extent, written back on every exit, alongside the three integer pins in R13–R15. Linux and macOS keep every XMM caller-saved, so nothing changes there (ARM64's D8–D15 are the follow-up). The assessment's FloatDot kernel: 0.048 s → 0.021 s. Six new fixture probes cover accumulators, a float through a nested loop, mixed int/float pins, more floats than registers, a break, and calls inside the loop
  • Array element addressing is one instruction (AMD64 lea with a scaled index; ARM64 add with a shifted register) — the index and the bound were both shifted by the element size before the compare, which changed nothing about the comparison, and the address was then built with two adds
  • Windows: JIT code saves XMM10–XMM15 — the allocator hands out those registers and the Windows x64 ABI makes them callee-saved; the JIT'd function is entered by a plain C++ call whose MSVC-compiled caller may keep values in them across the call, and nothing saved them. 96 bytes in the prologue, restored in the teardown; Linux and macOS have no callee-saved vector registers
  • OBJECK_JIT_REPORT=1 names every method the JIT hands back to the interpreter and why (an unsupported opcode, or a compile that failed part-way, with the instruction index). One unsupported instruction returns the whole method to the interpreter and nothing said so — the equivalence fixture's own division probe turned out to be interpreted because a twelve-term expression exhausted the AMD64 allocator's four registers
  • The interpreter/JIT equivalence fixture gains probes for Size() in a loop condition and body, a multi-dimensional Size(), and constant divisors of every shape (small, negative, above 32 bits, composite)
  • --jit=off / --jit=<calls> and --lib-path=<dir> — the JIT tunables existed only as environment variables documented in a comment inside jit_common.h, so "does it still happen with the JIT off?" could not be asked without reading source. The environment forms remain as the legacy path. The drain would also have lied had it been called: it reports "drained" when at most one interpreter is registered, and obd, unlike obr, never registered its own

StackInterpreter::debugger was set by exactly one constructor, and spawned VM threads use the default one, which left the member indeterminate while Execute's hot loop called through it on every instruction. It read as a -debug problem rather than a threading one because the hook touches nothing until a line number exists, and without symbols every line number is -1. _DEBUGGER is defined only for obd, so obr was never affected and the VM regression suite could not have caught it. Breakpoints and stepping still do not reach inside spawned threads, but they run

  • Windows ARM64 shipped without its runtimes: no C++ redistributable, because VCToolsRedistDir is empty on the ARM64 runner, and OpenCV without its image codecs. Nothing checked either. Because the traps compile unconditionally, "the API exists" proved nothing, and callers could not tell not supported from the network failed &mdash; which is how the Windows gap went unnoticed.
