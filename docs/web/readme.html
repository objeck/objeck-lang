v2026.11.4

  • A toolkit for AI agents — API.Agent is a provider-neutral tool-use loop for Claude, OpenAI, Gemini and Ollama with cancellation, budgets, bounded tool calls and a trace; mcp is a Model Context Protocol server and client over stdio and streamable HTTP; System.Actor adds actors with supervision; and llm_util, rag and System.Telemetry add prompt templates and JSON Schema checks, a retrieval-augmented generation kit and inference timing, all in Objeck.
  • OpenAI tool calls — Completion->CompleteWithTools sends a tools array to Chat Completions and Choice->GetToolCalls() returns the calls the model asked for, so the OpenAI client takes part in the same tool loop as the other providers.
  • Boosting and forecasting — System.ML.Boost is gradient boosting (regressor and classifier, early stopping, feature importances) and System.ML.TimeSeries is forecasting (imputation, differencing, ACF, an ADF test, exponential smoothing), both in pure Objeck.
  • ONNX on the GPU — DeviceTensor and BoundSession keep tensors in the provider's memory (ResNet-34, batch 32, RTX 4090: 48.9 ms per Session->Run, 6.1 ms with the data resident), ep=tensorrt adds an engine cache and CUDA graphs, Half, BFloat16 and Quantization convert exactly for FP16 and INT8 models, and an inference no longer holds up the garbage collector or a session shared by threads.
  • Editor support — the language server offers inline completion (off by default, local-first), inlineValue, linkedEditingRange, onTypeFormatting, willRenameFiles and variable semantic tokens, and obd --dap adds stepInTargets, goto, cancel, disassemble and the invalidated and progress events, halts a running program on disconnect, and verifies breakpoints against the program.
  • Time limits for HTTP — HttpClient and HttpsClient take SetConnectTimeout, SetReadTimeout and SetDeadline (connect, handshake, reads, redirects and retries), where before a server that dribbled one byte at a time could keep a request alive indefinitely.
  • A thread's error need not end the process — --thread-faults=isolate (or OBJECK_THREAD_FAULTS=isolate) ends only the thread that raised an uncaught error, prints its stack, releases its locks and lets the others run.
  • Safer secrets — the OpenAI, Gemini and Anthropic clients refuse the API key while OBJECK_TLS_INSECURE_SKIP_VERIFY is set, and Cipher.Encrypt->AES256 writes AES-256-GCM with a PBKDF2 key and a random salt and nonce (the old format is still read, and is no longer produced).
  • Input and files — Console->ReadLine returns Nil at the end of input, and File records I/O errors (IsOK(), GetLastError(), ClearError()) instead of ignoring them.
  • Faster generated code — the Linux x64 JIT keeps Float loop locals in registers, the ARM64 JIT pins loop locals in callee-saved registers, more methods are JIT-compiled instead of interpreted, the optimizer folds integer identities and uses a control-flow graph for loop-invariant code motion and dead stores, and obc resolves names about 27% faster.
  • Compiler and runtime fixes — String->New(Byte[]) no longer reads past the array, a method chain on a parenthesised calculation keeps every call, a local declared without a value in a loop starts empty each iteration, dead-store elimination keeps a store a handler reads, loop-invariant code motion no longer hoists an observable store, function references to method ids of 32768 or more work, threads making the first call of one long-running method no longer run it 20x slower, and an ARM64 hang on the minimum Int is gone.
  • Library fixes — KNearestNeighbors->Query, bounded LevenshteinDistance and the threaded VectorIndex search are corrected at their edges, SentimentAnalyzer, View->ToJson, Table->Save and the Gemini and JSON-schema parsers no longer carry a previous value into the next, and a Nil collection lookup reports not-found.
  • Build and release — core/lib/*.obl are rebuilt from source and compared in CI, docs/api.zip and the Windows objeck.rc files are generated instead of committed, and tools/hpc/alderaan runs Objeck on a Slurm cluster without root.

v2026.11.3

  • Regular expressions are 4.5 to 27 times faster — RegEx finds where the longest match ends with a lazily built DFA, one table lookup per character, and skips start positions that cannot begin a match. On 680 KB of text a class-first search went from 0.55 s to 0.043 s and an alternation with a group from 0.99 s to 0.09 s. Patterns with \b or \B, or that need more than 1,024 states, run on the NFA as before; capture groups are unchanged. A RegEx can now be shared by threads (matching on one instance is serialized).
  • RegEx bugs fixed — {n} was read as {n,}, so a{2} matched aaa; it now means exactly n, and {n,} is accepted. ReplaceAll matched against text it had already rewritten (\bx on xx with - gave --); it now works in one pass over the original. ^a, ^a+, ^a$ and ^$ were rejected; they compile. Unknown letter or digit escapes, including the backreference \1, were silently read as the literal character; they and a trailing backslash are now an error.
  • Parallel vector search — VectorIndex->SetThreads(n) splits a search over a large index into n parts on their own threads and merges them in the same order a single scan uses, so ids, scores and ties are identical. 100,000 vectors of 128 values, L2, top 10: 66 queries/s on one thread, 315 on sixteen.
  • Nearest neighbors and edit distance — KNearestNeighbors->Query keeps the best k in a heap in one pass instead of building and sorting an object per row: 200 queries over 50,000 rows of 16 values took 15.1 s and now take 0.057 s (13 to 3,506 queries/s). A k below 1 or a Nil query returns no neighbors instead of ending with an allocation error. TextSimilarity->LevenshteinDistance keeps two rows instead of the full matrix (20,000 pairs: 0.68 s to 0.12 s), and a new LevenshteinDistance(a, b, max_distance) stops at a ceiling; SpellChecker->Suggest uses it.
  • Nine new collection types and sturdier collections — Deque, MultiSet, UnionFind, Trie, OrderedHash, BiMap, PriorityMap (with decrease-key), FenwickTree and BloomFilter join the collections library, with one shared merge sort for Vector and CompareVector, Vector insert, slice and add-all, doubling growth, and a Stack that no longer crashes near 500,000 entries. A Nil key or value lookup now reports not-found instead of ending the program. Thirteen new regression tests cover them.
  • Library workloads are measured — docs/performance.md has a new Library workloads section with the regex, vector search, nearest-neighbor, edit-distance, string and JSON timings behind these numbers, and what it did not measure.

v2026.10.2

  • Query.Structured, a columnar engine — every column is a typed array with a null bitmap, text is dictionary-encoded, and 65,536-row groups carry zone maps so a filter skips what it cannot match. Queries return views with nothing copied, a where is compiled once into typed predicates, prepared statements take ? placeholders, and a method-chaining API (Col("value")->Gt(0.5)) sits beside SQL. The SQL parser is new: INNER/LEFT JOIN through a Catalog, GROUP BY with COUNT/SUM/AVG/MIN/MAX/MEDIAN/STDDEV and HAVING, multi-key ORDER BY ASC|DESC, LIMIT/OFFSET, DISTINCT, MATCHES, INSERT/UPDATE/DELETE/CREATE TABLE, and SQL expressions in every clause (score * 100 as pct, group by x % 10, having sum(a) / count(*) > 2, on t.n + 1 = u.w), evaluated 1,024 rows at a time and reduced to the ordinary filter where an index or zone map can serve it. The old API keeps its signatures and results. At 100,000 rows on Windows x64, a where went from 0.558 s to 0.023 s, order by from 3.16 s to 0.096 s and Sum from 0.051 s to 0.004 s (#1291, #1295, #1298, #1301, #1303, #1325, #1367, #1398, #1416, #1417)
  • Files and URLs are tables — a quoted path in FROM or JOIN is read by its extension (.csv, .tsv, .json, .jsonl, .xml, .otab, each also .gz), csv('data.txt', delimiter => ';') sets options, a glob reads several files as one table with a _file column, an http(s) path goes through a download cache revalidated with ETag and Last-Modified, and an archive member or worksheet follows the path after a dot: from 'results.zip'.'2026/runs.csv', from 'budget.xlsx'.'Q1 2026'. Catalog->SetFileAccess(false) refuses them all. The URL download cache is correct across processes that share the temporary folder (one folder of immutable versions per URL and one small note, published by an atomic rename), and a file rewritten within the second of its last read is read again (#1303, #1366, #1384, #1391)
  • Sources — CsvSource, FilesystemSource (flat or recursive with parent keys), ObjectSource<T>, TextSource (regular-expression capture groups become typed columns), JsonLinesSource, JsonSource and XmlSource (nested parts become child tables), HttpJsonSource, ArchiveSource (zip, tar and gzipped tar; nothing is extracted, and traversal, duplicate or overlapping members, zip bombs and CRC mismatches are refused), XlsxSource (typed cells, both date systems, merged cells kept or filled). In their own libraries so a file-only program loads no native module: query_ml's MlResultSource (folds, out-of-fold predictions, thresholds and intervals from System.ML), query_odbc's OdbcSource (typed from the driver, with columns and a SetWhere condition pushed into the SQL, names quoted and values bound), query_vision's VisionSource (images and a detector's boxes as tables; YoloDetector over API.Onnx) (#1329, #1331, #1334, #1350, #1352)
  • The .otab file — Save, Load, ToBytes, FromBytes and Append; every block and the footer carry a CRC32, a save writes path.part and renames it into place, and OtabFile reads only the footer and the columns named, over HTTP range requests as well as from disk. A table opened with TableStore->New or Table->Open is durable: every statement goes to a change log before the call returns, Checkpoint folds it into a save, and a writer lock refuses a second writer. Index definitions are kept in format 2, written only for a table with indexes. Byte-exact spec in docs/OTAB_FORMAT.md (#1315, #1321, #1365)
  • Hash and sorted indexes, and a planner that explains — CreateIndex(column, IndexKind->HASH | SORTED), SQL CREATE INDEX and DROP INDEX; a hash index serves = and IN, a sorted index ranges, BETWEEN, ORDER BY, GROUP BY and Min/Max. A lookup gives candidate slots and the whole condition is tested on them in slot order, so results equal a scan's by construction. Explain shows the plan. At 1,000,000 rows on Windows x64, equality on an Int 73 ms to 0.02 ms, ORDER BY value LIMIT 10 2.8 s to 0.08 s. Several threads may query one table at once, including right after a write (#1351, #1364)
  • Serving, bridges and threads — TableServer (query_server.obl) answers GET /tables, GET /tables/NAME and GET or POST /query as CSV, JSON or .otab, refusing anything but a SELECT, any file or URL named in a query, and any result over its row limit; RemoteSource queries a published table as a local one. ToCsv, ToJson, ToMatrix and FromMatrix on View and Table. GetError answers the calling thread's own error, a Catalog can be shared between threads, and Thread->GetCurrentId() and Thread->IsAlive(id) are new. TableServer answers requests at once, and BeginWrite() and EndWrite() bracket the program's own changes to published tables (#1325, #1378, #1389)
  • Hugging Face models without Python — System.NLP.Onnx.TextClassifier opens a model folder (what save_pretrained writes, with an ONNX export) and classifies text as pipeline("text-classification") does: its tokenizer, labels, scoring, inputs and maximum length come from the folder, and token ids and scores match Python. System.AI.Hub.HubClient (ai_hub.obl) downloads a model by name, as from_pretrained does, into a cache that checks every file's size and SHA-256 against the Hub, works offline, and sends HF_TOKEN to the Hub only. BpeTokenizer is RoBERTa's and GPT-2's tokenizer, matching the tokenizers library id for id and offset for offset.
  • Downloads of any size — HttpClient->GetToFile(url, path) and HttpsClient->GetToFile stream a body to path.part and rename it into place only when it is complete; Get no longer returns no content for a body over 256 MB.
  • Interpreted code no longer has an Int rewritten by a collection — a minor collection treated every operand-stack word that looked like a young object's address as a reference, so an Int that equalled one changed value (#1452). The VM now computes a reference map for each method, and interpreted frames skip the words the maps prove are Int or Float; anything not proven keeps the old handling, and typing stops above any frame that compiled code sits under (compiled frames are planned for the next release). OBJECK_GC_ROOTS=conservative restores the old behavior and OBJECK_GC_ROOTS=audit checks the maps against the live stacks (#1466, #1470, #1478).
  • Instance IDs survive the collector — GetInstanceID() was the object's address, and a minor collection moves young objects, so a Hash or Map keyed by BasicCompare objects lost its entries once the keys moved. The ID is now a number assigned once per object, which the collector moves with it.
  • TLS reads time out on a quiet peer — a TLS client socket had no receive timeout, so a peer that stopped sending without closing blocked a read for good; it now times out after 300 seconds (OBJECK_TLS_RECV_TIMEOUT sets it). A connection reset mid-reply is a failed request, not a 200 with an empty body.
  • Security: credentials stay with their origin — a redirect to another host or port no longer receives the caller's Authorization, Proxy-Authorization or cookies, as in curl and Python requests; API.OpenAI and API.Google send their tokens this way.
  • Allocation no longer searches, and collection follows the live heap — the old generation's free-block cache held blocks of any size in a power-of-two list, so after a major collection every allocation of a slightly larger size walked the whole list; each list now holds one size class, and the first read of a 4,000-row text column went from 0.96-1.03 s to 0.023 s.   • Full-screen editor in obi — /e opens raw-mode terminal editing over the REPL buffer: syntax coloring driven by the compiler's own scanner, damage-diffed rendering, CJK/tab-correct widths, undo/redo with coalesced typing, Shift-selection and a clipboard, plus an opt-in vi profile (F2). F5 compiles and runs the buffer as a subprocess, streaming its output into a pane that Esc can cancel, and F8 walks the cursor through compile errors. Header-only, with no build-system changes on any platform
  • HTTP/3 on Windows — Http3Client now works on Windows 11 / Server 2022 and later, backed by WinHTTP over MsQuic. It had shipped documented-and-dead: the trap handlers compile unconditionally, so the API was present and every request simply failed. WinHTTP treats HTTP/3 as a preference, so every request asserts the protocol actually used and fails rather than silently downgrading. No vendored QUIC library, no second TLS backend, no new DLL to deploy
  • Five HTTP request-injection fixes — the most severe needs only a URL: Url->New does not sanitize, and the path and host were appended verbatim into the HTTP/1.1 request line, so a CR/LF split the request line itself. Caller-supplied header values and content types were injectable the same way across HTTP/1.1, HTTPS, HTTP/2 and HTTP/3; a new Web.HTTP.HeaderCheck validates names, values and request targets per RFC 9110/9113 at every serialization site. Separately, HTTP/3 connection IDs could be uninitialised stack memory when the CSPRNG failed, since the gnutls_rnd return value was ignored — a memory disclosure in the cleartext QUIC Initial header
  • obu updater — obu check compares the installed version against the latest GitHub release; obu update and obu rollback (Linux/macOS) download the platform archive and its SHA256SUMS, verify the digest before touching disk, then do an all-or-nothing staged swap with a post-install check and automatic rollback. No shell is used for the download, extract or swap. Every release now ships a SHA256SUMS asset
  • AddHeader now actually sends headers on HTTP/2 and HTTP/3 — both clients stored headers on the Objeck side and then dropped them, because the trap signature had no headers argument and nothing ever wrote the map the native backends were already reading. Verified by a server echoing the value back, not by a status code. HTTP/1.1 was never affected
  • ARM64 JIT clobbered a general register on every float compare — move_freg_freg addressed the general register file rather than the FP file, because the Register enum restarts float numbering at D0 = 0. When the clobbered register held a live pointer, the next use followed a float bit pattern as an address — the long-open "memory corruption of free block" crash, whose faulting PC 0x3F947AE147AE147B is the IEEE-754 bits of 0.02. Correcting the encoding then exposed a stray copy that zeroed the divisor of every JIT float division. AMD64 was correct throughout
  • v->Pow(10) computed Pow(10, v) — 100 instead of 1024 — whenever the receiver was a variable, instance variable or array element; literals were correct, so the two spellings of one call disagreed. All 29 multi-argument primitive functions were affected. A calculated receiver in an expression, (1 + 1)->Pow(10), corrupted the heap outright because the emitter dropped the call arguments
  • Divide by zero crashed at default optimization — the constant folder kept a zero-divisor division for its runtime trap but emitted it before its operands, turning a clean trap into a silent crash. Modulus by zero never trapped at all, and now traps exactly as division does
  • Runtime feature reporting — runtime.feature.http2 and runtime.feature.http3 report which protocol engines were actually compiled in, so a caller can tell not supported from the network failed. Relatedly, obd had shipped with HTTP/2 and HTTP/3 compiled out, and HTTP/3 was silently unavailable on Linux ARM64
  • ONNX inference hardening — fixed an out-of-bounds read when a model exported mismatched KV key/value tensor counts, guarded the logits rank/offset access, surfaced an unsupported logits dtype instead of silently sampling token 0, and made the token sampler safe on empty/degenerate distributions
  • Debugger String rendering — the DAP formatter read a String's backing-array capacity instead of its length, returning NUL-padded values on POSIX platforms; both front ends now read the length from the String itself via a shared layout header
  • Nil-safe operators — a?->b() calls b only when a is non-Nil, yielding Nil instead of faulting, and a ?? b supplies b when a is Nil (evaluating b only when needed). A single ?-> guards the whole rest of a chain, so maybe?->Trim()->ToUpper() is safe throughout, and the two combine: maybe?->ToUpper()->Size() ?? -1. Both desugar onto the existing Try()/Otherwise() intrinsics, so no new bytecode is emitted and the JIT backends and VM are unchanged. Spelled ?-> rather than ?. because Objeck's member accessor is ->

Each returned a Result[] through the local argument array and failed its cast; they now write into the analysis instance the way find-references and document-symbols already did
  • Language server resolved the wrong method — a method's line range was converted to the editor's 0-based numbering at its start but not its end, and the end records the token after the closing brace, so every method overran onto the next declaration. Any cursor past the first method of a class resolved to the first method, affecting go-to-definition, find-references, hover, rename and call hierarchy
  • Chained calls after a nil default — anything written after Otherwise() was silently dropped, so x->Otherwise("abc")->ToUpper() returned "abc". Try()/Otherwise() also now resolve on an indexed receiver, so arr[i]?->m() compiles
