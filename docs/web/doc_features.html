Objeck Language Features

All documentationView docs/FEATURES.md on GitHub

Guide to Objeck's language features with examples. Each section is implemented in the current master unless it says otherwise; the design notes it links to give the rationale, the alternatives rejected and the known gaps. The language features added in v2026.10.1 (named arguments, ref parameters, array literals with expressions, jagged arrays, method-level generics, System.Error with try/on/finally) each ship with a programs/regression/<feature>*.obs test and bad_<feature>_*.obs negative tests; to check one, compile and run it with obc -src <file> -dest t.obe && obr t.obe, and again with obr --jit=off t.obe.

Object-Oriented Programming

Inheritance

class Triangle from Shape {
  New() {
    Parent();
  }
}

Interfaces

class Triangle from Shape implements Color {
  New() {
    Parent();
  }

  method : public : GetRgb() ~ Int {
    return 0xadd8e6;
  }
}

interface Color {
  method : virtual : public : GetRgb() ~ Int;
}

Field Accessors

@x : get : T writes the getter and @x : get set : T the getter and the setter; get and set are contextual words (a type named get is still a type), and a comma list shares the modifier. The getter is Get plus the field in PascalCase (the 2,000 hand-written accessors in the libraries and examples follow this: input_tokens is GetInputTokens, capacity is GetCapacity); a Bool is Is plus the name, a leading is_ or has_ is the prefix itself (is_error is IsError, has_uses is HasUses); the setter is Set plus the name without is_/has_. A method of the same name written by hand wins. Instance fields of a class only.

# before
@input_tokens : Int;
method : public : GetInputTokens() ~ Int { return @input_tokens; }
@model : String;
method : public : GetModel() ~ String { return @model; }
method : public : SetModel(value : String) ~ Nil { @model := value; }
# after
@input_tokens : get : Int;
@model : get set : String;

Test: field_accessors. The generated methods are made by the compiler, so the source-text doc tools (code_doc, doc_coverage.py) do not list them yet.

Constructor Field Promotion

In a constructor, a parameter written @name where the class has already declared the field @name fills that field: the parameter is name (and the argument's name for a named call), and the body starts with @name := name (after a leading Parent(..)). Defaults and named arguments work as for any parameter. A @name parameter with no field of that name is unchanged (the older style in programs/tests/prgm10.obs). Before this, New(@a : Int) {} made a parameter that shadowed the field, and the field stayed 0.

# before
class Point {
  @x : Int;
  @y : Int;
  New(x : Int, y : Int) { @x := x; @y := y; }
}
# after
class Point {
  @x : Int;
  @y : Int;
  New(@x : Int, @y : Int) {}
}

Test: ctor_field_promotion.

Default and Named Arguments

Trailing parameters can have default values. An argument can be passed by name, name: value, after any positional ones. Named arguments may come in any order, and they may skip any parameter that has a default, not just the trailing ones:

function : Train(data : Int[], epochs : Int := 10, rate : Float := 0.01, verbose : Bool := false) ~ Nil { ... }

Train(data);                        # every default
Train(data, verbose: true);         # skip epochs and rate
Train(data, rate: 0.1, epochs: 50); # any order
Point->New(y: 2, x: 1);             # constructors too

Arguments are evaluated in the order written. Named arguments work for the functions, methods and constructors of the program being compiled, and for those of libraries, which record their parameter names:

"abc"->Pad(num: 2, char: '*', is_left: true);  # "**abc"
Int->Clamp(value: v, min: 0, max: 10);

Virtual methods, function values and calls on a primitive value (v->Clamp(...)) do not take them: a call that tries is a compile error, never a silent positional call. A library's parameter names are part of its API. See NAMED_ARGUMENTS_DESIGN.md.

Reference Parameters

A ref parameter lets a function change its caller's variable. The call site says ref too, so a reader sees which arguments a call may change:

function : Swap(ref a : Int, ref b : Int) ~ Nil { t := a; a := b; b := t; }
function : Divmod(a : Int, b : Int, ref remainder : Int) ~ Int { remainder := a % b; return a / b; }

Swap(ref x, ref y);
q := Divmod(17, 5, ref r);   # q is 3, r is 2

The value is copied in and copied back after the statement, as Swift's inout is. A local, a parameter or a field can be passed. A call with ref arguments is a statement of its own or the right side of an assignment. See REFERENCE_PARAMETERS_DESIGN.md.

Array Literals

An array literal can hold expressions as well as constants; it is built when it is evaluated, the elements in the order written. Objects of several classes make a Base[], and primitives among objects are boxed:

x := 3;
squares := [x, x * x, Square(x + 1)];  # Int[]
row := ["id", x, 2.5, true];           # Base[]: String, IntRef, FloatRef, BoolRef
PrintEach([name, title->ToUpper()]);   # the variadic idiom: an array at the call site

Collection literals

An array literal takes the type of its target when the target is a Vector, CompareVector, IntVector or FloatVector (a declaration or assignment target or a return): it is the array those classes' constructors already accept, so the ->New(..)<T> and an AddBack per element are not written.

# before
v := Vector->New()<IntRef>;
v->AddBack(IntRef->New(1));
v->AddBack(IntRef->New(2));
# after
v : Vector<IntRef> := [IntRef->New(1), IntRef->New(2)];
nums : IntVector := [4, 5, 6];

It is exactly Vector->New([..])<IntRef>; elements of the wrong type give that call's error. The literal is not typed by a call argument (overloads are chosen before a target is known): assign it to a typed variable first. There is no map literal: Map has no array constructor to lower to. Test: collection_literals.

Jagged Arrays

T[][] is an array of T[] rows of any length, at any depth:

rows := Int[]->New[3];               # three rows, each Nil until set
rows[0] := [1, 2, 3];
rows[1] := Int->New[5];
rows[2] := [x, y];
total := rows[0][1] + rows[2][0];     # rows[i] is an Int[]; rows[i][j] an Int
triangle := [[1], [1, 1], [1, 2, 1]]; # a ragged literal is an Int[][]

function : Sum(rows : Int[][]) ~ Int { ... }

See JAGGED_ARRAYS_DESIGN.md.

The binding type test

if(value is Type name) { ... } runs the block when the value is a Type (or a subclass, or a class that implements it), with name bound to the value as that type:

# before
if(part->TypeOf(TextPart)) {
  text_part := part->As(TextPart);
  json->Insert("text", text_part->GetText());
}
else if(part->TypeOf(ImagePart)) {
  image_part := part->As(ImagePart);
  json->Insert("pixels", image_part->Pixels());
};

# after
if(part is TextPart p) {
  json->Insert("text", p->GetText());
}
else if(part is ImagePart p) {
  json->Insert("pixels", p->Pixels());
};

The name belongs to the block (each branch can reuse it; it is not visible in else or after the if) and is declared as name : Type is. The test is the whole condition of the if. A value that is more than a variable (items->Get(i) is TextPart t) is evaluated once. Nil is of no type: the test is false, where a bare Nil->TypeOf(T) is a runtime error. It compiles to if(value <> Nil & value->TypeOf(Type)) { name := value->As(Type); ... }. is is a keyword only in this position. Tests: type_test_binding, bad_type_test_*.

JSON literals

json{ ... } builds a Data.JSON.JsonElement where it is written (link the json library):

# before
request := JsonElement->New(JsonElement->JsonType->OBJECT);
request->Insert("model", model);
request->Insert("max_tokens", max_tokens);
messages := JsonElement->New(JsonElement->JsonType->ARRAY);
user := JsonElement->New(JsonElement->JsonType->OBJECT);
user->Insert("role", "user");
user->Insert("content", prompt);
messages->Add(user);
request->Insert("messages", messages);
request->Insert("stop", JsonElement->New(JsonElement->JsonType->NULL));

# after
request := json{
  "model": model,
  "max_tokens": max_tokens,
  "messages": [{"role": "user", "content": prompt}],
  "stop": Nil
};
request->ToString()->PrintLine();
# {"max_tokens":256,"messages":[{"content":"Hi","role":"user"}],"model":"m-1","stop":null}

A member's name is any String expression. A value is any expression JsonElement has an Insert for (a String, Int, Float, Bool or JsonElement), a nested { } or [ ], or Nil for null; names and values are evaluated once, in the order written. Anything else is a compile error at the value: The value of a JSON member is a String, Int, Float, Bool, Nil, JsonElement, or a nested { } or [ ]; this one is IntRef. The literal is an object at the top; an array is written inside one or built with JsonElement->New. It compiles to the New, Insert and Add calls shown above. json is a keyword only before {. Tests: json_literal, bad_json_literal_*.

Map literals

{key: value, ...} builds a map where it is written. Its type comes from its target: a declared variable or field, an assignment, or a return:

# before
status := Map->New()<IntRef, String>;
status->Insert(200, "OK");
status->Insert(404, "Not Found");
status->Insert(500, "Server Error");

# after
status : Map<IntRef, String> := {200: "OK", 404: "Not Found", 500: "Server Error"};
status->Find(404)->PrintLine();   # Not Found

function : Limits() ~ Hash<String, FloatRef> {
  return {"low": 0.25, "high": 4.0};
}
@cache := {};                      # the empty map, of the field's type

The targets are Map, Hash, OrderedHash, MultiMap, MultiHash, BiMap and IntMap. Each entry is an Insert(key, value) in the order written, so keys and values are checked and boxed as Insert does; an entry of the wrong type is an error at the entry (An entry of this map literal is String: IntRef; this one is String: String), and the same constant key twice is an error for a map that keeps one value per key. With no typed target (an inferred m := {...}, an argument, inside ?) the literal has no type and the compiler says to declare one. Tests: map_literal, bad_map_literal_*.

match, and select as a value

match picks an arm by the value of its subject. Used as a value, each arm is an expression; used as a statement, each arm is a block. Patterns are what select labels are (integers, characters, strings, enum items), | joins several, and other takes the rest:

enum Color { Red, Green, Blue }

# before
function : Name(c : Color) ~ String {
  select(c) {
    label Color->Red: { return "red"; }
    label Color->Green: { return "green"; }
    label Color->Blue: { return "blue"; }
  };
  return "";
}

# after
function : Name(c : Color) ~ String {
  return match c { Color->Red => "red", Color->Green => "green", Color->Blue => "blue" };
}

match c {                               # the statement form
  Color->Red | Color->Green => { "warm"->PrintLine(); }
  Color->Blue => { "cool"->PrintLine(); }
};

On an enum, every pattern must be an item of that enum, and without other the patterns must name every item. Leaving Green and Blue out of the first example is a compile error at the match:

This 'match' does not cover every item of 'Color', missing: Green, Blue
	Add an arm for each missing item, or an 'other' arm.

so adding an item to an enum points at every match that has to change. A value form on an Int, Char or String needs other; its arms agree in type as the branches of ? do (an Int arm and a Float arm are an error, not a conversion). select is a value too, with its own spelling: select(n) { label 0: "none" label 1: "one" label 2, 3: "few" other: "many" }.

The subject is evaluated once and only the arm taken is evaluated, where the expression stands: inside &, ? or a loop condition a match runs only when it is reached. It compiles to the select statement it stands for (a dense table stays a jump table). match is a keyword only before its subject, which starts with a name (match kind {, match item->GetKind() {); elsewhere it is an ordinary name. A method whose last statement is a match statement still needs other or a return after it, as after a select. Tests: match_value, match_statement, select_value, bad_match_*.

Variable Scope

A local belongs to the block it is declared in, from its declaration to the end of that block. Within one block a name is declared once; the parameters of a method and the locals of its body are one block. A nested block (the body of an if, a loop, a select label, a lambda) may declare a name that an enclosing block already has: the block's own variable hides the outer one until the block ends, and the outer one is unchanged. A loop variable is a declaration in the loop's block:

k := items->Size() - 1;      # an Int
each(k : names) {            # the loop's own k, 0 to names->Size() - 1
  names[k]->PrintLine();
};
k->PrintLine();              # still items->Size() - 1

n : Int := 3;
if(n = 3) {
  n : String := "three";     # hides the Int for this block
  n->Size()->PrintLine();    # 5
};
n->PrintLine();              # 3

x := value declares x only when no enclosing block has one; otherwise it assigns to the nearest. To hide an outer name, declare the inner one with its type. Declaring a name twice in one block is the error Variable already defined in this scope. Tests: block_local_shadowing, bad_local_redeclared_in_block, bad_local_redeclares_parameter.

Nil-guard and bail

x := E ?? return V; (also ?? break; and ?? continue;) leaves when E is Nil, and otherwise binds x to the value. The block form x := E ?? { ...; return V };, and x ?? { ...; return }; for a variable you already have, run a block that must end in return, break, continue or Runtime->Exit(..) (a block that can fall through would leave x Nil, so it is an error). It is only a spelling of x := E; followed by if(x = Nil) { ... }; the value form a ?? b is unchanged. The guard belongs to an assignment or declaration statement, not to an argument.

# before
x := Find(v, i);
if(x = Nil) { return -1; };
return x->Get();
# after
x := Find(v, i) ?? return -1;
return x->Get();

Test: nil_guard, bad_nil_guard_*.

Nil Safety

value->TypeOf(Type) is false when the value is Nil (Nil is of no type), and Nil->As(Type) is Nil.

?-> calls a method only when the receiver is non-Nil, yielding Nil instead of faulting. ?? supplies a value when the left side is Nil.

# without them
city := Nil;
if(person <> Nil) {
  address := person->GetAddress();
  if(address <> Nil) {
    city := address->GetCity();
  };
};

# with them
city := person?->GetAddress()?->GetCity();

# '??' supplies a default; the right side is evaluated only when needed
name := lookup ?? "(unknown)";
port := config_port ?? ExpensiveDefault();

A single ?-> guards the whole rest of the chain, so you do not need one at every step:

# both calls are guarded by the one '?->'
text := maybe?->Trim()->ToUpper();

A chain that ends in a value type needs ?? to supply the result, since an Int cannot itself be Nil:

size := maybe?->ToUpper()->Size() ?? -1;

For a guarded value -- Bool, Byte, Char or Int -- the default replaces only a failure: size above is -1 when maybe is Nil and 0 when it is "". For a guarded object, ?? takes the default when the chain failed or yielded Nil.

Both build on the Try()/Otherwise() intrinsics, so a?->b() is exactly a->Try()->b() and a ?? b is a->Otherwise(b). One consequence worth knowing: Try() guards against most runtime errors in the chain, not only a Nil dereference — a?->Get(999) yields Nil on an out-of-range index rather than faulting. An invalid object cast is recovered too, in interpreted and in JIT-compiled code alike — the same program behaves the same way whether or not the failing method happened to be compiled. A call-stack overflow (more than --call-depth frames, default 16384) is recovered too, as a RuntimeError with the message call stack bounds have been exceeded, in interpreted and in JIT-compiled code: compiled call sites also check the native-stack floor (v2026.10.2; core_call_depth_max.obs).

A guarded call works as a statement too: t?->Close(); runs Close() unless t is Nil, and recovers a runtime error inside it. A method that returns nothing yields Nil through the guard.

Reading a recovered error

After a ?-> recovers, the error it took is recorded for the thread:

value := table->Get(key)?->Parse() ?? 0;
if(Runtime->HasError()) {
  kind := Runtime->GetErrorKind();   # NIL_DEREFERENCE, INDEX_OUT_OF_BOUNDS,
                                     # DIVIDE_BY_ZERO, INVALID_CAST, OTHER,
                                     # RAISED (Runtime->Raise)
  "skipped {$key}: {$(Runtime->GetError())}"->ErrorLine();
  Runtime->ClearError();
};

A Nil receiver is not an error: x?->M() with x Nil calls nothing. See RECOVERED_ERRORS_DESIGN.md.

Errors: raise, try, on, finally

An error is an object: System.Error, or a subclass of your own. Runtime->Raise raises one; a try block catches errors by type, and finally runs on every way out:

class ParseError from Error {
  New(message : String) { Parent(message); }
}

try {
  rows := Load(path);
  model := Fit(rows);
}
on(e : ParseError) {
  "bad row: {$(e->GetMessage())}"->ErrorLine();
}
on(e : DivideByZeroError) {
  model := Nil;
}
finally {
  log->Close();
};
  • on clauses are tested in order; an error none of them names is raised again after finally, so a typed try never swallows what it did not ask for. on(e : Error) takes anything.
  • The runtime's own errors are NilError, IndexError, DivideByZeroError, CastError and RuntimeError (a failed Runtime->Assert, a failing library call).
  • Runtime->Raise(e) in a handler passes the error on. An error raised in a handler still runs finally first.
  • return, break and continue may leave a try body or a handler, through finally; they may not leave finally itself.
  • try, on and finally are contextual: they can still be used as names.
  • ?-> still recovers from any error below a guarded call, and Runtime->GetLastError() returns the one it took.
  • An error nothing catches ends the program with Unhandled <class>: <message>.

A method with a try block runs interpreted (the JIT compiles its callees), as one with a ?-> does. System.Error carries a message only: GetMessage() and ToString(); the recovered kind is read with Runtime->GetErrorKind(). See ERROR_HANDLING_DESIGN.md.

Tail calls

A method's call to itself on @self in tail position (Down(); } or return Down();) is compiled as a jump at -opt s1 and above, so unbounded tail recursion runs in constant stack. The transform is skipped for Main, constructors, virtual methods, methods containing &/|, and methods with a Try() region of their own. A call on another instance of the class is a real call, and so is any call at -opt s0.

Anonymous Classes

interface Greetings {
  method : virtual : public : SayHi() ~ Nil;
}

class Hello {
  function : Main(args : String[]) ~ Nil {
    hey := Base->New() implements Greetings {
      New() {}

      method : public : SayHi() ~ Nil {
        "Hey..."->PrintLine();
      }
    };
  }
}

Type-argument inference

A constructor call may leave its type arguments out when the compiler can read them. It looks in two places, in this order:

  1. The declared type the object is stored into or returned as, when that is the class being constructed: a declared local, a field, an element of an array, or the method's return type.
  2. The constructor's arguments, when the constructors that take that many arguments agree on what each type parameter is. A primitive argument is held by its class, as it is when the type argument is written (7 for an IntRef).
class Scores {
  @names : Vector<String>;
  @by_name : Map<String, IntRef>;

  New() {
    @names := Vector->New();                  # Vector<String>, from the field
    @by_name := Map->New();                   # Map<String, IntRef>
  }

  method : public : Best() ~ Pair<String, IntRef> {
    best := Pair->New("", -1);                # Pair<String, IntRef>, from the arguments
    each(name in @names) {
      score := @by_name->Find(name);
      if(score > best->GetSecond()) {
        best := Pair->New(name, score);
      };
    };
    return best;
  }

  method : public : Above(limit : Int) ~ Vector<String> {
    above : Vector<String> := Vector->New();  # from the declared local
    ...
    return above;
  }
}

Before, each of those calls repeated a type the line already stated:

@names := Vector->New()<String>;
@by_name := Map->New()<String, IntRef>;
best := Pair->New("", IntRef->New(-1))<String, IntRef>;
above := Vector->New()<String>;

Both versions are in programs/regression/generic_inference_before_after.obs, which runs them side by side and prints:

best and count above 80: sol 96 2
PASS: type-argument inference before and after

The compiler only fills in what would have been written, so every check that follows is the one an explicit call gets: overload resolution, the type parameter's bounds and the match between the object and where it is stored. Written type arguments mean what they always did (Cell->New("text")<Base> is a Cell<Base>), and a declared target is used before the arguments (wide : Pair<String, Base> := Pair->New("key", "value");).

A call is refused, never guessed, when:

callreported as
items := Vector->New(); (no declared type, no arguments)Generic type mismatch for class 'Collection.Vector': expected 1 type parameter(s), got 0
anything : Base := Vector->New(); (the target is another class)the same
Both->New("a", 7) with New(first : T, second : T)Cannot infer the type arguments of 'Both': type parameter 'T' is both 'System.String' and 'System.IntRef'
Slot->New(Nil)Cannot infer the type arguments of 'Slot': no argument gives type parameter 'T' a class
Tagged->New(words) with New(value : T) and New(values : Vector<T>)Cannot infer the type arguments of 'Tagged': its constructors make type parameter 'T' both 'Collection.Vector<System.String>' and 'System.String'

Each message ends Write them: Class->New(..)<..>. No common parent class is looked for, and one constructor is not preferred over another. A constructor call passed as an argument (Take(Vector->New())) is not inferred from the parameter; write the type arguments or use a declared local.

Type-parameter bounds

A type parameter can require an interface bound (T : Bound); a concrete argument must implement it. Multiple bounds combine with &, and a bound may be generic (F-bounded, e.g. self-comparable):

# single bound
class SortedBox<T : Compare> { ... }

# compound bound: T must satisfy BOTH interfaces
class Entry<T : Compare & Stringify> { ... }

# F-bounded: T must be comparable to itself
class Sorter<T : Compare<T>> { ... }

Variance (out / in)

Declaration-site variance relaxes the default invariance. A covariant parameter (out T) lets Producer<Dog> be used where Producer<Animal> is expected; a contravariant parameter (in T) lets Consumer<Animal> be used where Consumer<Dog> is expected. Omitting the modifier keeps the safe, invariant default.

class Animal {}
class Dog from Animal { New() { Parent(); } }

class Producer<out T> { @v : T; New() {}  method : public : Get() ~ T { return @v; } }

class Test {
  function : Use(p : Producer<Animal>) ~ Nil {}
  function : Main(args : String[]) ~ Nil {
    pd := Producer->New()<Dog>;
    Use(pd);   # accepted: Producer<Dog> is a Producer<Animal>
  }
}

Generic Methods

A function or method can declare its own type parameters, inferred from the arguments at each call:

function : Max<T : Compare>(values : Vector<T>) ~ T { ... }
function : Swap<T>(a : T[], i : Int, j : Int) ~ Nil { ... }

best := Max(scores);   # scores is a Vector<IntRef>, so best is an IntRef
Swap(names, 0, 2);     # T is String

A type parameter takes an object (box primitives as IntRef, ...). Library methods take type parameters too: Vector, List and CompareList have Map<R>((H) ~ R), so a map can change the element type:

lengths := words->Map(\(String) ~ IntRef : (s) => IntRef->New(s->Size()));  # Vector<IntRef>
upper := words->Map(\(s) => s->ToUpper());                                   # R from the body

An inferred lambda for a type parameter must return an object. See METHOD_GENERICS_DESIGN.md.

Type Boxing

A generic class holds objects, so a number in a collection is held by its holder class: IntRef for an Int, FloatRef for a Float, BoolRef for a Bool, CharRef for a Char, ByteRef for a Byte. The compiler moves a value in and out of its holder for you:

list := Collection.List->New()<IntRef>;
list->AddBack(17);
list->AddFront(4);
(list->Back() + list->Front())->PrintLine();

@counts : Map<String, IntRef>;
@recent : Vector<IntRef>;
@weights : Vector<FloatRef>;

count := 1;
if(@counts->Has(word)) {
  count := @counts->Find(word) + 1;       # unboxed for the '+'
};
@counts->Insert(word, count);             # boxed: IntRef->New(count)
@recent->AddBack(count);
@weights->AddBack(weight);

total := 0.0;
each(i : @recent) {
  total += @recent->Get(i) * @weights->Get(i);   # an IntRef and a FloatRef: Int made Float
};
bins[@recent->Get(i)] += 1;               # an index
return @counts->Find(word);               # returned as an Int

Written out by hand, as it had to be where the compiler did not do it:

count := @counts->Find(word)->Get() + 1;
@counts->Insert(word, IntRef->New(count));
@recent->AddBack(IntRef->New(count));
@weights->AddBack(FloatRef->New(weight));
total += @recent->Get(i)->Get()->As(Float) * @weights->Get(i)->Get();
bins[@recent->Get(i)->Get()] += 1;
return @counts->Find(word)->Get();

Both versions are in programs/regression/boxing_before_after.obs, which runs them side by side and prints:

red 3, weighted 15.750000, seen once 3
PASS: boxing before and after

The rules:

  1. Boxing. A primitive where a holder is wanted is Holder->New(value). It is allowed exactly when the primitive could be assigned to the holder's own primitive: Byte, Char, Int and Float convert among themselves, and a Bool is only a Bool. So r : FloatRef := 3; holds 3.0, r : IntRef := 2.75; holds 2 (as i : Int := 2.75; does), and r : BoolRef := 1; is an error.
  2. Unboxing. A holder where a primitive is wanted is holder->Get(), followed by the same conversion: an IntRef for a Float is the Int made a Float, a FloatRef for an Int is truncated, and a BoolRef is never a number. It applies to an assignment, a return, an argument (of a method, a function or a function value), an operand of a calculation, an array index, a select and a condition (if(flags->Get(i))).
  3. The value unboxed is the one the expression ends in: for order->Lines()->Get(0) it is what Get(0) returned.
  4. Overloads. A parameter is matched best by an argument of its type, then by one that converts to it (Int for Float), then by one that is boxed or unboxed to it (Int and IntRef), then by one that is converted and boxed or unboxed (Int and FloatRef). The method that is called fits every argument at least as well as each other method does; the order the methods are declared in does not matter.
function : Show(v : IntRef) ~ Nil { ... }
function : Show(v : Float) ~ Nil { ... }

Show(3.5);              # Show(Float): its own type
Show(3);                # Show(Float): an Int converts before it is boxed
Show(IntRef->New(3));   # Show(IntRef)

When no method is the best the call is refused; write the conversion to choose:

function : Pick(a : IntRef, b : Int) ~ String { ... }
function : Pick(a : Int, b : IntRef) ~ String { ... }

Pick(1, 2);               # error: Ambiguous function/method call: 'Pick(..)' boxes or
                          #        unboxes an argument to fit, and more than one method
                          #        fits as well
Pick(IntRef->New(1), 2);  # the first
  1. A holder is still an object where an object is wanted. r : IntRef := list->Get(0); stores the holder itself, r = Nil compares it with Nil, and each(value in ints) gives the holders. A holder that is Nil has no value: unboxing it is the run-time error calling Get() on it is (counts->Find("missing") for a key that is not there).

## Functional Programming

Closures and Lambda Expressions

A lambda is written one of two ways, and which you need depends on whether it takes parameters.

No parameters — the shorthand \() => body. When the surrounding context expects a FuncRef<R> — an assignment target, a return, a method argument, or a collection element — the return type is inferred and the lambda auto-wraps into a FuncRef<R> (no explicit FuncRef->New(...)<R> or ~ R : annotation). Call a FuncRef directly with v() — no ->Get()/->Call() step — and chain on the result (v()->Get()).

With parameters — the annotated form \(types) ~ R : (names) => body, which targets a function type rather than a FuncRef<R>. FuncRef<R> wraps a () ~ R and has no parameter slots, so a lambda taking an argument cannot be a FuncRef. See Lambdas with parameters below.

# bare lambda; return type inferred from the FuncRef<IntRef> target, called directly
f : FuncRef<IntRef> := \() => IntRef->New(5);
f()->Get()->PrintLine();          # 5

# block body: an arbitrary statement list (inferred locals, loops) with a return
sum := \() => {
  acc := IntRef->New(0);
  for(k := 0; k < 5; k += 1;) { acc->Set(acc->Get() + k); };
  return acc;
};
sum()->Get()->PrintLine();        # 0+1+2+3+4 = 10

# auto-wraps when stored in a generic collection, then called directly
funcs := Vector->New()<FuncRef<IntRef>>;
each(i : 5) { funcs->AddBack(\() => IntRef->New(i * 7)); };
each(i : funcs) {
  f := funcs->Get(i);
  f()->Get()->PrintLine();
};

A bare lambda also auto-wraps when returned or passed as an argument:

function : Mk(n : Int) ~ FuncRef<IntRef> {
  x := IntRef->New(n);
  return \() => x;                # auto-wraps to FuncRef<IntRef>
}

The verbose form with an explicit annotation is still supported and equivalent: FuncRef->New(\() ~ IntRef : () => x)<IntRef>.

Method references without ceremony

Where a function value is wanted, a static function can be named by itself: Class->Function. The compiler reads the signature from the function and builds the FuncRef, Func2Ref, Func3Ref or Func4Ref the long form would have built; the compiled program is byte-for-byte the same.

# before
registry->Add(AgentTool->New("get_weather", "Get the weather", schema,
  Func2Ref->New(AgentTour->Weather(JsonElement) ~ String)<JsonElement, String>));
# after
registry->Add(AgentTool->New("get_weather", "Get the weather", schema, AgentTour->Weather));

It works as a declaration or assignment target, a return, a call argument and a collection element. Rules: the name must be a single, non-virtual static function (an overloaded name is an error that asks for the full form); the arguments and the return must be plain classes (a function over Int, an array or a generic class needs the full form, as the long form itself does); at most three arguments. An enum item or a constant named the same way keeps its meaning. Test: method_ref_sugar.

Lambdas with parameters

The shorthand is zero-parameter only. A lambda that takes arguments uses the annotated form — parameter types, the return type, then parameter names — and targets a function type:

f : (Int) ~ Int := \(Int) ~ Int : (x) => x + 1;
f(41)->PrintLine();                                  # 42

The two parenthesised groups are types and then names, in that order. Writing \(x : Int) => ... does not compile: the shorthand has no parameter list, and the error points at the parameter name rather than saying so.

A parameterised lambda captures exactly as a zero-parameter one does, so a function can return one and the captures travel with it — independently per lambda, with no shared state:

function : MakeAdder(n : Int) ~ (Int) ~ Int {
  return \(Int) ~ Int : (x) => x + n;
}

add3 := MakeAdder(3);
add100 := MakeAdder(100);
add3(10)->PrintLine();      # 13
add100(10)->PrintLine();    # 110
add3(10)->PrintLine();      # 13 — unaffected by the second

This is what makes currying, partial application and function composition expressible; see First-Class Functions below for composition.

What a lambda can capture

A lambda can use the locals and parameters of the method that creates it: values, strings, arrays, objects, function references and other FuncRefs. Inside the body you can call methods on a captured object (including virtual methods) and call a captured function or FuncRef directly.

c := Counter->New();
inc : FuncRef<IntRef> := \() => c->Inc();     # instance method on a captured object
r : FuncRef<IntRef> := \() => IntRef->New(3);
next : FuncRef<IntRef> := \() => IntRef->New(r()->Get() + 1);   # captured FuncRef called

Captures are by copy, taken when the lambda is created:

  • A later assignment to the captured local is not seen: with n := 1;, then a lambda that reads n, then n := 2;, the lambda still sees 1. A loop variable captured in each iteration keeps that iteration's value.
  • An object is copied as a reference, so the lambda and the enclosing method share it: c->Inc() inside the lambda is visible as c->Get() outside. Rebinding the local (c := Counter->New();) does not change which object the lambda uses.

Fields and @self (a lambda in an instance method). A lambda written in an instance method captures the instance it was created in, so its body may read and write the instance's fields and name the instance:

# before: copy the field into a local (a later write is not seen), call through a local
method : Incrementer() ~ FuncRef<IntRef> {
  me := @self;                       # was not allowed in a lambda
  ...
}
# after
method : Incrementer() ~ FuncRef<IntRef> {
  return \() => { @count += 1; return IntRef->New(@count); };
}
method : Caller() ~ FuncRef<IntRef> {
  return \() => @self->Bump();       # an instance method, through the instance
}

Unlike a captured local, a field is not copied: it is read and written through the captured instance, so a write in the lambda is a write to the field, the method sees it, and the lambda sees the method's later writes. The lambda keeps the instance alive. Limits: only a lambda directly in an instance method (not one inside another lambda, and not one in a function); an instance method of the class is called with @self->Name(..), never as a bare Name(..) (still rejected, with a message that says so); @field inside a "{$ ...}" interpolation in a lambda is still rejected. Test: lambda_self_fields.

First-Class Functions

A named function is passed as Name(types) ~ Return, and a function type is written the same way. Compose two by returning a parameterised lambda, which closes over them:

function : Compose(f : (Int) ~ Int, g : (Int) ~ Int) ~ (Int) ~ Int {
  return \(Int) ~ Int : (x) => f(g(x));
}

function : F(a : Int) ~ Int { return a + 14; }
function : G(a : Int) ~ Int { return a + 15; }

function : Main(args : String[]) ~ Nil {
  compose := Compose(F(Int) ~ Int, G(Int) ~ Int);
  compose(13)->PrintLine();                 # 42
}

Each call to Compose produces an independent function, so several may be live at once.

Do not route the captures through static fields. It is the obvious way to write this without a lambda, because a plain function reference has nowhere to put f and g — and it is wrong: ``ruby @f : static : (Int) ~ Int; @g : static : (Int) ~ Int; function : native : BadCompose(x : Int) ~ Int { return @f(@g(x)); } function : BadComposer(f : (Int) ~ Int, g : (Int) ~ Int) ~ (Int) ~ Int { @f := f; @g := g; return BadCompose(Int) ~ Int; } ` Every result refers to the same BadCompose`, which reads whichever pair was stored last. Build two and the first silently changes meaning — no error, no warning, just a wrong number. Use the lambda above.

## Integer Arithmetic
  • Width: Int is 64-bit two's-complement; Byte and Char widen to Int.
  • Overflow: + - * wrap and never trap.
  • Shifts: use n and 63. >> sign-fills, >>> zero-fills.
  • Division: / truncates toward zero; % takes the dividend's sign.
  • Traps: a zero divisor is the only integer trap; MIN / -1 = MIN and MIN % -1 = 0.
  • Byte narrowing: a Byte is unsigned, 0 to 255. A value that lands in a scalar Byte -- a local, field or parameter, a ~ Byte return, ->As(Byte) or Int->ToByte -- keeps its low 8 bits, as a Byte[] element store does: 255 + 1 is 0, 0 - 1 is 255, 300 is 44. The arithmetic runs at Int width and wraps only where its result lands in a Byte: with b at 255, b + 1 = 256 is true, but (b + 1)->PrintLine() prints 0, because PrintLine takes a Byte parameter.
  • Char is not narrowed: a scalar Char holds a whole Unicode code point on every platform, so 0x1F600->As(Char) keeps its value and String->Append writes the surrogate pair where strings are UTF-16 (Windows). Only a Char[] element store is limited to the platform's character width (16 bits on Windows, 32 elsewhere).
  • Printing a Byte: always its decimal value. ToString, Print/PrintLine, interpolation, concatenation and String->Append(Byte) all give "65" for 65; use b->As(Char) for the character.
  • Consistency: identical in the interpreter, both JITs and at every -opt level.
min := -9223372036854775807 - 1;
(9223372036854775807 + 1 = min)->PrintLine(); # true: wraps
(min / -1 = min)->PrintLine();                # true: no trap
(1 << 65)->PrintLine();                       # 2: the count is 65 and 63 = 1
(-8 >>> 64)->PrintLine();                     # -8: a count of 64 shifts by 0
(-7 / 2)->PrintLine();                        # -3
(-7 % 3)->PrintLine();                        # -1

b : Byte := 255;
b += 1;
b->PrintLine();                               # 0: a Byte wraps on store
Int->ToByte(300)->PrintLine();                # 44
(b - 1 = -1)->PrintLine();                    # true: the arithmetic is Int-wide
## Strings & Formatting

Interpolation

Embed a value in a string literal with {$...}. The braces may hold any expression — a bare variable, a field, an arithmetic / comparison / logical expression, an array access, or a method call:

name := "World";
i := 41;
"Hello, {$name}!"->PrintLine();             # Hello, World!
"next = {$i + 1}"->PrintLine();             # next = 42
"even? {$i % 2 = 0}"->PrintLine();          # even? false
"upper = {$name->ToUpper()}"->PrintLine();  # upper = WORLD

A String or object that is Nil interpolates as Nil, so a message can show a value that is missing: s : String; "s={$s}"->PrintLine(); prints s=Nil. Only interpolation does this; String->Append(Nil) and + with a Nil operand still raise a Nil error.

Any object can be interpolated or concatenated. It prints through the nearest ToString in its class chain, ending at System.Base->ToString. That method prints a Stringify instance's own ToString, and for any other object the class name and instance ID (Point@0x1f). So a mixed Base[] prints without a cast. Methods with a body are bound statically. To make an object print its own way through a Base reference, implement Stringify rather than only declaring a ToString:

class Point implements Stringify {
  @x : Int; @y : Int;
  New(x : Int, y : Int) { @x := x; @y := y; }
  method : public : ToString() ~ String { return "({$@x}, {$@y})"; }
}

items := Base->New[2];
items[0] := Point->New(1, 2);
items[1] := "text";
each(i : items) { items[i]->ToString()->PrintLine(); };  # (1, 2) / text

Format specifiers

Append :spec to an interpolated expression for precision, width, alignment, or radix (Python / .NET–style):

SpecExampleResult

0N — zero-pad"{$n:05}"00042
<N — left-justify"[{$s:<6}]"[hi ]
>N — right-justify"[{$s:>6}]"[ hi]

pi := 3.14159; n := 42; v := 255;
"pi  = {$pi:.2}"->PrintLine();   # pi  = 3.14
"id  = {$n:05}"->PrintLine();    # id  = 00042
"hex = {$v:x}"->PrintLine();     # hex = 0xff

String->Format

For a positional template — handy when the format string is reused or built at runtime — use String->Format. Placeholders {0}, {1}, … are replaced by the matching argument's ToString; {{ and }} produce literal braces:

String->Format("{0} = {1}", "x", "y")->PrintLine();      # x = y
String->Format("{1} before {0}", "a", "b")->PrintLine(); # b before a

String and object arguments are passed directly; primitive values are boxed with their holder type (IntRef, FloatRef, …):

use System;
String->Format("n = {0}", IntRef->New(42))->PrintLine(); # n = 42
For mixing primitive values, string interpolation ("{$x}" / "{$x:.2}") is usually more convenient than Format.

Building strings manually

String also provides Append, Pad / PadTo, Justify, and Truncate for incremental construction:

buffer := String->New();
buffer->Append("count=");
buffer->Append(7);
buffer->ToString()->PrintLine();           # count=7
"42"->PadTo(5, '0', true)->PrintLine();     # 00042

Structured Concurrency

A TaskScope (nursery) spawns closures as worker Threads. Wrapped in a leaving { scope->JoinAll(); } block it can never exit until every child has joined — the structured-concurrency invariant (no task outlives its scope), on any exit path (normal, early return, or unwind). Library: System.Concurrency (link -lib gen_collect,concurrent).

use System.Concurrency;

scope := TaskScope->New();
leaving { scope->JoinAll(); }              # joins all children on every exit path
a := scope->Spawn(FuncRef->New(\() ~ System.Base : () => { return Work(1); })<System.Base>);
b := scope->Spawn(FuncRef->New(\() ~ System.Base : () => { return Work(2); })<System.Base>);
# after the block: a->GetResult(), b->GetResult(); scope->Cancel() for boundary cancel

TaskScope: Spawn(FuncRef<System.Base>)~Task, JoinAll(), Cancel(), IsCancelled(), Size(). Task: GetResult()~System.Base, IsDone()~Bool, DidRun()~Bool. Each Task is a real Thread, so mutator register/unregister and the GC stop-the-world contract are handled for free. Cancellation is cooperative and boundary-only — a lambda body can call static functions but not instance methods, so it can't poll the scope; Task.Run checks cancellation before invoking the body.
