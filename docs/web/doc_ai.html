Objeck AI & ML Developer Guide

All documentationView docs/AI.md on GitHub

All AI and ML capabilities are standard library — no third-party packages, no pip install, no package.json. Import the relevant bundle and go.

Authentication

OpenAI

Create openai_api_key.dat in your working directory containing your API key. The static helper reads it:

use API.OpenAI;

token := EndPoint->GetApiKey();

Anthropic

Set the ANTHROPIC_API_KEY environment variable, or create anthropic_api_key.dat in your working directory, or call EndPoint->SetApiKey(key). Chat->New(model, Nil) reads the key with EndPoint->GetApiKey(); pass a key as the second argument to override it for one chat.

Gemini

Create gemini_api_key.dat in your working directory. Use the static helper:

use API.Google.Gemini;

token := EndPoint->GetApiKey();

Ollama

No authentication needed. Ollama runs locally at http://localhost:11434 by default. Start it with ollama serve.

# Single-turn
response := Response->Respond("gpt-4o-mini",

    token);

# Multi-turn conversation

messages->AddBack(Pair->New("system", "You are a helpful assistant.")<String, String>);
messages->AddBack(Pair->New("user", "What is Objeck?")<String, String>);
messages->AddBack(Pair->New("assistant", "Objeck is a JIT-compiled OO language.")<String, String>);
messages->AddBack(Pair->New("user", "What platforms does it support?")<String, String>);

response := Response->Respond("gpt-4o-mini", messages, Nil, token);   # Nil: no output schema
response->GetText()->PrintLine();

# With reasoning control
response := Response->Respond("o3-mini",
    Pair->New("user", "Prove Fermat's Last Theorem.")<String, String>,
    ReasoningEffort->HIGH,
    Verbosity->HIGH,
    Nil, token);
response->GetText()->PrintLine();

Output cap. The max_tokens argument of Response->Respond(...) limits the generated tokens (reasoning tokens included) and is sent as the Responses API field max_output_tokens; -1 sends no cap. Completion->Complete(...) (Chat Completions) sends it as max_completion_tokens, because max_tokens is deprecated there and reasoning models reject it. Response->BuildRespondRequest(...) and Completion->BuildCompleteRequest(...) return the request body as a JsonElement without any network call.

Tool calls. Completion->CompleteWithTools(model, messages, tools, max_tokens, token) is the Chat Completions call with a tools array: messages is a JsonElement array of message objects and tools the array of {"type":"function","function":{name, description, parameters}} definitions, such as McpToolBridge->ToOpenAiJson() (see MCP). If the reply asks for tools, Choice->GetToolCalls() lists them (GetId(), GetName(), GetArguments() as the JSON text the model wrote, GetArgumentsJson() parsed, Nil if it is not valid JSON). Append Choice->GetMessageJson() (the assistant message as received) and one Completion->ToolResultMessage(call->GetId(), text) per call, then call again until GetToolCalls() is empty. Completion->BuildToolRequest(...) returns the request body without a network call. The Responses API (Response->Respond) does not take a tools array yet.

use API.OpenAI, API.OpenAI.Chat, Data.JSON;

messages := JsonElement->New(JsonElement->JsonType->ARRAY);
user := JsonElement->New(JsonElement->JsonType->OBJECT);
user->Insert("role", "user");
user->Insert("content", "What is (2 + 3) * 4? Use the calculator.");
messages->Add(user);

tools := bridge->ToOpenAiJson();   # an McpToolBridge
completion := Completion->CompleteWithTools(Models->GPT_4O_MINI(), messages, tools, 512, token);
choice := completion->GetChoices()->Get(0);
while(choice->GetToolCalls()->Size() > 0) {
  messages->Add(choice->GetMessageJson());
  each(call in choice->GetToolCalls()) {
    text := bridge->Run(call->GetName(), call->GetArgumentsJson());
    messages->Add(Completion->ToolResultMessage(call->GetId(), text));
  };
  completion := Completion->CompleteWithTools(Models->GPT_4O_MINI(), messages, tools, 512, token);
  choice := completion->GetChoices()->Get(0);
};
choice->GetMessage()->GetSecond()->PrintLine();

This round trip is tested against a local server (openai_tool_calls_test); it was not run against the live API.

The loop above needs an McpToolBridge. This one is self-contained: it declares one function tool by hand, runs it in Objeck, and bounds the loop. Completion->BuildToolRequest(...) returns the request body without a network call, so Main prints it before any request; with an argument it runs the loop against the API (it reads the key with EndPoint->GetApiKey()).

Compile: obc -src tool_loop.obs -lib net,net_server,json,cipher,misc,openai

use API.OpenAI, API.OpenAI.Chat;
use Data.JSON;

class WeatherTools {
  # one function tool: {"type":"function","function":{name, description, parameters}}
  function : Tools() ~ JsonElement {
    parameters := JsonParser->TextToElement("{\"type\":\"object\",\"properties\":{\"city\":{\"type\":\"string\"}},\"required\":[\"city\"]}");
    spec := JsonElement->New(JsonElement->JsonType->OBJECT);
    spec->Insert("name", "get_weather");
    spec->Insert("description", "Get the current weather for a city");
    spec->Insert("parameters", parameters);
    tool := JsonElement->New(JsonElement->JsonType->OBJECT);
    tool->Insert("type", "function");
    tool->Insert("function", spec);
    tools := JsonElement->New(JsonElement->JsonType->ARRAY);
    tools->Add(tool);
    return tools;
  }

  function : Run(call : ToolCall) ~ String {
    arguments := call->GetArgumentsJson();     # Nil when the model wrote invalid JSON
    if(arguments = Nil | call->GetName()->Equals("get_weather") = false) {
      return "error: bad call";
    };
    city := arguments->Get("city")->GetString();
    return "18C and sunny in {$city}";
  }

  function : Ask(question : String, token : String) ~ String {
    messages := JsonElement->New(JsonElement->JsonType->ARRAY);
    user := JsonElement->New(JsonElement->JsonType->OBJECT);
    user->Insert("role", "user");
    user->Insert("content", question);
    messages->Add(user);

    tools := Tools();
    model := Models->GPT_4O_MINI();
    for(step := 0; step < 5; step += 1;) {           # bound the loop
      completion := Completion->CompleteWithTools(model, messages, tools, 512, token);
      if(completion = Nil) {
        return "error: {$Completion->GetLastError()}";
      };

      choice := completion->GetChoices()->Get(0);
      calls := choice->GetToolCalls();
      if(calls->Size() = 0) {
        return choice->GetMessage()->GetSecond();    # a plain answer: done
      };

      messages->Add(choice->GetMessageJson());       # the assistant message, as received
      each(call in calls) {
        messages->Add(Completion->ToolResultMessage(call->GetId(), Run(call)));
      };
    };
    return "error: the model kept asking for tools";
  }

  function : Main(args : String[]) ~ Nil {
    # no network: the request body the first call would send
    first := JsonElement->New(JsonElement->JsonType->ARRAY);
    user := JsonElement->New(JsonElement->JsonType->OBJECT);
    user->Insert("role", "user");
    user->Insert("content", "What is the weather in Paris?");
    first->Add(user);
    Completion->BuildToolRequest(Models->GPT_4O_MINI(), first, Tools(), 512)->ToString()->PrintLine();

    if(args->Size() > 0) {
      Ask("What is the weather in Paris?", EndPoint->GetApiKey())->PrintLine();
    };
  }
}

Batch Processing

Process up to 50,000 requests asynchronously at 50% of standard API cost. Responses are available within 24 hours.

use API.OpenAI;

# 1. Upload a .jsonl file of requests (or reuse the one already uploaded)
file := File->LoadOrCreate("requests.jsonl", "batch", token);

# 2. Create the batch job
job := Batch->Create(file->GetId(), "/v1/chat/completions", token);
"Batch ID: {$job->GetId()}"->PrintLine();
"Status: {$job->GetStatus()}"->PrintLine();   # "validating"

# 3. Poll for completion
job := Batch->Get(job->GetId(), token);
if(job->IsComplete()) {
    output_id := job->GetOutputFileId();
    "Output file: {$output_id}"->PrintLine();
};

# 4. List recent jobs
jobs := Batch->List(token);
each(j in jobs) {
    id := j->GetId();
    status := j->GetStatus();
    "{$id}: {$status}"->PrintLine();
};

Request format (requests.jsonl — one JSON object per line):

{"custom_id":"r1","method":"POST","url":"/v1/chat/completions","body":{"model":"gpt-4o-mini","messages":[{"role":"user","content":"Hello"}]}}

Anthropic (Claude)

API.Anthropic is a client for the Anthropic Messages API: chat with a system prompt, tool use, streaming over server-sent events, structured output, and extended-thinking blocks. Compile with -lib anthropic. A failed call returns Nil, and EndPoint->GetLastError() says why, as in the other clients. Requests go over HTTPS; EndPoint->SetBaseUrl points the client at a gateway and EndPoint->SetCertificate pins its certificate.

Chat and system prompts

A Chat keeps the message history. SetSystem, SetMaxTokens (default 4096) and SetTemperature return the chat, so they chain.

use API.Anthropic;

chat := Chat->New("claude-sonnet-5-5", Nil);
chat->SetSystem("Answer in one sentence.");
chat->Send("Why is the sky blue?")->PrintLine();
chat->Send("And at sunset?")->PrintLine();

SendReply(message, tools) returns the whole Reply: GetText(), GetThinking(), GetStopReason(), GetInputTokens(), GetOutputTokens(), and the tool calls. Pass Nil as the message to send the history as it stands.

SetThinking(budget_tokens) turns on extended thinking. The API needs a budget of at least 1024 tokens and a SetMaxTokens above it. While thinking is on the temperature is not sent, and SendJson leaves thinking off for its one request, because the API rejects a forced tool with thinking.

What joins the history, so a chat never wedges: a reply that fails is dropped together with the message that asked for it; a refusal (stop_reason refusal) and an empty reply are returned to you but not kept, as the API advises; an empty text block is removed from a turn before it is replayed; thinking blocks, including redacted ones, are replayed whole.

Tool use

Describe each tool with a name, a description and a JSON schema. When a reply has tool uses, run them, return each result with AddToolResult(use_id, text) and send again. Results for one reply share one user message, as the API requires. Mark a failed tool with AddToolResult(id, text, true).

use API.Anthropic;
use Collection;
use Data.JSON;

schema := JsonParser->TextToElement("{\"type\":\"object\",\"properties\":{\"city\":{\"type\":\"string\"}},\"required\":[\"city\"]}");
tools := Vector->New()<Tool>;
tools->AddBack(Tool->New("get_weather", "Get the weather for a city", schema));

chat := Chat->New("claude-sonnet-5-5", Nil);
reply := chat->SendReply("What is the weather in Paris?", tools);
while(reply <> Nil & reply->HasToolUses()) {
  uses := reply->GetToolUses();
  each(i : uses) {
    call := uses->Get(i);
    city := call->GetArgument("city");
    chat->AddToolResult(call->GetId(), "18C and sunny in {$city}");
  };
  reply := chat->SendReply(Nil, tools);
};
reply->GetText()->PrintLine();

Tool->New(func) also takes the FunctionType the other clients use.

Structured JSON output

SendJson(question, name, schema) makes the model call a tool whose input schema is the one you give, and returns that input as JSON. It is one-shot: neither the question nor the answer joins the history.

schema := JsonParser->TextToElement("{\"type\":\"object\",\"properties\":{\"city\":{\"type\":\"string\"},\"temp\":{\"type\":\"integer\"}},\"required\":[\"city\",\"temp\"]}");
answer := chat->SendJson("Name a city where it is 18 degrees.", "answer", schema);
answer->Get("city")->GetString()->PrintLine();

Streaming

Stream(message, tools) returns a ReplyStream. Read it piece by piece; the exchange joins the history when the stream ends, whether or not you ask for the whole reply, and GetReply() can be called more than once. Close() before the end, an error event and a tool input that was cut off by max_tokens all drop the exchange from the history.

stream := chat->Stream("Write a haiku about rivers.", Nil);
while(stream <> Nil & stream->HasNext()) {
  stream->Next()->Print();
};
reply := stream->GetReply();

Streaming works over HTTPS only. A refused request (a bad key, a rate limit) returns Nil with the status and what it usually means in GetLastError(); the body of a refused stream is not read, so the API's own message is not shown there.

Tested against a local mock, not the live service. anthropic_parse_test replays recorded response bodies and event streams, and anthropic_http_test runs the client against a local HTTPS server that speaks the same message shapes, checking the x-api-key and anthropic-version headers, errors, a tool round trip, structured output and streaming. Neither calls api.anthropic.com. If a field or event the live API sends is not handled, the parse test is where to add a recorded case.

ONNX Local Inference

Run ML models locally using the ONNX Runtime. The execution provider is a per-session choice (ep: cpu, cuda, dml, qnn, vitisai, coreml) among those the loaded ONNX Runtime carries. Without ep a session uses the build's default: DirectML on Windows x64, QNN on Windows ARM64, CoreML on macOS, and the CPU on Linux x64 and ARM64 (each linked with a vendored ONNX Runtime 1.19.0 CPU-only build). No release ships CUDA; with an ONNX Runtime you supply that carries it, ep=cuda runs on an NVIDIA GPU. See execution providers for the setting and core/lib/onnx/README.md for how to set CUDA up.

A provider the runtime does not carry is refused with an error that lists the ones it does, and the session does not open; it is never quietly run on the CPU. Ask first:

use API.Onnx, Collection;

each(provider in OnnxRuntime->GetProviders()) {       # what the runtime reports, e.g. CUDAExecutionProvider
  provider->PrintLine();
};
OnnxRuntime->GetDefaultProvider()->PrintLine();       # "dml", "qnn", "coreml" or "cpu": what a session gets without ep

config := Map->New()<String, String>;
if(OnnxRuntime->HasProvider("cuda")) {
  config->Insert("ep", "cuda");                       # other keys, such as "device_id", are provider options
};
session := YoloSession->New("yolo11n.onnx", config);
if(<>session->IsOpen()) {
  "session did not open, the reason was printed above"->PrintLine();
};

Any Model (generic run)

YoloSession, ResNetSession, DeepLabSession, OpenPoseSession, Phi3Session, Phi3VisionSession and FaceSession each handle one model family. For anything they do not cover -- a model with several inputs, a text or audio model, or a model whose output you want to decode yourself -- Session runs any ONNX graph. Ask it what the model wants, build the tensors, run it:

use API.Onnx, API.Models, Collection;

session := Session->New("model.onnx");
if(<>session->IsOpen()) {
  return;
};

# what does this model take and return?

  spec->ToString()->PrintLine();      # e.g.  data: FP32[-1,3,224,224]

A dimension the model leaves to you is reported as -1 -- a batch size or a sequence length. You choose it; nothing guesses.

You never state an element type. The model's own declaration decides what each input becomes, so FP32, FP16, INT64, UINT8 and BOOL models are all driven the same way.

An integer tensor keeps its integers. The conversion to Float happens only at the native crossing, which is the one place that needs it, and refuses a value past 2^53 rather than rounding it -- 9,007,199,254,740,992, so every token id and class index is far inside it. A server takes integers as JSON integers and has no such limit, which is why the conversion lives at the boundary that cares rather than in the tensor.

Preprocessing and decoding are yours, in Objeck. That is the trade: more work than YoloSession, and it works for models no per-family class exists for. programs/frameworks/opencv_onnx/ab_phi3.obs drives Phi-3 through it with 67 inputs, which is what the shape is for.

GPU inference: IO binding, half precision, shared sessions

A Session chooses its execution provider with the ep config key (cpu, cuda, tensorrt, dml, qnn, vitisai, coreml). The ONNX Runtime beside libobjk_onnx must carry the provider (Choosing the provider); a session asks the runtime and refuses an absent one, so nothing is silently moved to the CPU. CUDA 12, cuDNN 9 and the NVIDIA driver are yours to supply; no Objeck release ships them. OnnxRuntime->HasProvider("cuda") asks what is available. A session option, or a provider option ONNX Runtime does not know, is refused with a reason rather than ignored.

config := Map->New()<String, String>;
config->Insert("ep", "cuda");
config->Insert("device_id", "0");                       # provider options go straight through
config->Insert("cudnn_conv_algo_search", "HEURISTIC");
session := Session->New("resnet34.onnx", config);

IO binding: tensors that stay on the device. A plain Session->Run converts and copies every input to the device and every output back on every call. A DeviceTensor is a tensor in the provider's memory, allocated once, filled with Upload and read with Download only when the program wants the numbers; a BoundSession points the model's inputs and outputs, by name, at device tensors, and Run() reads and writes them in place:

use API.Onnx, Collection;

class Bound {
  function : Main(args : String[]) ~ Nil {
    config := Map->New()<String, String>;
    config->Insert("ep", "cuda");
    session := Session->New("resnet34.onnx", config);
    if(<>session->IsOpen()) {
      "no session, the reason was printed above"->PrintLine();
      return;
    };

    # the model's input is FP32[-1,3,224,224]: the batch is yours to choose
    input := DeviceTensor->ForInput(session, "data", [8, 3, 224, 224]);
    scores := DeviceTensor->ForOutput(session, "resnetv23_dense0_fwd", [8, 1000]);

    bound := BoundSession->New(session);
    bound->BindInput("data", input);
    bound->BindOutput("resnetv23_dense0_fwd", scores);

    frame := Float->New[8 * 3 * 224 * 224];
    host := Float->New[8 * 1000];
    for(i := 0; i < 10; i += 1;) {
      input->Upload(frame);             # skip this when the input is already resident
      bound->Run();
      scores->Download(host);           # skip this when the output stays on the device
    };

    bound->Close();
    input->Close();
    scores->Close();
    session->Close();
  }
}

The program needs a ResNet-34 model and a CUDA runtime, so it was compiled here but not run. ForInput and ForOutput take the element type from the model (DeviceTensor->New(session, "FP16", shape) names it); an output whose shape you do not know is bound with BindOutputToDevice(name) and fetched with GetOutput(name). On ep=cpu a device tensor is ordinary host memory, so the same program runs without a GPU.

What the tests assert: a bound Run gives exactly the answer Session->Run gives on the same provider and input (onnx_iobinding on the CPU provider everywhere, onnx_iobinding_gpu where a GPU session opens; without one it prints SKIP:). Against the CPU, a GPU result is within float tolerance, not bit-identical: the CUDA provider convolves in TF32 on recent cards, and the provider option use_tf32=0 turns that off.

Device memory is the provider's, not the garbage collector's: Close() every DeviceTensor and BoundSession. A session closed while tensors still use it is released after the last of them.

Half precision, bfloat16 and 8-bit models. You never have to say what type a model wants: Session->Run reads the model's declaration and converts, rounding an FP16 or BF16 input from the Float you gave (to nearest, ties to even, overflow to infinity) and widening outputs back to Float. Integer inputs truncate toward zero and saturate at the type's range, so a 300 sent to an INT8 input is 127. For the bit patterns themselves there are Half, BFloat16 and Quantization:

use API.Onnx;

class Bits {
  function : Main(args : String[]) ~ Nil {
    Half->ToBits(1.0)->PrintLine();                  # 15360 (0x3C00)
    Half->Round(0.1)->PrintLine();                   # 0.0999756, the nearest binary16
    Half->FromBits(31743)->PrintLine();              # 65504, the largest finite half
    BFloat16->ToBits(3.0)->PrintLine();              # 16448 (0x4040)
    packed := Half->Pack([1.0, 0.5]);                # Float[] -> Int[] of 16-bit patterns
    Half->Unpack(packed)->Size()->PrintLine();       # 2
    # a model with an INT8 input: scale and zero point are the ones it was quantized with
    q := Quantization->ToInt8([300.0, -3.0], 0.0078125, 0);   # Float[] of whole numbers, saturated
    q->Size()->PrintLine();                          # 2
  }
}

DeviceTensor->UploadBits(Int[]) and DownloadBits(Int[]) move raw element patterns, so a half-precision model can be fed without a per-element conversion. Quantization also has ToUInt8 and Dequantize. onnx_float16 needs no GPU or model file: it checks known patterns, the round trip of all 65,536 half and bfloat16 patterns, every rounding midpoint between neighbouring finite values, and a tiny generated model with FP16, BF16, INT8 and UINT8 inputs and outputs. An FP16 or INT8 model is made offline from an FP32 one with Python (programs/tests/onnx_gpu/make_models.py); INT8 needs calibration on representative data before its accuracy means anything.

One session, many threads. Session->Run from several Objeck threads on the same Session is supported on every provider. Session->Run, BoundSession->Run and the device copies hand the calling thread to the collector for the length of the native work, so a long inference does not hold up garbage collection for other threads. Give each thread its own BoundSession and DeviceTensors over the shared Session: a BoundSession belongs to one thread at a time. onnx_concurrency (CPU provider) and onnx_concurrency_gpu (SKIP: without a GPU) run four threads on one shared session beside a thread that allocates garbage without pause, and check every answer against the single-threaded one. The per-family sessions (YoloSession, ResNetSession, Phi3Session, ...) are not changed by this and still run their inference without handing over the thread.

CUDA graphs. enable_cuda_graph=1 (for ep=cuda; cuda_graph=1 for ep=tensorrt) records the kernels of a run and replays them with one launch. It needs fixed shapes, every node on the GPU and tensors that stay at the same addresses, which is what a bound DeviceTensor is: refill it with Upload, never replace it. A session that asks for a graph runs the CUDA provider sequentially.

use API.Inference, API.Models, Collection;

client := Client->New("http://gpu-box:8000");

A failed call returns Nil and the reason is in EndPoint->GetLastError(). Servers report errors in a JSON body rather than only in the status line, so a body that will not parse means something else answered -- a proxy's error page, a truncated response -- and the body itself is reported.

Ask the server what a model expects before guessing at names and shapes:

if(client->IsReady("iris")) {
  client->Metadata("iris")->ToString()->PrintLine();
};

And when a request is rejected, print the body rather than reading the error:

client->DescribeRequest(inputs)->PrintLine();

The two protocols shape the same tensors very differently and a tensor nested to the wrong depth looks identical in Objeck, so seeing what was sent is usually faster than interpreting what came back.

One interface over both

Tensor, EndPoint and the Engine interface live in API.Models, which both backends link. So calling code can name a backend once and not again:

use API.Models, API.Onnx, API.Inference, Collection;

if(use_gpu_box) {
  engine := HttpEngine->New("http://gpu-box:8000", "iris");
}

IsOpen differs in kind between them and the difference is worth knowing: OnnxEngine reports whether a file loaded, once; HttpEngine asks the server and the answer can change between calls, so it is not cached.

What the interface deliberately leaves out is anything only one backend has -- GetModelInfo on ONNX, Metadata and DescribeRequest on HTTP. Reach them through GetSession() or GetClient(); an interface that carried the union of two backends would describe neither.

Agents (API.Agent)

API.Agent is a provider-neutral tool-use loop. You give a chat model Objeck functions as tools; the library sends the conversation, runs the tool calls the model asks for, sends the results back, and repeats until the model answers in plain text. The same program runs against Anthropic, OpenAI, Gemini or a local Ollama by changing one line, and against a scripted fake model with no key and no network. Compile with -lib agent,net,json,cipher,misc.

The library talks to the providers itself, so it does not need the anthropic, openai, gemini or ollama libraries. Its classes have distinctive names (AgentTool, AgentReply, ...) because the compiler resolves another library's Vector<Tool> by its short name.

A tool is a name, a description the model reads, a JSON Schema for its arguments and a handler: a function (JsonElement) ~ String wrapped in a Func2Ref, or an object that implements AgentToolHandler. ScriptedBackend replays a list of replies, so a tool can be tried without a model:

use API.Agent;
use Collection;
use Data.JSON;

class Weather {
  function : Get(arguments : JsonElement) ~ String {
    city := arguments->Get("city")->GetString();
    return "18C and sunny in {$city}";
  }

  function : Main(args : String[]) ~ Nil {
    schema := JsonParser->TextToElement("{\"type\":\"object\",\"properties\":{\"city\":{\"type\":\"string\"}},\"required\":[\"city\"]}");
    registry := ToolRegistry->New();
    registry->Add(AgentTool->New("get_weather", "Get the weather for a city", schema, Func2Ref->New(Weather->Get(JsonElement) ~ String)<JsonElement, String>));

    # a scripted model: it asks for the tool, then answers
    script := Vector->New()<AgentReply>;
    script->AddBack(AgentReply->Ask("call_1", "get_weather", "{\"city\":\"Paris\"}"));
    script->AddBack(AgentReply->Say("It is 18C and sunny in Paris."));

    agent := Agent->New(ScriptedBackend->New(script), registry);
    result := agent->Run("What is the weather in Paris?");
    result->GetText()->PrintLine();
    result->ToString()->PrintLine();
  }
}

What the loop does with a call. Whatever fails becomes an error result the model can read, and the loop carries on. A call is answered unknown (no such tool), denied (the registry's Allow or Deny list excludes it), invalid (the arguments broke the tool's schema; the handler did not run), refused (a dangerous tool, or SetApproveAll(true), and the AgentApprover said no or there is none), error (the handler raised, returned Nil or faulted), timeout, skipped (the step limit was reached) or ok. Run returns an AgentResult with GetText(), GetStatus() (completed, max_steps or error), GetSteps(), ToString() and ToJson(); the conversation is kept, so a second Run carries on and Reset() forgets it.

Safety.

  • Offer the least: ToolRegistry->Allow(name) restricts the model to the listed tools, and Deny(name) always wins.
  • AgentTool->SetDangerous(true) sends every call through the AgentApprover; with no approver the call is refused.
  • Arguments are checked against the tool's schema before the handler runs. Write schemas with required, enum, bounds and "additionalProperties": false; a path or command line still needs checking inside the handler.
  • Model output and tool output are untrusted. Do not give one agent both a tool that reads untrusted content and a tool that can send or delete without approval.
  • API keys are masked in error messages and in AgentResult->ToString() and ToJson() (Redactor->Scrub(text) does the same for anything else you log).
  • AgentTools has three ready-made, non-dangerous tools: Calculator(), CurrentTime() and ReadFile(directory). The file reader is lexical: it refuses .. and absolute paths but does not detect a symbolic link that points outside the directory.

Limits.

  • SetMaxSteps(n) (default 10) bounds the model calls in one Run; a model still asking for tools on the last step gets skipped answers and the result is max_steps.
  • Timeouts are not interruptions: SetToolTimeout(ms) reports a slow handler as timeout and discards its result, but a handler that never returns still hangs the run unless the tool runs in BOUNDED_THREAD mode (see run control below).
  • Tool calls run one after another, even when the model asks for several at once.
  • The schema checker covers type, properties, required, additionalProperties, enum, const, the numeric, string and array bounds, items, anyOf and oneOf; pattern, format and $ref are not checked.
  • No token streaming: an AgentObserver sees each step as it happens, and the model's text arrives whole.
  • Tested without the live services. agent_loop_test, agent_backend_test and agent_http_test use a scripted model, recorded provider response bodies and a local HTTPS server; nothing in the tests calls api.anthropic.com, api.openai.com, Google or a real Ollama.

Declaring an agent. agent Name(parameters) { backend : ...; instructions : ...; tools : ...; mcp : ...; allow : ...; deny : ...; budget { steps : 8; tokens : 5000; } trace : ...; } stands where a class does and states the model, the instructions, the tools and the limits in one place. It declares a class with one function: Name->Build(arguments) makes a new Agent each time, with the settings evaluated in the order written. An entry of tools is a class (every @tool function of it, with the derived schema) or an AgentTool value; mcp takes initialized McpClients; budget sets an AgentBudget; only backend is required. Each value is an ordinary expression that may use the parameters and is checked by the compiler where it is written; an unknown setting or limit, a setting twice, no backend and a class with no @tool function are compile errors with the line and column. agent is a keyword only at the start of a declaration. Section "Declaring an agent" of ai_sections/agent.md has a program with its output; programs/deploy/agent_decl_48.obs is a runnable example.

Run control (cancel, budgets, isolated tools, trace). By default a run cannot be stopped from outside, a tool's time limit is reported only after the handler returns, and nothing bounds a run in time, tokens or money. Four opt-in pieces add that; an agent that sets none of them behaves as before. The full reference is the "Agent run control" section of docs/ai_sections/agent_control.md.

  • Cancel. AgentCancel is a thread-safe token; any thread calls Cancel("reason"). The loop checks it before every step and between tool calls; a cancelled run ends with the stop reason cancelled, the calls that did not run are answered skipped, and the same agent can run again with a fresh token. A cancel that arrives while an approver is deciding stops the call before its handler starts. AgentCancel->New(parent) links a token to a parent, so one cancel stops a group. A handler that implements AgentCancelableHandler (Run(arguments, cancel)) is handed the token, which also becomes cancelled when the run's deadline passes, so it can poll IsCancelled() and stop early.
  • Budgets. AgentBudget limits one Run; every limit is off (0) until set and the first one reached ends the run: SetMaxSteps (budget_steps), SetMaxModelCalls (budget_model_calls, retries count), SetMaxToolCalls (budget_tool_calls; the call over the limit is skipped), SetMaxTokens (budget_tokens), SetMaxCost with SetPrice(in, out) or SetPrices(table, model) (budget_cost; prices are currency per million tokens) and SetMaxWallMs (deadline, enforced everywhere the loop waits). Tokens and cost count only what the backend reports; a backend that reports none never trips them. A reply that crosses a token or cost limit and asks for tools ends the run before those tools run; a final answer is kept as completed.
  • Stop reasons. result->GetStopReason() is one of completed, cancelled, deadline, budget_steps, budget_model_calls, budget_tool_calls, budget_tokens, budget_cost or error (the backend failed after its retries, or the reply was cut off or filtered). GetStatus() returns the same word, so IsCompleted() is true only for completed. GetModelCalls(), GetElapsedMs(), GetTotalTokens() and GetCost() say what the run used.
  • Tool modes. IN_THREAD (the default) runs the handler on the loop's thread, so a limit or a cancel is seen only after it returns. BOUNDED_THREAD runs it on a worker and the loop stops waiting at the tool's limit (SetTimeout, else SetToolTimeout), the deadline or the cancel. Set the default with agent->SetToolMode(mode) and one tool's with tool->SetMode(mode). An abandoned worker is a leak: a thread cannot be killed, so a handler that never returns keeps its thread until the process exits; a worker that returns is joined and leaves nothing behind. What the mode guarantees is that the run does not wait for it and that its late result never reaches the transcript. There is no separate process-isolated mode: IN_THREAD and BOUNDED_THREAD are the only two, and a fault that kills a thread outside any try still ends the whole process.
  • A blocked model call. A cancel is seen between model calls. To cut a call that is blocked inside the backend, agent->SetBoundedModelCalls(true) runs it on a worker and abandons it at the budget's per-call limit (SetModelCallMs), the deadline or a cancel. A backend that implements AgentDeadlineAware is told its time limit before each call and returns by itself; ScriptedBackend does (SetDelayMs makes a call slow), the four provider backends do not yet. With neither, a final answer that arrives after the cancel or the deadline is kept (completed), as it is for the token and cost limits; a late reply that asks for tools is not acted on.
  • Trace. agent->SetTrace(sink) delivers one AgentEvent per step to an AgentTraceSink (an AgentObserver may implement it too). The events, in order: run_start, budget_check (only with a budget), model_start, model_end, model_retry, tool_start, tool_end, halt (a cancel, deadline or budget was noticed) and run_end; each has seq (from 1), ms and step. AgentTraceBuffer keeps them in memory (GetEvents(), Kinds(), Count(kind), First(kind)), and AgentEvent->ToString() is one JSON object, so a custom sink can write its own file. Every event goes through the library's key redaction before delivery, like the transcript: registered keys and key-shaped tokens become [REDACTED], and a tool's arguments are cut at 500 characters.

A scripted model shows all three controls with no key and no network. Compile with -lib agent,net,json,cipher,misc:

use API.Agent;
use Collection;
use Data.JSON;

Model Context Protocol (API.MCP)

API.MCP is a pure-Objeck implementation of the Model Context Protocol. A server offers tools, resources and prompts that an MCP client (Claude Desktop, Claude Code, or this library's own client) can discover with the tools/list, resources/list and prompts/list requests and then call; a client does the same against another program; and a bridge hands a connected server's tools to the Anthropic, OpenAI and Gemini clients. Compile with -lib mcp plus the libraries it links:

obc -src server.obs -lib gen_collect,json,net,net_server,cipher,misc,mcp -dest server.obe

The protocol revision is 2025-11-25 (a client asking for 2025-06-18, 2025-03-26 or 2024-11-05 is answered with that revision). The newer stateless 2026-07-28 revision is not implemented.

A server over stdio

A tool is a name, a description, the JSON Schema of its input and a function that takes a McpCall and returns a McpToolResult. ServeStdio() reads one message per line from standard input and writes one reply per line to standard output until the input ends:

use API.MCP;

class Greeter {
  function : Main(args : String[]) ~ Nil {
    server := McpService->New("greeter", "1.0.0");
    server->AddTool("greet", "Greet a person by name",
      "{\"type\":\"object\",\"properties\":{\"name\":{\"type\":\"string\"}},\"required\":[\"name\"]}",
      Func2Ref->New(Greeter->Greet(McpCall) ~ McpToolResult)<McpCall, McpToolResult>);
    server->ServeStdio();
  }

  function : Greet(call : McpCall) ~ McpToolResult {
    name := call->GetString("name");
    return McpToolResult->Text("Hello, {$name}!");
  }
}

Resources and prompts are added the same way (AddResource, AddPrompt); a resource URI containing { is a template. A handler can poll call->IsCancelled() and send call->ReportProgress(progress, total, message).

A tool that fails is not a protocol error: a handler that returns McpToolResult->Error("..."), raises, returns Nil or gets arguments that miss the schema's required names or types produces a normal reply with isError true, so the model can read it and retry. Protocol errors (-32700 parse, -32600 invalid request, -32601 unknown method, -32602 bad parameters, -32002 resource not found) are for malformed requests.

A client

McpClient initializes a connection, lists and calls tools, reads resources and gets prompts. A refused request returns Nil (or false) and GetError() and GetErrorCode() say why; a tool that ran and failed is a result whose IsError() is true:

use API.MCP, Collection, Data.JSON;

class Tour {
  function : Main(args : String[]) ~ Nil {

      "{\"type\":\"object\",\"properties\":{\"a\":{\"type\":\"integer\"},\"b\":{\"type\":\"integer\"}},\"required\":[\"a\",\"b\"]}",

A client reaches a server through a transport: McpClient->Http(url) (streamable HTTP), McpClient->InProcess(service), McpClient->Command(command) (a server program started by the shell once per request, so only for servers whose tools do not depend on earlier requests; the runtime has no process with pipes) or McpClient->New(transport) for your own McpTransport.

Serving over HTTP

server->ServeHttp(8080) listens on 127.0.0.1 (port 0 takes a free port, GetBoundPort() says which; ServeHttp("", 8080) listens on every interface). The server issues an Mcp-Session-Id, refuses a browser Origin that is not loopback unless you add it with AllowOrigin, and answers every POST with JSON. Limits: there is no authorization, so keep the loopback address unless something in front of it authenticates; replies are never an event stream, so progress notifications are dropped (cancellation works); sessions live in memory and never expire; only one HTTP server runs in a process.

Limits

  • The JSON parser is lenient: a malformed message inside well-placed braces can be accepted.
  • Tool input is validated for required names and each property's type only; enum, minimum, patterns, nested objects and $ref are not checked.
  • Each tools/call takes a thread of its own, with no cap.
  • Standard input is read a byte at a time, which makes a line of any length work and is slow for very large messages.
  • A stdio server ends when its input does; there is no shutdown.

A function is a tool. A line that starts with @tool in a function's doc comment makes it an MCP tool: the compiler derives the name, the description, the JSON Schema (from the parameter types, defaults and @param lines), the @readonly/@destructive hints and the code that reads the typed arguments, and writes Class->McpTools(server) (see MCP for the rules and the limits). @resource <uri> (a fixed URI or a template such as weather://{city}, read into the function's parameters) and @prompt make resources and prompts the same way, and McpTools registers all three. Declaring tools from types, typed clients, agents. RAG answers from your documents instead of from what a model was trained on: split the documents into chunks, embed them, keep the vectors in an index, and for each question retrieve the closest chunks, put them in the prompt as numbered sources, and ask the model to cite them. The kit is glue over parts that already exist: VectorIndex (see Local vector search), the embedders and the chat clients.

  • Citations are asked for, not enforced: a model may cite nothing, cite wrongly, or answer from what it knows, and the kit does not check that a claim is supported by its source.

Actors and supervision (System.Actor)

System.Actor is the substrate for multi-agent programs: a running agent, a tool server or a worker is an actor, a thread with a private mailbox and a user object that handles one message at a time. Actors share no state; they send each other messages. When one fails, its supervisor restarts it by a stated policy, and when restarts come too fast the supervisor itself fails and its own supervisor decides what happens next. This is the Erlang/OTP model on the stock Thread, ThreadMutex and Condition, in Objeck with no VM change. Compile with -lib gen_collect,concurrent,actor. Agents as actors are a separate library, actor_agents, so actor links nothing heavy.

The limit to know first. An uncaught VM fault on any thread ends the whole process, so supervision recovers only from failures that surface as errors the actor can catch. The receive loop wraps Init, every Handle and Terminate in a try, and these become the exit reason FAILED instead of killing the program: a raised Error, divide by zero, index out of bounds, a Nil dereference, a bad cast, a failed Runtime->Assert, and unbounded recursion (the --call-depth limit). It cannot catch memory exhaustion, a crash in a native library or the VM, Runtime->Exit or a signal; those end every actor with the process. Actors isolate state and errors, not VM faults.

use System.Actor;

class Counter implements ActorBehavior {
  @n : Int;

  New() {
  }

The behavior object's fields are the actor's state; only the actor's thread touches them, so they need no lock. A behavior that also implements ActorLifecycle gets Init (before the first message; raising fails the actor) and Terminate. A Mail has a kind: DATA, CALL, DOWN (a watched actor ended) or EXIT (a linked actor ended, delivered to an actor that traps exits).

Supervisor policies. Strategy: ONE_FOR_ONE (only that child restarts), ONE_FOR_ALL (the others stop, last started first, then all restart in order), REST_FOR_ONE (the children started after it, then it). Restart: PERMANENT (always), TRANSIENT (after FAILED or KILLED, not after a normal end), TEMPORARY (never). Supervisor->New(name, strategy, max_restarts, period_seconds): more than max_restarts in the period fails the supervisor (the escalation: put it under a parent supervisor with inner->AsFactory()). Agents as actors. actor_agents (-lib gen_collect,concurrent,actor,actor_agents,agent,net,json,cipher,misc) runs an API.Agent agent as an actor: AgentActorFactory->New(builder, fail_on_error) is the child factory and an AgentBuilder makes a fresh Agent for each start, so a restart begins a new conversation. A prompt is a String payload; a Call returns the AgentResult. With fail_on_error a run that does not complete is delivered and then fails the actor, so the supervisor restarts that agent and the others are untouched. An agent run is one blocking call: Stop waits for it and Kill cannot end it, so give agents a shutdown timeout that fits a model call and set a step limit and a tool timeout on the Agent. The library is blocked in the hosted playground (it links the model clients); actor is not.

What is not guaranteed.

  • A blocked or looping handler cannot be interrupted. Stop and Kill are requests; a supervisor abandons such a child after the shutdown timeout and the thread leaks until the handler returns. There is no preemption, no per-handler time limit and no hang detection.
  • Delivery is in-process, at most once and unacknowledged. A message to an actor that fails before handling it is lost (GetDiscardedCount()), REJECT loses mail by design, nothing is retried, and there is no ordering between different senders.
  • A restart loses state, and mail queued for the failed incarnation is discarded.
  • Two actors that Call each other (or one that calls itself) wait until the timeout.
  • Every actor is an operating-system thread with a stack; thousands of actors are thousands of threads.
  • Left out on purpose: a DROP_OLDEST policy, selective receive, a name registry, an ActorSystem convenience and a TaskScope tie.

Inference telemetry (System.Telemetry)

System.Telemetry is the measurement base for resource-aware inference: it times a call, keeps latency statistics per (model, device, batch, tag) in bounded memory, samples the resources around the call, estimates energy from sampled power, saves the result as a profile and answers Predict from it. It is pure Objeck, in its own library with no dependency on onnx: wrap your own session calls with it. Compile with -lib telemetry,gen_collect,json or -lib @telemetry. Every latency is in milliseconds, a Float.

use System.Telemetry;

class Work {
  function : Spin() ~ Nil {
    sum := 0.0;
    for(i := 0; i < 20000; i += 1;) {
      sum += (i * 1.5)->Sqrt();
    };
  }

  function : Main(args : String[]) ~ Nil {
    for(i := 0; i < 40; i += 1;) {
      probe := Telemetry->Start("spin", "cpu", 8, "run");   # model, device, batch, phase tag
      Work->Spin();
      probe->Stop();                                        # elapsed milliseconds, recorded
    };

    store := Telemetry->Default()->GetStore();
    p := store->Predict("spin", "cpu", 8);
    if(p = Nil) {
      store->GetError()->PrintLine();
    }
    else {
      "count {$p->GetCount()}, exact {$p->IsExact()}, p50 <= p95: {$(p->GetP50() <= p->GetP95())}"->PrintLine();
    };

    # a batch never measured is a miss with the reason, not an interpolation
    if(store->Predict("spin", "cpu", 16) = Nil) {
      store->GetError()->PrintLine();
    };

    s := SeriesStats->New(0);                 # 0: no warm-up discard
    s->Add(2.0); s->Add(4.0); s->Add(4.0); s->Add(4.0); s->Add(5.0); s->Add(5.0); s->Add(7.0); s->Add(9.0);
    "n={$s->GetCount()} p50={$s->GetP50()}"->PrintLine();
  }
}

The clock. Every duration comes from System.Time.Timer, the C++ steady_clock: monotonic, never jumping with the wall clock, with nanosecond ticks (the Windows tick is 100 ns). A latency is GetElapsedTime() * 1000.0. The runtime exposes no absolute nanosecond timestamp, so anything placed on a timeline (a sampler reading, the energy attributed to a call) uses Telemetry->NowMs(), at one millisecond resolution. An empty Start plus Stop measured 29 ns at the median on Linux (WSL2); Telemetry->MeasureOverhead(n) measures it on your machine. A handle that is never stopped records nothing, Cancel() drops a failed call, and Telemetry->Time(model, device, batch, tag, fn) times a function reference. The static calls share one process-wide recorder; make a TimingRecorder->New() to keep profiles apart (it is safe to share between threads).

Statistics. SeriesStats keeps the count, minimum, maximum, mean and sample standard deviation by Welford's update (a test checks a 1e9 offset), a warm-up discard (SeriesStats->New(n) drops the first n samples and nothing smarter: there is no steady-state detection) and a ring of the last 256 raw samples. Quantiles are nearest rank: the sample at rank ceil(q * n), so p50 of 2 4 4 4 5 5 7 9 is 4 and a value never appears that was not observed. Up to 512 samples they are exact (IsExact()); beyond that LatencySketch answers, a log-bucketed histogram (the DDSketch construction) whose estimate is within a stated relative error of the order statistic, 1 percent by default with about 12 KB, whatever the count. The regression test measured the worst error against exact sorting at 0.99 percent on a bimodal set, 0.87 on lognormal, 0.66 on uniform, 0.65 over twelve decades and 0 on a constant, and fails if any quantile exceeds the bound; merging two sketches gives the sketch of the union. There are no confidence intervals: a p99 from 200 samples is the 198th value, a p99.9 needs at least 1,000 samples, and samples from one process are not independent, so compare configurations in the same process, interleaved.

Resources. RuntimeSampler reads the runtime's own runtime.* monitors (resident and peak memory, heap, CPU time and percent, threads, collector counts and pauses); GpuSampler runs nvidia-smi (an absent GPU is a graceful no-op: IsAvailable() is false and GetError() says why); SamplerLoop samples on its own thread, and once a second is enough because each GPU sample starts a process. PowermetricsSampler for Apple Silicon is the interface only and always unavailable: powermetrics needs root and no Apple hardware was used. EnergyEstimator integrates sampled power with the trapezoid rule, and it is an estimate: board power is itself a sensor reading, and the energy attributed to a call is the average board power over the call times its duration, which includes whatever else runs on the GPU. The collector exports counts and the last, maximum and average pause, but no total pause, no pause distribution and no safepoint wait; the full list of gaps is in ai_sections/telemetry.md.

Profiles. ProfileStore aggregates by model, device, batch and tag. Save writes lossless JSON (moments, exact samples, the sketch), so a loaded profile gives the same quantiles and Merge makes the profile of the union; SaveCsv writes a summary for a spreadsheet, and a profile loaded from CSV works for Predict but merges with NaN quantiles rather than an invented number. Predict returns what was observed in that cell (p50, p95, p99, mean, extremes, memory, and energy per run when a power source was attached) or Nil with the reason; a batch is never interpolated, because latency against batch is not linear. ContentionRunner->New(workers, calls, fn)->Run() runs K threads and reports throughput and GetMedianSpread(), the slowest worker's median over the fastest; run one worker first as the baseline.

What it is not. It is the host-side latency of a call: for an asynchronous GPU launch it measures the call, not the kernel, and it uses no CUDA events. It decides nothing; the policy that uses a profile is a later layer. Five regression programs (telemetry_sketch, telemetry_stats, telemetry_profile, telemetry_sampler, telemetry_contention) need no network and no GPU, and the timing tests check lower bounds only. The program above was compiled and run for this guide; the GPU sampler, PowermetricsSampler, the energy estimator, JSON and CSV profiles and ContentionRunner were not run here (the regression tests cover them). Examples: programs/examples/telemetry_demo.obs (offline) and programs/examples/telemetry_onnx.obs; reference: ai_sections/telemetry.md.

LLM utilities (API.LlmUtil)

Helpers for the work around a chat model, in Objeck with no network code and no key: prompt templates and a message builder, token estimation with a context window that keeps a conversation inside a budget, JSON Schema validation that reports every problem with a JSON pointer, and structured calls that ask any chat backend for JSON matching a schema and retry with the validation errors until the reply is right. Any backend works through the two-method ChatFn interface, which you implement over the client you use. Compile with -lib llm_util,regex,json,gen_collect.

use API.LlmUtil;
use Collection;

class Example1 {
  function : Main(args : String[]) ~ Nil {
    template := PromptTemplate->New("Summarize for {{audience|a general reader}}.\n{{#if style}}Style: {{style:lower}}\n{{/if}}Sources:\n{{#each sources}}{{@number}}. {{this}}\n{{/each}}Text: {{text:json}}");

Placeholders: {{name}} (required), {{name?}} (optional), {{name|fallback}} (a default), {{name:json}} (a filter: json, upper, lower, trim), {{#each items}}...{{/each}} (with {{this}}, {{@index}}, {{@number}}), {{#if name}}...{{else}}...{{/if}} and \{{ for a literal. Render returns Nil and GetError() names every missing variable at once. Values are never scanned for placeholders, so text a user supplies cannot add a variable or a loop to your prompt. A bad template is a value, not a crash: IsOk() is false and GetError() says what and where. PromptBuilder collects a conversation (System, User, Assistant, each from text or a template) and gives it as ToPairs() for Completion->Complete, or as ToJsonMessages(with_system) for OpenAI-style APIs and Ollama.

Prompt literals. prompt "Answer {question} in at most {words : Int} words." is checked when the program is compiled: {name} is a hole filled from the variable name, {name : Type} also requires the variable to be exactly that type (String, Int, Float, Bool, Char, Byte), {{ and }} are literal braces and {$expression} is the ordinary interpolation. A hole that names no variable, a declared type the variable does not have, an object in a hole or {} is a compile error at the line and column of the hole. The value is a Prompt: ToString() renders it with each String value fenced between tags that do not occur in the value (<question>...</question>, or question_1 when the value holds </question>), so a value cannot close its own slot; EstimateTokens() estimates its size. The fence marks where a value begins and ends and does not stop a model from obeying what the value says. prompt is a keyword only directly before a string. Section "Prompt literals" of ai_sections/llm_util.md has a program with its output and the rules; programs/deploy/prompt_literal_47.obs is a runnable example.

Tokens and context. TokenEstimator counts what a byte-pair tokenizer usually produces, with no tokenizer and no network call (Estimate("Hello, world!") is 4). Its bounds, calibrated by hand against cl100k: English prose within about 15 percent (a little high), source code and JSON within about 30 percent, CJK within about 50 percent, and a single short string can be off by two tokens. The regression test holds it to characters-per-token ranges on fixed samples and has not been compared with a live tokenizer, so use it for a budget with a margin (SetScale(1.15) suits Claude, whose tokenizer gives 10 to 20 percent more tokens; SetMargin and Safe()), and use the provider's own count where a limit is hard (TokenCounter is a one-method interface that both fit). ContextWindow->New(budget, counter)->Fit(conversation) drops the oldest turns first, keeps the system prompt and the newest turn, never starts on an assistant turn and can add an omission note to the system prompt. It drops turns; it does not summarize them.

Structured calls. StructuredCall->New(chat, schema) adds the schema to the system prompt, finds the JSON in the reply (a fenced block, a sentence around it or the whole text), validates it and, on a failure, sends the model its own reply with the exact errors, up to SetMaxRetries(n) times (default 2). SetRepair(true) turns on a lenient JsonRepair, off by default and used only after the strict parse failed: trailing commas, single quotes, unquoted keys, a reply cut off, raw line breaks in strings, True, None and NaN, comments and text after the value. It does not guess further (a missing value, colon or comma stays an error), and a repaired value is still validated. LLM evaluation (System.LLM.Eval)

System.LLM.Eval measures how well a language model writes programs, and in general evaluates any model on tasks whose answer can be checked. It sends each task of a suite to the model N times, takes the code block out of the answer, compiles it with the real compiler (obc), runs it under a timeout and compares what it printed with the expected output. Each attempt records whether it compiled, ran and was correct, the first compiler error (normalized into a category), and tokens and latency when the client exposes them. The results become a compile rate, pass@k, the most common error categories and, for two models, a paired-bootstrap comparison with a plain verdict.

It is a research harness, not a shipped library: the source is tools/llm_eval/llm_eval.obs, and you compile it with your program, obc -src yourprogram.obs,tools/llm_eval/llm_eval.obs -lib ml,csv,json,gen_collect. It needs no network and no key; the provider adapters (OpenAI, Anthropic, Gemini, Ollama, or any command line) are one file each in tools/llm_eval, because the four clients cannot be linked into one program. obc must be on the path or beside the running VM. A ScriptedModel answers from a script, so the whole path runs without a key (the second answer below does not compile):

The task suite. tools/llm_eval/tasks holds 40 tasks graded 1 to 5 across basics, collections, classes, generics, lambdas, exceptions, file I/O, JSON, recursion and the quirks models trip on in Objeck (the ~ before a return type, Nil, := against =, Int[] arrays, use). The run costs tasks x n model calls and prints the count first. Flags include --n (attempts per task; pass@k needs n of at least k, and attempts differ only with a temperature above 0), --k, --ids, --categories, --out PREFIX (writes PREFIX.md, PREFIX.json and PREFIX_results.json), --baseline FILE, --system-file, --max-tokens, --keep-files and --list. adapter_command.obs evaluates any tool with a command line: the prompt goes to its standard input and its output is the answer. To compare two runs, compare.obs reads two _results.json files, and ModelComparison->Of(a, b, reps, seed) pairs attempt j of a task for model A with attempt j for model B and gives Metrics->PairedBootstrapDifference those pairs. A positive difference means B is better, and the verdict is one of <model> is better than <model>: +33.3 points of pass rate, 95% interval [21.7, 46.7] excludes 0. (either way round) or No significant difference: ... includes 0. The pairs are attempts, not tasks, so with several attempts per task the interval is a little narrower than a resampling of whole tasks would give.

Reading the report. EvalReport->Markdown writes a summary row per model (compile rate, pass@k, failed API calls, mean latency, tokens in and out, n/a when the client does not say), pass@1 by category, the compile-error categories (undefined_class, undefined_variable, undefined_method, type_mismatch, generics, missing_return, scope, syntax, array, string_interpolation and others, with quoted names replaced by '_' so messages that differ only in a name group together), the outcomes (pass, wrong_output, runtime_error, timeout, compile_error, no_code, model_error), a per-task table and, for two models, the verdict. pass@k is the unbiased estimator of Chen et al. (2021), 1 - C(n-c, k) / C(n, k) averaged over tasks (PassAtK->Estimate(10, 3, 5) is 0.916667); a task with fewer than k counted attempts is left out, and attempts whose model call failed are left out of every rate.

Limits.

  • A program runs through a small watchdog script (a shell script on Linux and macOS, PowerShell on Windows) that kills it past its time and caps what it prints, but it is not otherwise sandboxed: it runs with your permissions and can read and write files and use the network. Evaluate untrusted models in a container or a throwaway account.
  • Attempts run one after another, and a task is judged by standard output only. An answer without a fenced code block is no_code; with several blocks the longest one that defines Main is used.
  • Only the Anthropic and Ollama clients report token counts.
  • Each compile is a real obc run, about 0.1 to 0.5 s.
  • The provider adapters are compiled but not exercised against the live services by the regression suite. The library, the checkers, the watchdog, CommandModel and the report are.

N-grams, spelling and style features

These are the features of text-classification chapters such as fake-review and fake-news detection. All are in nlp.obl; none needs a model.

TF-IDF over word n-grams. TF_IDF->New(min_n : 1, max_n : 2) counts words and word pairs as scikit-learn's TfidfVectorizer(ngram_range=(1, 2)) does; (1, 3) adds triples and (2, 2) is pairs only. Smoothed IDF and unit-length vectors follow scikit-learn (the regression test compares every IDF and vector entry with it). min_df drops terms found in fewer documents and max_features keeps the most frequent ones. Fit returns true when it built a vocabulary. An invalid setting (min_n below 1, max_n below min_n), a Nil or empty corpus, or a corpus with no term left returns false: IsValid() is false for a bad setting and GetError() says why (it is "", never Nil, when there is nothing to report). Existing calls such as TF_IDF->New(stem : true) and a statement tfidf->Fit(docs); still compile.

TransformAll(texts) and FitTransform(texts) give a Float[,], a row per text, ready for a classifier, so no study writes the loop. The matrix is dense: 8 bytes times the vocabulary times the documents (40,000 documents at 20,000 terms is 6.4 GB). EstimateDenseBytes(documents) tells you before you ask, and TransformAll returns Nil with a reason rather than allocate more than GetMaxDenseBytes() (2 GiB; SetMaxDenseBytes changes it). Limit the vocabulary with max_features and min_df.

tfidf := TF_IDF->New(min_n : 1, max_n : 2, min_df : 2);
X_train := tfidf->FitTransform(training_texts);   # Nil, with tfidf->GetError(), when Fit fails
X_test  := tfidf->TransformAll(test_texts);       # the test texts use the training vocabulary
bytes   := tfidf->EstimateDenseBytes(100000);

Misspelling rate. SpellChecker counts the tokens a word list does not know. No dictionary ships with Objeck: load a newline-delimited list yourself, for example /usr/share/dict/words on Linux, the SCOWL / aspell lists (http://wordlist.aspell.net) or words_alpha.txt, and check its licence. Tokens are Tokenizer->WordTokenize's, matching is case-insensitive, tokens with digits are never misspelled, and the rate is misspelled tokens over all tokens. Suggest returns words within a Levenshtein distance, nearest first. TextSimilarity->LevenshteinDistance(a, b, max_distance) is the same distance with a ceiling: it returns the exact distance when that is at most max_distance and max_distance + 1 otherwise, and only computes the cells near the diagonal, so comparing one string with many far-off ones is cheap (Suggest uses it). A checker with no words and a Nil text give -1 instead of failing.

checker := SpellChecker->New("words.txt");   # checker->GetError() is "" when fine

    n    := checker->CountMisspelled("teh product is gud");

    near := checker->Suggest("gud", 1, 3);
};

BERT tokens and sentence embeddings

WordPieceTokenizer is BERT's tokenizer (Hugging Face's BertTokenizer, checked id for id on a 13,000-line corpus); it reads a model's vocab.txt and gives the input_ids, attention_mask and token_type_ids a BERT-family ONNX model takes. ApiSequenceTokenizer builds a vocabulary of API names from malware traces. BpeTokenizer is RoBERTa's and GPT-2's byte-level BPE (checked id for id and offset for offset against Hugging Face's tokenizers, with DistilRoBERTa's own 50,265-token vocabulary). Both implement SubwordTokenizer, and their encodings carry each token's character offsets (GetOffsets, BPE). BertEmbedder (library nlp_onnx) runs an exported BERT through ONNX Runtime and pools its output into one vector per text — CLS, mean over the real tokens, or the model's pooler. The encoder is frozen: train a classifier on the embeddings. Design and limits: docs/ML_BERT_DESIGN.md.

Layers. By default the final layer is pooled. SetLayers (or the three-argument Embed) can pool the sum of the last four hidden layers (SUM_LAST_4, Embed gives hidden columns) or concatenate them (CONCAT_LAST_4, 4 x hidden columns, oldest layer first), each with CLS or mean pooling. A model has to export its intermediate layers for this: four or more FP32 outputs named hidden_states.N (also hidden_states_N, hidden_state_N), or one FP32 [layer, batch, sequence, hidden] output named hidden_states. A standard export does not have them (export with output_hidden_states=True and name the outputs). When the model does not, HasHiddenLayers() is false and Embed with another layer strategy returns Nil and GetError() says so. POOLER pooling is the final layer's only.

embedder->SetLayers(BertEmbedder->Layers->CONCAT_LAST_4);
embedder->SetPooling(BertEmbedder->Pooling->MEAN);
X := embedder->Embed(texts);   # 4 x hidden columns, or Nil with GetError() when the model lacks the layers

Models from the Hugging Face Hub

HubClient (library ai_hub) downloads a model repository's files by name into a local cache, as Python's from_pretrained does, and returns the snapshot folder the model classes open.

  • Pinned to one commit: every file of a snapshot comes from the same commit.
  • Verified: each file is checked against the Hub's SHA-256 (large files) or git blob hash (small files), and its size. A mismatch is not kept.
  • Streamed: downloads go to disk, so file size is limited only by disk space.
  • Cached: a second run downloads nothing, and OBJECK_HUB_OFFLINE=1 works from the cache alone. Python's cache is read as a fallback, never written.
  • Tokens stay with the Hub: a token (HF_TOKEN) is sent to the Hub only, never to its file CDN.

The default cache is .objeck/hub in your home folder; set OBJECK_HUB_CACHE to move it. Design: docs/AI_FOUNDATION_DESIGN.md §7.3.

Topic modeling and BSON (System.NLP.Topics)

LDA topic modeling for text, with the steps of a Gensim workflow: decode a MongoDB .bson dump, tokenize, drop stopwords, build a dictionary and filter infrequent tokens, train, read the topics, measure their quality and draw them. It is one library, nlp_topics.obl (-lib nlp_topics,json,plot,gen_collect, or -lib @ai; it needs json for the BSON documents and plot for the picture). It was written for the topic-modeling lab of "Extracting Cyber Threat Intelligence from X Using AI" (book chapter 11), but nothing in it is specific to that data.

use System.NLP.Topics;

texts := BsonReader->ReadStrings("CyberTweets.bson", "text");       # step 1: the "text" field of every document
docs := TopicTokenizer->New(TopicStopwords->English()->Union(TopicStopwords->Cyber()))->TokenizeAll(texts);

dict := TokenDictionary->New();                                       # step 2: Gensim's Dictionary
dict->AddDocuments(docs);
dict->FilterExtremes(5, 0.5, 0)->ToString()->PrintLine();             # size and % of token occurrences removed
corpus := dict->ToCorpus(docs);

lda := Lda->FitBest(corpus, dict, 10, 0.0, 0.0, 20, 50, 2000, 1, 5);  # step 3: 10 topics, best of 5 seeds
lda->GetTopic(0, 10)->ToString()->PrintLine();                        # step 4: top words and mixtures
mix := lda->GetDocumentTopics(corpus, 0);                             # Float[] that sums to 1
"bound {$lda->LogPerplexityBound(corpus)}, perplexity {$lda->Perplexity(corpus)}"->PrintLine();

cv := TopicMetrics->Mean(TopicMetrics->CV(lda->GetTopics(10), docs, 110));
TopicPlots->SaveReport(lda, corpus, 0, 0.6, 15, "topics.svg");        # step 5: a static counterpart of pyLDAvis
  • BSON. BsonReader decodes a .bson file (documents back to back, each starting with its own little-endian length) into Data.JSON elements, one at a time with HasNext/Next or all at once; ExtractStrings("user.name") takes one string field, by dotted path, from every document and counts the ones it skipped. Every type is mapped: strings, numbers, documents and arrays as themselves, an ObjectId as its 24 hex digits, a datetime as an ISO-8601 string, binary, timestamp, regular expression and min/max key as small $-objects, and decimal128 is kept as its 16 raw bytes ({"$decimal128": hex}) and not decoded. Bad input does not crash or hang the reader: every length is checked against the bytes left, nesting deeper than 100 levels (MongoDB's own limit) is refused, and a truncated or hostile file gives Nil and a message with the byte offset in GetError(). The class documentation lists the mapping in full.
  • Tokens and stopwords. TopicTokenizer lowercases, keeps runs of a-z and digits (so it suits English text; accented and non-Latin characters end a token), drops URLs and @mentions, keeps a hashtag's word and drops tokens that are too short, all digits or on the stopword list. It is its own tokenizer, and does not use TextPreprocessor, because tweets need the URL and mention handling and TextPreprocessor would add a dependency on nlp.obl; there is no stemming. The three stopword strategies of the lab are data: TopicStopwords->New() (none), ->English() (the 179 words of NLTK's English list, embedded, so nothing is downloaded) and ->English()->Union(->Cyber()). Cyber() is a small starting point, 28 words of Twitter noise and of words found in nearly every cybersecurity tweet, not a researched list; build your own with FromArray.
  • Dictionary. TokenDictionary is Gensim's Dictionary: token to id, document and collection frequencies, FilterExtremes(no_below, no_above, keep_n) with Gensim's semantics (no_above times the number of documents, truncated; keep_n keeps the most frequent, ties to the smaller id; ids are compacted in their old order) and ToCorpus for the bag-of-words TopicCorpus. FilterExtremes returns a FilterReport: the dictionary size before and after and the percentage of token occurrences removed (and of distinct tokens).
  • LDA. Lda is online variational Bayes, the algorithm of Hoffman, Blei and Bach and the one Gensim's LdaModel uses, with Gensim's parameters: num_topics, alpha (a number, or SetAlphaMode("asymmetric") or "auto"), eta, passes, iterations, a seed, plus SetChunkSize, SetLearningRate (offset and decay) and SetGammaThreshold. Passing 0 for alpha or eta means Gensim's default of 1/num_topics. GetTopic/GetTopics give the top words with their probabilities, GetDocumentTopics the mixture of one document (a probability vector), GetDocumentTopicMatrix all of them, GetLambda the topic-word pseudo-counts in Gensim's layout, Save (or Store, the System.ML spelling) and Load the model in a file with a checksum, and GetDocumentTopicMatrix2D/GetLambda2D the same numbers as Float[,] matrices. It is comparable in kind to Gensim, not numerically identical: the random generator differs (so a seed gives another, equally valid, model), the E step starts each document from gamma = 1 instead of a random draw, and summation order differs. The same seed gives the same model on every run and platform here.
  • Local optima. Variational Bayes starts from a random point and can end with two real topics merged and another split. On the planted-topic data of the tests roughly half of the seeds did, and the per-word bound of such a run is clearly lower. So train from several seeds and keep the best: Lda->FitBest does that, and TopicMetrics->Stability measures how alike two runs are. Reading a stability number. Stability is the mean over the topics of one model of the best cosine with any topic of the other (not one-to-one), averaged over both directions, so one pair of seeds is a coin toss, not a measure: when both runs reach the same optimum it is about 1.0, and when one has merged two topics it drops to 0.67 to 0.8. On the 600-tweet planted corpus (K = 5, 10 passes, 50 iterations, 15 seed pairs from six seeds) Objeck gave a mean of 0.84 (min 0.67, max 1.00, 3 pairs above 0.99) and Gensim 0.88 (min 0.67, max 1.00, 3 pairs above 0.99), the same distribution; the single pair of seeds 11 and 12 happens to be 0.996 in Objeck and 0.673 in Gensim, which says nothing about either. Report the mean over several seed pairs, or the best-of-seeds model from FitBest, rather than one pair. The cosines themselves were checked: Objeck's two topic-word matrices fed to a numpy implementation of the same definition give the same stability to 1e-15.
  • Bound and perplexity. LogPerplexityBound(corpus) is Gensim's log_perplexity: a variational lower bound on the log likelihood per word. It is negative and higher is better. It is not perplexity; Perplexity(corpus) returns exp(-bound), lower is better. The lab table in topic_lab.obs prints both and says which is which.
  • Coherence. TopicMetrics implements three measures after Roeder, Both and Hinneburg (2015), each the mean over a topic's word pairs, on the top-N words you pass in: UMass (document co-occurrence over the bag-of-words corpus, log((D(wi,wj)/D + 1e-12) / (D(wj)/D)) over pairs with j < i; Gensim's u_mass), CNpmi (normalized PMI over sliding windows, Gensim's c_npmi, whose default window is 10) and CV (the NPMI context-vector cosine, Gensim's default c_v, window 110). The windows are cut from the token lists you pass in; a text no longer than the window is one window, an empty text one empty window, as in Gensim. Gensim's sliding window has a quirk that is reproduced on purpose so the numbers match: when it slides it removes the token that left even if the same word is still inside the window, so a word repeated within a window is under-counted (a plain per-window set count differed from Gensim by up to 0.18 on a test corpus). Diversity (unique words among all topics' top-k, divided by topics times k), Overlap (mean pairwise Jaccard of the top-k sets) and Stability (mean best-match cosine between two models' topic-word vectors, taken both ways) complete the lab's metrics.
  • Picture. TopicPlots writes one SVG with an intertopic distance map (topics placed by classical MDS of the square roots of their Jensen-Shannon divergences, circle area proportional to prevalence) and the bar chart of a topic's most relevant terms (relevance with a lambda you choose, grey bar for the corpus frequency, colored bar for the part the topic explains). It is a simple static counterpart of pyLDAvis: no slider and no interactivity; the term ranking uses pyLDAvis's relevance formula. Relevance and SalientTerms return the numbers behind it.

Measured on a Ryzen 9 7950X3D (Windows, JIT on) with a synthetic corpus of 20,000 documents of 12 tokens, a vocabulary of 10,000 and 15 topics: tokenizing 0.5 s, dictionary, filter and corpus 0.3 s, Fit 0.28 s per pass (2.8 s for 10 passes, 8.2 s for 30, since the E step stops early once documents converge), LogPerplexityBound 0.3 s, c_v coherence 0.06 s. A corpus of 50,000 such documents trained 5 passes in 3.5 s. Memory is a few arrays of vocabulary times topics doubles.

Limits: one thread; text is English (ASCII tokens); num_topics times the vocabulary may not exceed 50 million; no live data was used, so the lab numbers in the example come from a planted synthetic corpus. What was checked against independent values is listed in the test headers: the model against a numpy/scipy port of the same algorithm, the BSON decoder against hand-encoded struct.pack fixtures and against bytes written by pymongo's bson, and the coherence measures against Gensim 4.4.0's CoherenceModel (u_mass, c_npmi, c_v; they agree to 1e-16, programs/regression/nlp_topics_gensim_check.py). Against Gensim's LdaModel on two planted-topic corpora (tools/ml/lda_gensim_compare) the per-word bounds agree to about 0.01 to 0.1 for fits of the same quality, a fit with merged topics scores clearly lower in both, and when both end in the same optimum the topics and document mixtures agree (cosine 1.000); the two systems do not land in the same local optimum from the same seed number.

The whole lab, with the five experiments of the assignment (topics, minimum frequency, stopword strategy, passes, alpha) printed as System.ML.Lab tables on a synthetic corpus with planted topics, is programs/examples/ml/topic_lab.obs.

Model Persistence

Store/Load round-trip the linear models (LinearRegression, RidgeRegression, ElasticNet, LassoRegression, LogisticRegression, Perceptron, SVM), GaussianNaiveBayes, GaussianMixture, PCA, NeuralNetwork, DecisionTree, RandomForest, AdaBoost, RegressionTree and GradientBoostedTrees; loaded models reproduce the original predictions exactly. KernelSVM, OneClassSVM, RandomForestClassifier, EmbeddingClassifier, KMeans, DBSCAN, KNearestNeighbors and the outlier detectors have no Store/Load: refit them (they are seeded, so a refit is reproducible). LassoRegression loads back as an ElasticNet.

model->Store("model.dat");
loaded := LinearRegression->Load("model.dat");
loaded->Predict(X);

Load answers Nil for a file that is missing, not a zlib stream (a truncated download, a file from another tool) or not a model of that type, rather than ending the program. Check for Nil, as above. System.IO.Deserializer has the same two pieces for your own formats: IsOk() is false when the bytes were Nil, damaged or not zlib, and every read then answers its zero value; Byte->TryUncompressZlib(bytes) is UncompressZlib that returns Nil instead of ending the program.

Bad input

Fit, Predict, Transform and Score do not end the program on a Nil, an empty or a wrong-width matrix, or on targets that do not match its rows. They answer a failure value instead, as scikit-learn raises a ValueError you can catch. What that value is depends on the method:

CallOn bad input
Fit of the matrix models (the linear models, GaussianNaiveBayes, PCA, FeatureScaler, GaussianMixture, DBSCAN, the tree and boosting classes, KernelSVM, OneClassSVM, AdaBoost)false
DenseNetwork->Fita Float below 0.0 (the loss otherwise)
DecisionTree->Fit and RandomForest->Fit (the Bool[,] ones)Nil, as always: the failure shows in IsFitted()
Predict, PredictScore, PredictAll, TransformNil
Score0.0
Predict(row) of RegressionTree and DecisionTree, whose result has no room for an error0.0 / false, for a row of another width than the tree was fitted on

Score returns 0.0 for bad input, which is also a real accuracy or R-squared. To tell them apart, call Predict on the same matrix first (it is Nil for bad input), or check IsFitted(). Metrics->ThresholdAtFpr has the same limit: it returns 0.0 for bad input and for a real threshold of 0.0; Metrics->RecallAtFpr returns -1.0 for the same input, so check that first.

A model remembers the width it was fitted on, so a feature matrix with a different column count at predict time (the usual mistake, and the one a changed CSV produces) gets Nil. A Bool[,] model takes the width of its training matrix, label column included, for Score and either that width or one less for Predict. A tree or forest read back from a file has no width on record, so only the shape is checked there.

A Fit that is refused for its arguments leaves most models as they were: the linear models, the trees and boosters, GaussianNaiveBayes, GaussianMixture, PCA, FeatureScaler, DBSCAN, AdaBoost, the Bool[,] trees and forests and DenseNetwork (which has no fitted flag, only its weights). IsFitted() stays true and Predict answers from the earlier fit, as scikit-learn leaves the old model when fit raises. KernelSVM, OneClassSVM, EmbeddingClassifier and the outlier detectors mark themselves unfitted at the start of Fit, so a refused refit leaves them unfitted, and so does a Fit that fails inside the solver (a singular system). Check the result of Fit, or IsFitted() on a model you meant to fit for the first time, rather than assuming either. programs/regression/ml_input_validation.obs runs every model against Nil, empty, wrong-width and mismatched-target inputs.

if(<>model->Fit(X, y)) {
  "could not fit: check that X and y have the same number of rows"->ErrorLine();
};
preds := model->Predict(X_new);
if(preds = Nil) {
  "X_new does not have the columns the model was fitted on"->ErrorLine();
};

A cell, a deviation or a chart point that is NaN or infinite is a missing value, not a number: System.Stats returns NaN by design (a degenerate fit has no p-value), and it can flow straight into a ResultTable. Number formats. A column is "fixed" (its decimals, the default and the only form before) unless you ask: AddIntegerColumn(name) writes a count as 176 instead of 176.0000, AddPValueColumn(name) writes 0.0471 but <0.0001 for anything smaller (a tiny p-value no longer reads as 0.0000), AddScientificColumn(name, decimals) writes 1.23e-05, and AddColumn(name, decimals, "fixed" | "sci" | "p" | "int") is the general form. Scientific text matches Python's '%.*e' (checked on 600 random values).

Local vector search (System.ML.VectorSearch)

A local index for retrieval over your own documents, with no hosted vector store: keep an embedding per document under a string id and ask for the closest ones to a query vector. It is ml_vector.obl (-lib ml_vector,gen_collect or -lib @ai) and needs nothing from System.ML. The vectors can come from anywhere that gives a Float[]: BertEmbedder (see BERT tokens and sentence embeddings), the OpenAI, Gemini and Ollama embedding calls, or a file.

use System.ML.VectorSearch;

index := VectorIndex->New(384, VectorMetric->COSINE);   # DOT and L2 too
index->Add("doc-1", embedding_1);      # Float[] of exactly 384 values; false if refused
index->Add("doc-2", embedding_2);

hits := index->Search(query_embedding, 5);     # the 5 closest, closest first
each(i : hits) {
  "{$hits->Get(i)->GetId()}  {$hits->Get(i)->GetScore()}"->PrintLine();
};

index->Remove("doc-1");
index->Store("docs.vix");
loaded := VectorIndex->Load("docs.vix");       # Nil if the file is not a good index
  • Metrics. COSINE and DOT score higher-is-closer (the cosine similarity or the dot product); L2 scores the Euclidean distance, so lower is closer. Search returns the hits closest first for all three.
  • Exact. A search scans every vector, so it always returns the true top k; there is no approximate mode. Ties on the score are broken by id, smallest first, so the answer does not depend on the order vectors were added or removed in. That holds for bit-identical scores: vectors that tie only mathematically (parallel vectors of different length under COSINE, say) can differ in the last bit and then rank by that bit, not by id. COSINE scores are clamped to [-1, 1]. Add of an id that is already there replaces its vector, and Get and Add copy, so the caller's arrays never alias the index.
  • Bad input returns a value. A wrong-length, Nil, NaN or infinite vector, a Nil or empty id, k below 1 and an index created with a dimension below 1 never end the program: Add, Remove and Store return false, Search returns an empty Vector (never Nil) and Get returns Nil, and the index's GetError() says why. Load is a function with no index to ask, so it returns Nil and gives no reason. Cosine scores a zero-length vector as 0.
  • Value range. A nonzero value must have a magnitude between 1e-100 and 1e100 (zero is fine); Add and Search refuse anything else, and say so. Past that range a squared length overflows or underflows, so a cosine would silently read 0 and a dot product could turn NaN and break the ranking. Rescale such data first. Inside the range every score is finite.
  • Files. Store writes a small header (a format tag and a CRC32 of the body) and then the body through System.IO.Serializer, the path the System.ML models use. Load checks the tag, the three reserved header bytes (zero) and the CRC32 before it decompresses anything, so a missing, truncated, damaged or foreign file gives Nil. (The System.ML model loaders cannot do that yet: see LIBRARY_BACKLOG_2026_11.md item 1.)
  • Memory. Objeck's Float is 64 bits, so a vector of 384 values takes 3 KB: 100,000 of them take about 307 MB, plus the ids. The first Add at the largest dimension (1,048,576) allocates a 128 MB block, and Load holds the file, its body and the decoded vectors at once, about three times the file size at its peak.
  • Threads. An index is not thread-safe: Search records a refusal in the index, so concurrent calls, or a search beside Add or Remove, need the caller's lock.
  • Parallel search. index->SetThreads(8) splits a search over a large index (about 8 MB of vectors or more) into that many parts, scans each on its own thread and merges the parts' best results. The answer, ties included, is the same as with one thread (the test compares ids, scores and order for all three metrics). Smaller indexes are always searched on the calling thread, and the default is 1. Each search starts its threads, so this helps one slow search; it does not raise the throughput of many small ones.

Measured on a Ryzen 9 7950X3D (Windows, JIT on, -opt s3), random vectors of 384 values, one thread, 20 queries after a warm-up, top 10:

The three metrics cost the same, and a four-accumulator unrolled inner loop was no faster: at 100,000 x 384 a search streams 307 MB, so one thread is limited by memory bandwidth (about 7 GB/s) and not by arithmetic. Several threads get more of the machine's bandwidth: at 100,000 x 128 (L2, top 10, 500 queries) SetThreads gives 66, 81, 132, 229 and 315 queries/s at 1, 2, 4, 8 and 16 threads, and no more at 32. An approximate index (HNSW) was not built: 44 ms per query is fast enough for retrieval over a document collection of this size, and an approximate answer brings recall to measure, a second file format and a build step with it. If you need far more vectors or queries per second, the next step is HNSW or an inverted-file index, not a faster scan.

Replicates and reports (System.ML.Report)

ml_report.obl (-lib @ai, or ml_report,ml_lab,ml,stats,plot,csv,json,gen_collect) turns a study into a hand-in: a single document with numbered sections, results tables, figures, code and notes, that opens in a browser and prints to PDF. It is pure Objeck, so it runs in the web playground. No call ends the program on bad input: a call that cannot do its job returns false (or Nil) and GetError() says why, "" when there is nothing to report. Output is deterministic (nothing reads a clock), so a test can compare exact strings.

Replicates collects the value of each metric per seed and per setting (group). A statistic leaves out a value that is not finite (NaN, an infinity, or the marker given to SetMissing, for the -1.0 that Metrics->AucRoc returns) and GetMissing counts them; a statistic that needs more values than there are is NaN, so one seed has a mean and an undefined standard deviation.

use System.ML.Report;

rep->GetMean("depth 2", "test_accuracy")->PrintLine();
rep->GetStd("depth 2", "test_accuracy")->PrintLine();        # sample (n - 1) standard deviation
rep->GetCiLow("depth 2", "test_accuracy")->PrintLine();      # t interval of the mean, n - 1 df

Face verification: FAR, FRR, EER and CLIP embeddings (System.ML.Verification, System.ML.Clip)

Two libraries for a verification study such as "does a CLIP image embedding separate same-person pairs from different-person pairs on Labeled Faces in the Wild". ml_verify.obl (in @ai, needs only gen_collect, pure Objeck, so it runs in the web playground) holds the metrics. ml_clip.obl (in @vision; needs onnx, opencv, models, ml_verify) holds the CLIP image encoder and the pair reader. No call in either ends the program on bad input: a call that cannot do its job returns a failure value (Nil, false, or a result whose IsValid() is false) and GetError() says why, "" when there is nothing to report. A scalar with no value is NaN.

Metrics. A pair is accepted when its similarity score is greater than or equal to the threshold. FAR (false acceptance rate) is impostor pairs accepted over impostor pairs, FRR (false rejection rate) is genuine pairs rejected over genuine pairs, and the EER (equal error rate) is where the two are equal. Verification->Evaluate(scores, same) takes one score per pair (higher means more alike, finite) and a Bool[] that is true for a same pair, and returns a VerificationResult:

use System.ML.Verification;

r := Verification->Evaluate(scores, same);
if(<>r->IsValid()) {
  r->GetError()->ErrorLine();            # "no impostor (different) pair: FAR is undefined", "score 3 is not finite", ...
  return;
};
"EER {$r->GetEer()} at threshold {$r->GetEerThreshold()}"->PrintLine();
far := r->FarAt(0.65);                   # FAR, FRR and accuracy at any threshold
frr := r->FrrAt(0.65);
acc := r->AccuracyAt(0.65);
best := r->GetBestAccuracyThreshold();   # the threshold with the best accuracy (ties: the lowest)
frr_1 := r->GetFrrAtFar(0.01);           # FRR when FAR may not exceed 1%
t_1 := r->GetThresholdAtFar(0.01);

The curve has one operating point per distinct score plus a last point at +Infinity that accepts nothing (FAR 0, FRR 1), thresholds ascending: GetThresholds, GetFarCurve, GetFrrCurve, or all three as rows with GetCurve. Scores that are equal share one point, so a tie is never split. The EER rule: d = FAR - FRR is 1 at the first point and -1 at the last and never increases; the EER is read at the first point where d <= 0. If d is exactly 0 the EER is that point's FAR and the threshold is its score; otherwise the two rates cross between two points and both the EER and the threshold are interpolated linearly along that segment (lambda = d(j-1) / (d(j-1) - d(j))), which is what interpolating the ROC polyline with scipy gives; when the crossing is after the highest score, the threshold reported is the highest score. GetRocCurve returns [threshold, FAR, 1 - FRR] rows in the layout Metrics->RocCurve returns, so Axes->RocCurve("name", r->GetRocCurve()) from System.Plot draws it; GetDetCurve returns [FAR, FRR] rows for a DET plot (Axes->SetLogX(true) after dropping the rows where a rate is 0). Verification->Far, Frr and Accuracy give one number at one threshold in O(n) without building the curve, and Verification->Check(scores, same) returns the reason an input would be refused. Similarity->Cosine(a, b) and Similarity->Normalize(v) are the embedding helpers.

CLIP encoder. ClipEncoder runs an exported CLIP image tower (input pixel_values [N, 3, 224, 224], output the embedding [N, D]; export the Hugging Face model with torch.onnx.export of CLIPModel.get_image_features, the text tower is not needed):

use System.ML.Clip;
use System.ML.Verification;

encoder := ClipEncoder->New("clip-vit-base-patch32-image.onnx");
if(<>encoder->IsOpen()) {
  encoder->GetError()->ErrorLine();
  return;
};
pairs := FacePairs->ReadLfw("lfw_home/pairsDevTest.txt", "lfw_home/lfw_funneled");   # also pairs.txt, pairsDevTrain.txt, or ReadCsv
scores := encoder->ScorePairs(pairs);                    # cosine per pair; each distinct image is embedded once
r := Verification->Evaluate(scores, pairs->GetLabels());
"EER {$r->GetEer()}"->PrintLine();

Embed(path, normalize), EmbedImage(image, normalize) and EmbedBatch(paths, normalize) give raw or L2-normalised embeddings (the batch size is SetBatchSize, 16 by default). ClipPreprocessor is what CLIPImageProcessor does: resize the shortest side to 224 with a bicubic filter, centre-crop 224 x 224, RGB, scale to 0..1, normalise with the CLIP mean (0.48145466, 0.4578275, 0.40821073) and standard deviation (0.26862954, 0.26130258, 0.27577711), CHW. Its default resize, ClipPreprocessor->Resize->PIL_BICUBIC, is Pillow's bicubic written in Objeck, with Pillow's antialiasing (the filter support grows with the shrink factor), 22-bit fixed-point coefficients, 8-bit intermediate rounding and the order of the two passes Pillow chooses (that order is an empirical rule, fitted on 1,478 random sizes and not read from Pillow's source). ClipPreprocessor->Resize->OPENCV_CUBIC is cv::resize with INTER_CUBIC instead. A model that was exported with a different input size takes ClipPreprocessor->New(size, mode) and ClipEncoder->New(path, config, pre).

Why Pillow's resize and not OpenCV's. OpenCV's INTER_CUBIC does not antialias when it shrinks an image (it reads four pixels per output pixel, whatever the scale) and uses the kernel with a = -0.75; Pillow uses a = -0.5 and widens the kernel by the shrink factor. On 12 test images (10 LFW faces, one 400 x 250 and one 180 x 320 image, so the aspect-ratio resize and the centre crop are exercised) the Objeck preprocessing with PIL_BICUBIC differs from CLIPImageProcessor's pixel_values by at most 2.8e-7 (the reference is float32; the difference is float32 rounding), and with OPENCV_CUBIC by at most 0.26 in normalised units (about 18 grey levels, at one pixel); the embeddings differ from PyTorch's by at most 1.5e-5 (ViT-B/32), 1.1e-5 (ViT-B/16) and 4.8e-5 (ViT-L/14) with PIL_BICUBIC, and by up to 0.20, 0.28 and 0.38 with OPENCV_CUBIC (cosine to the PyTorch embedding at worst 0.9974, 0.9972 and 0.9945). The ONNX towers themselves agree with PyTorch to 1.1e-5, 1.1e-5 and 1.6e-5 on the same pixels. Two more differences from a Pillow pipeline: OpenCV decodes the image, so a JPEG decoder difference of a grey level is possible (none was seen on LFW), and it applies an EXIF orientation tag, which Pillow does not.

Convolutional networks (System.ML.Cnn)

Convolutional networks for image classification, on the CPU (and, optionally, on an NVIDIA GPU: see the CUDA backend below): Conv, MaxPool, ReLU, Flatten, Dense and Dropout layers with forward and backward passes, the Adam and SGD optimizers, binary cross-entropy on logits, an image dataset with a seeded train / validation / test split and on-the-fly augmentation, and a training loop that records loss, accuracy and wall time for every epoch. The layers are native (libobjk_ml, plain C++ and Eigen, nothing platform-specific: no intrinsics, no OpenMP) and the library is ml_cnn.obl: obc -lib ml_cnn,ml,ml_lab,opencv,csv,json,cipher,gen_collect or -lib @cnn,gen_collect. It reads image files through opencv, scores with System.ML.Metrics and writes its history as a System.ML.Lab.ResultTable.

use System.ML.Cnn;

data := ImageDataset->New(224, 3);              # every image is resized to 224 x 224
data->AddDirectory("real", 0);                  # class 0
data->AddDirectory("fake", 1);                  # class 1
splits := data->Split(0.7, 0.15, 42);           # train, validation, test: seeded, repeatable

aug->SetFlip(0.5);                              # half the training images are mirrored
aug->SetRotation(0.3, 10.0);                    # 30% are turned by up to +-10 degrees
aug->SetBrightness(0.3, 0.8, 1.2);              # 30% are scaled by 0.8 .. 1.2
splits[0]->SetAugmentation(aug);                # augments the training subset only

# the study's baseline: three Conv 3x3 + ReLU + MaxPool blocks (16, 32, 64 filters),
# Dense 128, dropout 0.1, Adam at 1e-4; 5,561,633 parameters at 224 x 224
model := CnnModel->Baseline(224, 3, 0.1, 128, 0.0001, 42);

trainer := CnnTrainer->New(model, splits[0], splits[1], 64, 42);   # batch size 64
trainer->SetVerbose(true);

history->SaveCsv("history.csv");
test := trainer->Evaluate(splits[2]);           # accuracy, precision, recall, F1, confusion matrix
test->ToString()->PrintLine();
model->Save("model.bin");

A different architecture is built layer by layer (each Add answers false and GetError() says why if the layer does not fit):

model := CnnModel->New(3, 64, 64, 42);          # channels, height, width, seed
model->AddConv(32, 3, 1, Padding->SAME);        # filters, kernel, stride, padding
model->AddReLU();
model->AddMaxPool(2);
model->AddFlatten();
model->AddDense(64);
model->AddDropout(0.3);
model->AddDense(1);                             # the last layer is one logit per image
model->Compile(0.001);                          # Adam; CompileSgd(lr, momentum) for SGD
loss := model->TrainBatch(images, labels);      # Float[] of whole images (NCHW) and 0.0 / 1.0 labels
probabilities := model->Predict(images);        # sigmoid of the logit: P(class 1)

What it is, exactly.
LayoutNCHW, float32; a batch is Float[] of whole images, each channels x height x width (planes, not interleaved), values 0 to 1. Weights are [filters][channels][kh][kw] for a convolution and [units][inputs] for a dense layer, the layouts of PyTorch
Convcross-correlation, square kernel, stride, bias; VALID (no padding) or SAME (output ceil(size / stride), an even kernel's extra pixel at the bottom/right, as TensorFlow does). im2col and one matrix multiply per image, the column buffer reused
MaxPoolsquare window, stride defaults to the window, no padding, floor; a tie goes to the first maximum in scan order
Dropoutinverted: survivors are scaled by 1 / (1 - rate) in training, evaluation is the identity. The mask is a function of the model seed, the forward-pass counter and the element index, so a run repeats and ResetDropout() replays a mask
Lossbinary cross-entropy on the logit, `max(z, 0) - z y + log(1 + e^-z)`, stable for logits of any size (a logit of 30,000 gives 30,000 or 0, not NaN)
OptimizersAdam as torch.optim.Adam (bias-corrected moments, eps outside the square root), and SGD with optional momentum
Initial weightsGlorot (Xavier) uniform, limit sqrt(6 / (fan_in + fan_out)), the Keras default; SetInitializer(Initializer->KAIMING) for He uniform, limit sqrt(6 / fan_in). Biases start at 0. Drawn from the model seed with a portable generator, so a seed gives the same weights on every platform
Threadsthe batch is spread over a thread pool, default the hardware threads, at most 8 (CnnRuntime->SetThreads(n)). Work is split statically, so a run repeats bit for bit at a given thread count; different counts agree to rounding. The setting is process-wide (all models share one pool), and the default is the machine's hardware threads, so call CnnRuntime->SetThreads(n) with a fixed n when a result must be the same on another machine (the examples use 8)
Save / Loadweights only, in a small binary file with a digest of the architecture; Load is bit-exact and refuses a file from another architecture, a truncated file or a foreign one, leaving the model unchanged
Scopebinary classification (one logit per image). The default and the fallback is the CPU; an optional GPU backend (model->SetDevice("cuda"), below) implements the same layers. Layers are an interface over contiguous NCHW tensors (core/lib/matrix/cnn.h)

Nothing here ends the program on bad input: an empty batch, a Nil array, a wrong size, a model that is not compiled or a layer that does not fit answers false, -1.0, 0 or Nil, and GetError() gives the reason. A model holds native memory, so call Close() when done (twice is harmless; IsOpen() says whether the model is alive). GetError() returns "", never Nil, when nothing went wrong. A model is not thread-safe: one thread at a time.

Images. ImageDataset holds file paths (decoded and resized when a batch needs them, or kept with SetCache(true)) and in-memory pixels. AddDirectory takes the .jpg, .jpeg, .png and .bmp files of a folder in name order, so the same folder always gives the same indexes; Check() decodes every file once and counts the ones that fail. Split(train, validation, seed) deals three ImageSubsets by a seeded shuffle (the rest is the test set); when the data is already in folders, make one dataset per folder and use All(augment). Augmentation (Augmentation: flip, rotation by a random angle with bilinear interpolation, brightness factor) is applied as an image is staged for a batch and only on a subset made for training; whether each fires, and its value, is a function of the seed and the image's position in the epoch, so training repeats exactly. ImageDataset->Synthetic(size, per_class, seed) makes a procedural two-class set (low against high spatial frequency) for demos and tests with no files.

Loading speed. Decoding JPEGs used to run one image at a time on the calling thread, which for large sets cost more than the GPU training (140,000 256 x 256 JPEGs: 437 images/s). A batch is now decoded and resized on several native threads (libobjk_opencv; the Objeck class is API.OpenCV.ImageBatch), ImageDataset->SetThreads(n) sets how many (default 4, 1 to 64; separate from CnnRuntime->SetThreads, which sets the layers' threads), and CnnTrainer->SetPrefetch(true) (the default) decodes the next batch while the current one trains, in Fit and in Evaluate. The staging and the training stay on the calling thread, so the pixels, the training order and every loss are bit-identical to the one-thread, no-prefetch path whatever the settings (test ml_cnn_loader); only the time changes. Check() is parallel as well. For code that wants the batches itself, ImageDataset->Begin(indexes) and ImageSubset->Begin(order, start, count) start decoding and return a PendingImages whose Get(j) waits and returns the pixels of image j; Close() it when done. Memory: a decoded image is already kept as 8-bit pixels at the model size (224 x 224 x 3 = 150,528 bytes, 21 GB for 140,000 images with SetCache(true)), which is the least raw pixels can take, so no smaller cache is offered; with loading overlapped, leaving the cache off costs little and holds one extra batch instead. A disk-backed or memory-mapped cache was not added. Measured on the faces set (256 x 256 JPEGs decoded to 224 x 224, Ryzen 9 7950X3D, files in the OS cache, 10,000 images): the old path decoded 1,107 images/s (695 on a cold cache); the new one 1,253 with 1 thread, 2,432 with 2, 3,817 with 4, 5,236 with 8 and 6,131 with 16. An epoch of 20,000 images of the baseline model on the RTX 4090, no cache: 30 to 34 s before, 13.5 s with 4 decoding threads, 9.1 s with prefetch added (the GPU alone takes about 7.4 s); 8 threads with prefetch were no faster (9.5 to 11 s: the decoders compete with the layer threads). A 2-epoch seeded run on 2,000 images (losses, accuracies and a hash of every pixel) is bit-identical to the old code at 1 thread without prefetch and at 8 threads with prefetch.

Metrics. CnnTrainer->Fit(epochs) returns a TrainingHistory: per epoch the training loss and accuracy (running means over the epoch's batches in training mode, as Keras reports them), the validation loss and accuracy (evaluation mode, after the epoch) and the wall time; ToCsv(), SaveCsv(path) and ToResultTable(title) write it out, with the column names of the System.ML.Lab experiment tables (train_loss, train_accuracy, val_loss, val_accuracy, epoch_seconds). Evaluate(subset) returns a CnnEvaluation with loss, accuracy, precision, recall, F1 (System.ML.Metrics, class 1 positive, threshold 0.5) the confusion matrix, GetScores() (the class-1 probability of each image) with GetActuals() for Metrics->AucRoc and ROC curves, and ToResultTable(title). GetParameterCount() gives the parameter count: for a convolution filters x (channels x k x k) + filters, for a dense layer units x inputs + units. For the baseline at 224 x 224 that is 448 + 4,640 + 18,496 for the three convolutions, a flatten of 26 x 26 x 64 = 43,264 values, 128 x 43,264 + 128 = 5,537,920 for the hidden dense layer and 129 for the output: 5,561,633. The baseline takes CnnModel->Baseline(image_size, conv_blocks, dropout, dense_units, learning_rate, seed), so the experiments of the study (2, 3 or 4 blocks; dropout 0, 0.1, 0.3, 0.5; image size 64, 128, 224; learning rate 1e-3, 1e-4, 1e-5) are one-argument changes.

Complete runs. programs/examples/ml/cnn_synthetic.obs trains the baseline on a generated 64 x 64 set in seconds, with no data. programs/examples/ml/cnn_images.obs reads image folders (--data ROOT for the train/, valid/, test/ layout of the 140k Real and Fake Faces dataset, or --real DIR --fake DIR for a seeded split) and takes the study's settings as options: --blocks, --dropout, --lr, --size, --batch, --epochs and --augment. It prints the parameter count, one line per epoch and the test metrics, and writes the history to a CSV file.

How it was checked. Five regression tests (ml_cnn_*.obs) and a PyTorch reference.

Gradients. ml_cnn_gradcheck.obs compares backpropagation with central finite differences for every layer type, alone and stacked, and for a three-block network. The optional CUDA backend

The same model can run on an NVIDIA GPU. It is optional and is not shipped: Objeck's releases and CI build no CUDA code, libobjk_ml links nothing from CUDA and does not need it to load, and without the extra library every model simply stays on the CPU, which is the default. The GPU code is a separate shared library, libobjk_ml_cuda (core/lib/matrix/cuda/: the kernels and the cuBLAS calls in objk_ml_cuda.cu, the C interface in objk_ml_cuda.h), that libobjk_ml loads on demand with LoadLibrary / dlopen the first time a "cuda" device is asked for.

use System.ML.Cnn;

CnnRuntime->GetDevices()->PrintLine();      # "cpu", "cuda:0 NVIDIA GeForce RTX 4090 (24563 MB, compute capability 8.9)"
model := CnnModel->Baseline(224, 3, 0.1, 128, 0.0001, 42);
if(model->SetDevice("cuda")) {              # or "cuda:1"; "cpu" moves it back
  "on {$model->GetDevice()}"->PrintLine();
}
else {
  "staying on the CPU: {$model->GetError()}"->PrintLine();   # no library, no GPU, out of memory ...
};
trainer := CnnTrainer->New(model, train, validation, 64, 42);  # unchanged: the same trainer, history and metrics

CnnRuntime->HasCuda(), CudaDeviceCount(), CudaStatus() (why not), CudaFreeMemory(index) and GetDevices() describe what is there; CnnModel->SetDevice(name), GetDevice() and GetDeviceMemory() (the GPU bytes the model holds) place it. A refused SetDevice answers false, says why in GetError() and leaves the model where it was; nothing crashes. A model can move at any time and keeps its weights (the Adam moments restart from zero). Save and Load write the same bytes on both devices, so a model trained on the GPU loads on the CPU and the other way round. programs/examples/ml/cnn_images.obs takes --device cuda, and programs/examples/ml/cnn_speed.obs measures images per second.

What it needs. An NVIDIA GPU of compute capability 7.5 or newer (Turing and later) with a current driver, and the CUDA Toolkit 12.x or 13.x to build it (nvcc and cuBLAS; cuDNN is not used). At run time libobjk_ml_cuda needs cublas64_*.dll (Windows, found through CUDA_PATH) or libcublas.so (Linux, on the loader path).

Building it. By hand, never as part of the Objeck build:

The script builds machine code for compute capabilities 7.5 to 9.0 and 12.0 and PTX for newer GPUs (CUDA_ARCHS changes the list). Host compiler: CUDA 13.1 accepts only the Visual Studio 2019 and 2022 compilers (_MSC_VER below 1950) and refuses the v145 toolset of Visual Studio 2026 (unsupported Microsoft Visual Studio version). That IDE still installs the v143 toolset beside it, which is what build_cuda.cmd selects (vcvarsall.bat amd64 -vcvars_ver=14.4), so -allow-unsupported-compiler is not needed; VC_TOOLSET and VCVARSALL override the choice.

How it works. The model keeps its weights, activations and gradients on the GPU between layers; per batch only the images and labels go in and the loss and logits come out. Convolution is an im2col kernel and cublasSgemmStridedBatched (one matrix multiply per image, launched as a batch), its input gradient a batched multiply and a gather (col2im), its weight gradient a batched multiply into per-image partial sums that a kernel adds in a fixed order; dense layers are cublasSgemm; max pooling, ReLU, bias, dropout, the loss and the Adam and SGD updates are small CUDA kernels. Nothing uses atomic additions on floats, so a run repeats bit for bit on the same GPU and driver. Dropout draws the CPU engine's counter-based mask (same seed, same forward-pass counter, same element index, compared in double), so a given seed drops the same activations on both devices. Everything is full FP32: cuBLAS runs in its default math mode, which does not use Tensor Cores. SetDevice("cuda", true) allows TF32 instead; it was measured to change the logits by 2e-3 and the gradients by up to 7e-2 (relative to the largest entry) and to give no speed-up on this network (the matrix multiplies are not the bottleneck), so it is not recommended.

Memory. A model holds its parameters, gradients and optimizer state plus buffers for the largest batch it has seen: the baseline at 224 x 224 takes 1.1 GB at batch 32, 2.1 GB at 64, 4.2 GB at 128 and 8.2 GB at 256 (GetDeviceMemory()). A batch that does not fit answers -1.0 and "out of GPU memory: a batch of N needs about X MB and Y MB are free" and leaves the model usable with a smaller one. Close(), SetDevice("cpu") or the end of the program give the memory back; a model left open is released when the library unloads.

At larger sizes (cnn_parity.py --large --float64, ml_cnn_cuda_parity.obs <dir> large, not committed: megabytes) the baseline at 64 x 64 agrees with PyTorch to 8e-7 (gradients) and at 224 x 224 to 2.1e-6 (gradients) and 1.4e-7 (input gradient). Against a float32 PyTorch reference the 224 x 224 gradients differ by 2.9e-3 and the input gradient by 6e-2, for the CPU engine and the GPU alike: PyTorch's own float32 run differs from its float64 run by exactly that much (a ReLU input within rounding of zero flips sign with the summation order, and over 800,000 activations per image a few do), so the float64 reference is the one to compare with. In a 20-step Adam run at 64 x 64 the GPU follows PyTorch to 8e-5 per step and 5e-3 in the weights, and the CPU engine to 4.2e-3 and 3.9e-2: Adam amplifies the float32 noise of near-zero gradients, and it is the CPU engine's trajectory that drifts there (not investigated further; it does not depend on the thread count).

Experimental: API may change. System.ML.TimeSeries forecasts one numeric series with a prediction interval around every forecast: benchmark forecasters, exponential smoothing (simple, Holt, damped Holt, Holt-Winters), ARIMA with optional seasonal differencing, automatic selection, and rolling-origin evaluation. Limits:

  • One series, evenly spaced. There are no exogenous regressors and no multivariate models; timestamps are kept but the models treat observations as equally spaced.
  • Exponential smoothing is the additive-error family: no multiplicative trend, no multiplicative-error models. The initial states come from a fixed rule, so the fit is not the exact state-space maximum likelihood, and the multiplicative-season interval is an approximation.
  • ARIMA is conditional least squares, not exact maximum likelihood. The seasonal part is differencing only (no seasonal AR or MA terms, so the common "airline" model is not available); check residuals with Acf->LjungBox. Intervals do not include coefficient uncertainty.
  • Stationarity. Adf gives a statistic and critical values but no p-value, and there is no KPSS test. SuggestDiff is a heuristic for a first guess.
  • Results are deterministic on a platform; across platforms compare with a tolerance, not for equality.

Conventions worth knowing. The mean difference is the first group minus the second, and the confidence interval is for that difference (for a one-sample test, mean minus the hypothesised mean). Cohen's d divides by the pooled standard deviation (one-sample: the sample's; paired: that of the differences), and Hedges' g multiplies it by the exact correction Gamma(df/2) / (sqrt(df/2) * Gamma((df-1)/2)) (Dist->HedgesJ, about 1 - 3 / (4 df - 1)); the Welch test reports the same pooled-sd d and g as the Student test. A regression with an intercept uses the centred total sum of squares and tests against the intercept-only model; without one it uses the uncentred sum and df_model = k, as statsmodels does, and AIC and BIC count one parameter per coefficient, also as statsmodels does. Put every level of a categorical variable beside an intercept and the fit is refused as rank deficient (the dummy trap); Design->Dummies drops the first level for that reason.

The p-values come from the regularized incomplete beta function (continued fraction, Lentz), so they stay accurate in the far tail (p = 7e-18 is 7e-18, not 0) and for large degrees of freedom. Every distribution function is tested against scipy at small and large df.

# perfect play with alpha-beta pruning
searcher := Minimax->New(9);            # depth limit
best := searcher->FindBestMove(state);

# Monte Carlo tree search for bigger branching factors
mcts := MonteCarloTreeSearch->New(2000, 1.414, 7);  # playouts, UCB1 c, seed
best := mcts->FindBestMove(state);

Optimization

# genetic algorithm over Bool[] chromosomes: implement FitnessFunction
class OneMax implements FitnessFunction {
  New() {}
  method : public : Fitness(genes : Bool[]) ~ Float {
    count := 0;
    each(i : genes) { if(genes[i]) { count += 1; }; };
    return count->As(Float);
  }
}

ga := GeneticAlgorithm->New(40, 24, 0.02, 0.9, 7);  # pop, genes, mutate, cross, seed
best := ga->Run(OneMax->New(), 80);
"fitness: {$ga->GetBestFitness()}"->PrintLine();    # 24.0

# simulated annealing / hill climbing over Float[] states: implement EnergyFunction
sa := SimulatedAnnealing->New(10.0, 0.995, 0.5, 7); # temp, cooling, step, seed
best := sa->Run(energy, [-8.0, 9.0], 4000);

hc := HillClimbing->New(0.5, 50, 5.0, 7);           # step, patience, restart range, seed
best := hc->Run(energy, start, 3000);

Reinforcement Learning

Implement the Environment interface (GetNumStates, GetNumActions, Reset, Step), then train:

agent := QLearning->New(0.2, 0.95, 0.2, 7);  # alpha, gamma, epsilon, seed
agent->Train(env, 400, 60);                  # episodes, max steps
best := agent->BestAction(state);

# on-policy variant
sarsa := Sarsa->New(0.2, 0.95, 0.2, 7);
sarsa->Train(env, 400, 60);

# explicit MDP solved by value iteration
mdp := MarkovDecisionProcess->New(6, 2);     # states, actions
mdp->AddTransition(0, 1, 1, 1.0, -1.0);      # state, action, next, prob, reward
mdp->AddTransition(4, 1, 5, 1.0, 10.0);
mdp->Solve(0.95, 0.000001, 1000);            # gamma, tolerance, max iterations
policy := mdp->GetPolicy();
values := mdp->GetValues();

A group must be closed under dependencies — the linker loads exactly what the group lists and does not chase a member's own dependencies, so a group that omits one fails on every use, even from a program that never touches it.

An unknown alias names the config file and lists the groups it does define. An unresolvable class names the library that would supply it:
