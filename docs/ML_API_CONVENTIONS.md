# ML API conventions: a review of System.ML, System.Stats, System.NLP, System.NLP.Topics and System.ML.Cnn

**Status: a review and a set of proposals (2026-11-19).** Nothing here changes behaviour and no library was edited to write it. The first half records what the five library areas do today, with class and method names; the second half proposes conventions, a few small interfaces, a results-aggregation helper and a report builder, and an ordered plan of pull requests. Every proposal is marked as one: a signature in a "proposed" block does not exist in any branch.

Questions this page answers: do the libraries report failure, name their methods, take seeds and move data in the same way; can a user write a pipeline, a cross-validation helper or a parameter sweep once for all of them; what is missing between a CSV of reviews and a single hand-in file with tables and figures; where does a user add a metric, a tokenizer, a layer or a coherence measure.

## Summary

What the libraries already get right, and should be kept:

- **No new library raises.** `System.Stats`, the NLP additions, `System.NLP.Topics` and `System.ML.Cnn` contain no `Runtime->Raise`; every one documents "nothing here ends the program on bad input". `System.ML.Lab` and `System.Plot` raise a `System.Error` subclass (`LabError`, `PlotError`) for a caller's mistake, which is the split [ERROR_CONVENTIONS.md](ERROR_CONVENTIONS.md) already proposes.
- **Seeds are real.** Every stochastic class in the four new areas takes one (`Lda`, `CnnModel`, `CnnTrainer`, `ImageDataset->Split`, `Augmentation->SetSeed`), documents that the same seed gives the same result on every platform, and most of the existing ML classes do the same through `System.ML.Random` (the exceptions are F20).
- **The pieces compose where someone designed them to.** `Axes->RocCurve` takes what `Metrics->RocCurve` returns; `Axes->ConfusionMatrix` takes the `Int[,]` that `Metrics->ConfusionMatrix` and `CnnEvaluation->GetConfusion` return; `TrainingHistory->ToResultTable` puts a CNN's epochs into a Lab `ResultTable`; `BertEmbedder->Embed` returns the `Float[,]` that `EmbeddingClassifier->Fit` and `ScoreModel` consume; `TopicPlots` draws onto `System.Plot`'s `PlotScene`.
- **Reference values come from independent code.** The new regression tests compare against numbers generated by a script (`tools/stats/gen_stats_reference.py`, `programs/regression/data/nlp/gen_tfidf_expected.py`, `programs/regression/nlp_topics_reference.py`, `tools/ml/cnn_parity.py`), not numbers copied from the library's own output. Keep that.
- **Names are free of collisions.** No new top-level class short name duplicates an existing one (section "Short names"), and the doc-comment fence check passes on all eight new or changed source files (it was run on them for this review).

What should change, in the order a student writing the hand-in would hit it (the full list, with files, is the findings table):

1. `ResultTable->ToJson()` writes `nan` for a NaN cell, which is not JSON, and `System.Stats` produces NaN by design. Verified by running it. (F1)
2. `System.ML.Lab`'s `Experiment` can only sweep a binary classifier and only reports eight fixed metrics, so none of the new areas (OLS, t-tests, BERT heads, CNNs, LDA) can use it; the LDA example builds its five tables by hand and reports "best of 4 seeds" instead of mean and standard deviation over seeds. (F12)
3. There is no way to turn tables and figures into one hand-in file; `ResultTable->ToMarkdown()` and `Chart->ToSvg()` are the only pieces. (section "Experiments and reporting")
4. "No error" is `""` in 21 `GetError()` declarations and `Nil` in 8, and calling `->Size()` on the `Nil` ends the program (verified). Most `System.ML` classifiers have no `GetError()` at all. (F2, F3)
5. Text becomes numbers one string at a time (`TextFeatures->Extract`, `TF_IDF->Transform`), so every study writes the same double loop to build a `Float[,]`; several outputs are flat `Float[]`; labels travel as `Bool[]`, `Float[]` and `Float[,]`. (F5, F8, F9)
6. `TF_IDF` with an invalid setting fits an empty vocabulary without a word (verified), and its dense output costs 8 bytes times vocabulary per document. (F7)
7. A fitted `FeatureScaler`, `TableEncoder`, `DenseNetwork` or `EmbeddingClassifier` cannot be stored, and the classes that can use three verbs (`Store`, `Save`, instance `Load`). (F10, F11)
8. Reproducibility holes: `Matrix2D->Random`, `RandomNormal`, `CrossValidation->KFold` and `TrainTestSplit` are unseeded, and a CNN's result depends on the thread count, whose default depends on the machine. (F18, F20)

## Recommended conventions

Each convention is a rule, why, and a short example. The examples marked "compiled" were compiled and run against the libraries named in the check section; the rest are proposals.

### C1. One failure channel per layer

| Situation | Channel | Today |
|---|---|---|
| An estimator, vectorizer, reader or native model is given input or settings it cannot use | the call returns its failure value (`false`, `Nil`) and the object keeps the reason, read with `GetError()` | `System.ML` ([AI.md](AI.md), "Bad input"), `System.ML.Cnn`, `System.NLP.Topics`, `TF_IDF`, `BertEmbedder` |
| A scalar that has no value (a statistic of too few observations) | `NaN`; never a number in the valid range, so never `0.0` | `System.Stats`, `Lda->LogPerplexityBound` |
| A compound statistic (a test, a fit, a correlation) | a result object whose `IsValid()` is false and whose `GetError()` says why, with NaN numbers inside | `TTestResult`, `CorrelationResult`, `OLSResult` |
| The orchestration layer is called wrongly (an empty sweep, a trial that returns `Nil`, an axes with nothing to draw) | `Runtime->Raise` of a `System.Error` subclass named for the library | `LabError`, `PlotError` |

**Why.** This is the split that already exists, so adopting it changes nothing for users. Rule 2 of [ERROR_CONVENTIONS.md](ERROR_CONVENTIONS.md) (raise for a broken precondition, return for an expected failure) answers its open question "should `ml` raise like `ml_lab`": the model layer returns, because a sweep over a thousand fits must survive one refused fit, and the orchestration layer raises, because a sweep cannot continue past its own misuse. A library function never does both for the same condition. A new scalar-valued function returns NaN, not `-1.0`, unless an existing interface already fixes the sentinel (`ScoreMetric` requires a negative value; keep that).

```ruby
fit := OLS->Fit(X, y, true);            # compiled
if(<>fit->IsValid()) {
  "no fit: {$fit->GetError()}"->ErrorLine();
  return;
};
p := fit->GetPValues();
```

### C2. `GetError()` returns an empty string, never `Nil`; one boolean says whether to ask

**Rule.** `GetError() ~ String` returns `""` when there is nothing to report. The object also answers one boolean: `IsValid()` for "the configuration or result is usable", `IsFitted()` for "`Fit` succeeded", `IsOpen()` for "the native handle is live". Do not add a new spelling (`IsOk`, `IsLoaded`, `GetLastError`).

**Why.** By a count of the declarations, `""` is the contract of 21 of them (`DenseNetwork`, `VectorIndex`, the `OutlierDetector` interface and its classes, the three `System.Stats` result classes, five in `System.ML.Cnn`, three in `System.NLP.Topics`) and `Nil` of 8 (`TF_IDF`, `SpellChecker`, `WordPieceTokenizer`, `SubwordTokenizer`, `BpeTokenizer`, `BertEmbedder`, `TextClassifier`, `EmbeddingClassifier`). `GetError()->Size()` on a `Nil` string stops the program with "Attempting to dereference a 'Nil' memory instance" (verified), so the `Nil` convention turns the diagnostic into a crash for the one caller who chains it. This disagrees with the proposed rule 1 of [ERROR_CONVENTIONS.md](ERROR_CONVENTIONS.md), which says `Nil`: that proposal was written for the process-wide `GetLastError()` of the LLM clients and is unadopted; the recommendation here is to amend it to "`""` for instance errors in the ML family". It is the maintainer's call.

```ruby
err := model->GetError();               # compiled: "" when fine, so this never dereferences Nil
if(err->Size() > 0) {
  err->ErrorLine();
};
```

### C3. One shape for an estimator

| Verb | Signature | Notes |
|---|---|---|
| fit | `Fit(X : Float[,], y : Bool[]) ~ Bool` for a binary classifier (this is `ScoreModel`), `Fit(X : Float[,]) ~ Bool` for an unsupervised model or transformer | returns `false` and sets `GetError()`; a refused refit leaves the old model, as [AI.md](AI.md) already documents |
| score | `PredictScore(X) ~ Float[]` higher means more positive | the only method the lab's ROC, AUC and bootstrap need |
| class | `PredictClass(X) ~ Bool[]` | |
| value | `PredictValues(X) ~ Float[]` (proposed name) for a regressor | `Predict` keeps its released meaning |
| transform | `Transform(X) ~ Float[,]`, `FitTransform(X) ~ Float[,]` | `Nil` when unfitted or the width differs |
| state | `IsFitted() ~ Bool`, `GetError() ~ String` | |
| persist | `Store(path) ~ Bool`, `function : Load(path) ~ T` | see C7 |

**Why.** The shape exists, but `Predict` is the one name whose result type changes with the class: `Float[,]` for `LinearRegression`, `RidgeRegression`, `ElasticNet`, `DenseNetwork`, `GaussianNaiveBayes`; `Float[]` for `LogisticRegression` (probabilities), `Perceptron`, `SVM`; `Bool[]` for the forest, tree and boosted classifiers and every outlier detector; `Int[]` for `OneClassSVM`; one `Float` for a tree row. A pipeline or a cross-validation helper written against `Predict` cannot exist. `PredictScore` and `PredictClass` are already consistent (with the exceptions listed in F4), so new code and interfaces should be written against them and leave `Predict` alone.

### C4. Rows are samples; name the type of every label

**Rule.** A feature matrix is `Float[,]`, rows are samples. Binary labels are `Bool[]` (true is the positive class, the lab's convention). A continuous target is `Float[]`. `Float[,]` of one column is accepted only where it is the released signature. Flat `Float[]` is for images and native buffers, and any method that returns one says its layout in the first sentence and has a reshape helper.

**Why.** The same label travels as `Bool[]` (every `ScoreModel`, `EmbeddingClassifier`, `DataSplit`), `Float[,]` (`LinearRegression`, `DenseNetwork`, `LogisticRegression`'s first `Fit`), `Float[]` (`OLS->Fit`, `CnnModel->TrainBatch`, `Labels->ToIndices`) and `Int[]`. Conversions exist in one direction each (`Design->Column` makes a `Float[]` into a one-column matrix, `Matrix2D->GetColumn` the reverse, `CrossValidation->ToBool` and `ToFloat`); there is none for `Bool[]` to `Float[,]`, none for rows into a matrix, and none for a flat array into a matrix (section "Data flow").

### C5. Every stochastic class takes a seed, last, and documents what it guarantees

**Rule.** A class that shuffles, samples, initializes weights or restarts takes `seed : Int` as the last constructor (or method) argument and uses a local generator (`System.ML.Random`, or a documented native one), never `Float->Random()`. The class comment says three things: that the same seed gives the same result on every platform, what else it depends on (thread count, backend), and what a seed of 0 or below means (`System.ML.Random->New` maps it to a valid state).

**Why.** Four of the five new areas already do this; the exceptions are in `System.ML` (F20) and in the CNN's thread-count dependence (F18). "Same seed, same table" is what makes a hand-in reproducible, and what the regression tests assert.

```ruby
m := Lda->New(10, 0.1, 0.01, 10, 50, 42);        # num_topics, alpha, eta, passes, iterations, seed
c := CnnModel->New(3, 64, 64, 42);               # channels, height, width, seed
r := RandomForestClassifier->New(100, 8, 2, 42); # trees, depth, min_samples, seed
```

### C6. Configure with constructor arguments and named defaults; setters only for tuning, and they say whether they refused

**Rule.** Required hyper-parameters are constructor arguments. Optional ones use defaulted parameters, which callers name (`TF_IDF->New(min_n : 1, max_n : 2)`), so no builder class is needed. A setter that validates returns `Bool` (`Lda->SetAlphaMode`, `CnnModel->SetLearningRate`); a constructor never refuses by crashing, it records the reason that the first `Fit` or `IsValid()` reports (`Lda`, `TF_IDF`, `CnnModel`). Every default is stated in the doc comment of the parameter.

**Why.** Named arguments cross the `.obl` boundary ([NAMED_ARGUMENTS_DESIGN.md](NAMED_ARGUMENTS_DESIGN.md)) and `TF_IDF` already uses them, so the alternative of an overload per combination (`KernelSVM` has four constructors, `RandomForestClassifier` two) is no longer needed for new classes. Setters currently disagree on their result: `Augmentation->SetFlip`, `EmbeddingClassifier->SetL2` and `BertEmbedder->SetBatchSize` return `Nil` and cannot say that a value was clamped or refused, `Lda->SetAlphaMode` and `TextClassifier->SetMaxLength` return `Bool` (F22).

### C7. `Store` and `Load` for models, `Save` for artifacts

**Rule.** A model or fitted transformer has `method : public : Store(path : String) ~ Bool` and `function : Load(path : String) ~ T` (a factory that returns `Nil` on failure, with the reason in a static or in the returned object's `GetError()` where it can be made). `Save(path)` is for writing something a person will open: a table, a chart, an SVG, a CSV of history. Anything a pipeline needs at predict time must be storable: a scaler, an encoder and a vectorizer are part of the model.

**Why.** `Store`/`Load` is the verb of 15 classes in `System.ML` and of `VectorIndex`. `Lda` and `ApiSequenceTokenizer` use `Save` for a model, and `CnnModel` has `Save(path)` and an instance `Load(path) ~ Bool`, so one program uses three shapes. `FeatureScaler`, `TableEncoder`, `DenseNetwork`, `EmbeddingClassifier` and `TF_IDF` have no persistence at all, which means a stored `LogisticRegression` cannot be used on new data without refitting a scaler on training data that is no longer there (F11). Adding the missing `Store` aliases is additive.

### C8. A native-backed object has `Close()`, `IsOpen()` and a thread-safety sentence

**Rule.** An object that owns native memory or a session has `Close() ~ Nil` that is safe to call twice, a boolean (`IsOpen()` is the existing word for sessions and embedders) and, in its class comment, one of "not thread-safe: one thread at a time per object" or "read-only after construction, safe to share". An accelerator-capable class has `IsCpuFallback()`, which `BertEmbedder` and `TextClassifier` already have.

**Why.** `Close()` is already the verb of `Session`, `BertEmbedder`, `TextClassifier` and `CnnModel`, but nothing makes them uniform: `CnnModel` calls its liveness `IsValid()`, the embedder `IsOpen()`. There is no finalizer, so a `CnnModel` that is not closed keeps its native memory until the process exits; `CnnModel->Baseline` closes a model it refuses to return, which is the pattern to copy. Only `VectorIndex`, `CnnModel` and `Lda` say anything about threads; `CnnRuntime->SetThreads` is process-wide, so two models trained from two Objeck threads share one pool. The rest (the `System.ML` models, `ResultTable`, `Experiment`, `TF_IDF`, `BertEmbedder`, `Session`) are silent, and a `Predict` that records a refusal in the object (`@error`) is not safe to share even when its arithmetic is.

### C9. Reportable results expose a `ResultTable`; units are in the name

**Rule.** Anything a person will want in a hand-in has `ToResultTable()`, or an adapter does (section "Proposed APIs"). Column names are snake_case with the unit as a suffix (`fit_ms`, `epoch_seconds`), a proportion is a fraction in 0 to 1 and never a percent, and a column that means the same thing has the same name everywhere (`train_accuracy`, `test_accuracy`, `val_accuracy`).

**Why.** `Experiment` writes `train_accuracy`, `test_accuracy`, `fit_ms`; `TrainingHistory->ToResultTable` writes `train_acc`, `val_acc`, `seconds`; a chart built from both has to rename. `FilterReport->GetTokensRemovedPercent` is the one percent in a library of fractions, and it is documented as such (F23).

### C10. Extension points are flat interfaces

**Rule.** A thing users will plug in is an interface with the smallest method set that lets the library run it (the precedent is `ScoreModel`, `ScoreMetric`, `Trial`, `OutlierDetector`, `SubwordTokenizer`), and a class may implement several. Do not use `FuncRef` in a library signature.

**Why, and the language limits found by compiling them:** an interface cannot extend another (`interface B from A` is a syntax error), an interface cannot be generic (`interface Xform<T>` is a syntax error), and a class can implement several interfaces that share a method signature (verified, and `ml_lab.obs` gives the same reasoning against `FuncRef`: it crosses the library boundary and reads clearly in a write-up). So the interfaces in "Proposed APIs" are small, flat and typed on `Float[,]` or `String[]`, one family per input type, and `implements A, B` composes them.

### C11. Naming, documentation, tests and registration

- A class short name is unique across `core/compiler/lib_src` (the compiler resolves generic arguments such as `Vector<Tool>` by short name, and `Tool` is defined by `anthropic`, `ollama` and `openai`; `Proxy` and `TreeNode` are the standing exceptions, section "Short names").
- A doc comment follows `description`, `@param`, `@return`, then at most one fenced example last (`tools/cicd/check_doc_fences.py` fails otherwise, because the API reference silently drops the member). `@return` names the failure value and where the reason is read, the way `Ollama`'s and `EmbeddingClassifier`'s do.
- A class that can fail says "nothing here ends the program" or says what it raises, in its first paragraph.
- A regression test is `programs/regression/<library>_<topic>.obs` with an `# EXTRA_LIBS:` line, contains a `Runtime->Exit(` on its failure path (`check_test_exit_codes.py`), and compares against values from an independent script that is committed beside it.
- A new library is registered in the lists [ML_LAB_SUPPORT_DESIGN.md](ML_LAB_SUPPORT_DESIGN.md) enumerates, plus the alias group and the playground map; the cookbook has the full list.

### C12. A method that measures time names its unit

`Stopwatch->GetElapsedMs()` and `GetElapsedSeconds()`, `Lda->GetTrainSeconds()`, `TrainingHistory->GetEpochSeconds()`, `TrialResult->GetFitMs()` follow this already. Keep it; do not add a method called `GetTime`.

## Findings

Severity: **breaking** means a user gets a wrong, lost or crashing result; **confusing** means the user has to learn a special case; **cosmetic** means naming or duplication. "Compatible" means source-compatible for released code: an added method or `implements` clause, or a change to a value that was invalid before. A branch marked "open PR" has no released API to break, so the fix is free there and cheaper to make before the merge than after.

## Data flow between the libraries

A study is CSV, then text features, then a matrix, then a model, then metrics, then tables and plots. This is what each hop takes and gives today:

| Hop | From | To | What exists | What is missing |
|---|---|---|---|---|
| CSV to text | `CsvTable` | `String[]` | `Labels->Column(table, "text")` | nothing |
| CSV to labels | `CsvTable` | `Bool[]` | `Labels->ToBinary(values, positive)`, `ToBinaryExcept` | nothing |
| text to hand features | `String` | `Float[]` | `TextFeatures->Extract(text)`, `Names()` | `ExtractAll(String[]) ~ Float[,]`; the misspelling rate (F8, F28) |
| text to TF-IDF | `String` | `Float[]` (dense, vocabulary-wide) | `TF_IDF->Fit(String[])`, `Transform(String)` | `TransformAll`, `FitTransform`, a sparse form for large vocabularies (F7) |
| text to BERT | `String[]` | `Float[,]` | `BertEmbedder->Embed(String[])`, `SetPooling`, `SetLayers` | nothing; this is the model of the right shape |
| text to topics | `Vector<String>` per document | `TopicCorpus` | `TopicTokenizer`, `TokenDictionary->ToCorpus` | feed `Lda` doc-topic mixtures to a classifier: `GetDocumentTopicMatrix` is flat (F9) |
| image to CNN | file or `Byte[]` | `ImageSubset` | `ImageDataset->AddDirectory`, `Split`, `CnnTrainer->Fit` | scores out of `Evaluate` (F27) |
| matrix to estimator | `Float[,]` | model | `LinearRegression`, `LogisticRegression`, `EmbeddingClassifier`, `RandomForestClassifier`, `DenseNetwork`, `OLS` | one label type (C4); `DenseNetwork` needs a one-hot `Float[,]` and there is no one-hot helper |
| split | `Float[,]`, `Bool[]` | `DataSplit` | `Partition->TrainTest(X, y, fraction, seed, stratify)` | a split of raw `String[]` texts, so a vectorizer can be fitted on the training texts only |
| model to metrics | scores, labels | numbers | `Metrics`, `ConfusionMatrix`, `Metrics->Bootstrap(ScoreMetric, ...)` | regression metrics (RMSE and R-squared are on the model, not in `Metrics`) |
| numbers to tests | `Float[]` | `TTestResult`, `OLSResult` | `TTest->Welch`, `Paired`, `OLS->Fit`, `Design->Dummies` | adapters into a `ResultTable` |
| numbers to table | rows | `ResultTable` | `AddColumn`, `AddRow(name, value, cells, stds)`, `ToMarkdown`, `ToCsv`, `ToJson` | NaN handling (F1), the adapters |
| table to figure | `ResultTable` | SVG | `ToChart(metrics)`, `Chart->Save`, `Axes`, `Figure->Save`, `TopicPlots->SaveReport` | one file with all of them |

How the types are converted today, and the glue that is missing:

| Needed | Today | Proposal |
|---|---|---|
| `Float[]` to a one-column `Float[,]` | `Design->Column(v)` (`System.Stats`), so a `System.ML` program links `stats` for it | `Matrix2D->FromColumn` in `System.ML` |
| `Bool[]` to `Float[]` / `Float[,]` | `CrossValidation->ToFloat(labels)`, then `Design->Column` | `Labels->ToMatrix(Bool[])` |
| class indices to one-hot | none | `Labels->OneHot(Float[] indices, Int classes) ~ Float[,]` |
| rows (`Float[]` each) to `Float[,]` | a hand loop | `Matrix2D->FromRows(Vector<FloatArrayRef>)` |
| flat `Float[]` to `Float[,]` | a hand loop | `Matrix2D->Reshape(flat, rows, cols)` |
| `Vector<Float>` (`FloatVector`) to `Float[]` | `FloatVector->ToArray()` | none needed |
| `FloatMatrixRef` | only `NeuralNetwork`, the legacy network, takes `Vector<FloatMatrixRef>` | leave; new code never takes it |

## Experiments and reporting

What exists in `System.ML.Lab`: `Partition->TrainTest` (stratified, seeded), `Resample->ToPositiveRatio`, `Stopwatch`, `Labels`, `Experiment` with `SetValues`, `SetSeeds`, `AddSetting` and `Run(Trial)`, `ResultTable` (text, Markdown, CSV, JSON, `ToChart`), `Chart` (lines, bars, error bars, log x, `LossCurve`). "Change one parameter at a time, same split, same seeds, repeat over seeds, mean and standard deviation" is already a few lines for a **binary classifier**:

```ruby
# the Trial interface, from ml_lab.obs
class ForestTrial implements Trial {
  @split : DataSplit;
  New(split : DataSplit) { @split := split; }
  method : public : Run(value : Float, name : String, seed : Int) ~ TrialResult {
    forest := RandomForestClassifier->New(value->As(Int), 8, 2, seed);
    sw := Stopwatch->New();
    sw->Start();
    forest->Fit(@split->GetTrainX(), @split->GetTrainY());
    ms := sw->Stop();
    return TrialResult->New(forest->Predict(@split->GetTrainX()), @split->GetTrainY(),
      forest->Predict(@split->GetTestX()), @split->GetTestY(), ms);
  }
}
exp := Experiment->New("Random forest: trees", "n_estimators");
exp->SetValues([10.0, 50.0, 100.0]);
exp->SetSeeds([1, 2, 3]);
exp->Run(ForestTrial->New(split))->ToMarkdown()->PrintLine();
```

What does not fit:

- **Only binary labels and eight fixed columns.** `TrialResult` carries `Bool[]` predictions, and `Experiment->Measure` computes `train_accuracy`, `test_accuracy`, `precision`, `recall`, `f1`, `fpr`, `false_negatives`, `fit_ms` and nothing else. An OLS sweep (R-squared, AIC), a BERT head with AUC, a CNN with epochs, an LDA with coherence and perplexity (the example's five experiments) cannot say what they measure.
- **No raw per-seed rows.** The table keeps the mean and the standard deviation; a paired test between two settings (`TTest->Paired`) needs the per-seed values, which are discarded.
- **No confidence interval and no count.** A mean of five seeds with one NaN is a mean of four, and the table does not say so (F31).
- **Nothing builds the hand-in file.** A student pastes `ToMarkdown()` output and `Chart->Save` SVGs into a Word document by hand.

I checked what exists first: no class named `Report`, `Pipeline`, `Aggregate` or `Summary` exists in any library or index (the names are free), no HTML or Markdown document builder, and no PDF or DOCX writer. Objeck can compress (`Byte->CompressZlib`) but has no ZIP container writer, so a `.docx` is out of reach for a library this month; a self-contained HTML file with inline SVG, printed to PDF by a browser, is within reach.

The proposal is two small additions, and it deliberately does not touch `Experiment->Run`:

1. In `ml_lab` (additive): a `MetricTrial` interface and `Experiment->RunMetrics`, so a sweep can name its own columns and return any numbers, with the same seed loop and the same mean and standard deviation.
2. In a new bridge library `ml_report.obl` (bundle `System.ML.Report`, linking `ml_lab`, `stats`, `json`): `Replicates` (per-seed values with mean, standard deviation, count and t-interval from `System.Stats`), adapters that turn `OLSResult`, `TTestResult` and `TrainingHistory` into a `ResultTable`, and `Report`, a builder that writes Markdown (figures as separate SVG files) and HTML (one file, inline SVG, print stylesheet). A bridge library, not a change to `ml_lab`, because a library's link list is inherited by every program that links it (the reason `ml_lab` is separate from `ml`, in [ML_LAB_SUPPORT_DESIGN.md](ML_LAB_SUPPORT_DESIGN.md)): putting `stats` into `ml_lab` would make every lab program add `-lib stats`.

The aggregation half runs today as user code. This was compiled and run against the branch `System.Stats` and master `System.ML`; the output is the table it prints:

```ruby
# compiled and run: per-seed values in, mean, standard deviation and a t-interval out
class Replicates {
  @columns : String[];
  @rows : Vector<FloatArrayRef>;
  New(columns : String[]) { @columns := columns; @rows := Vector->New()<FloatArrayRef>; }
  method : public : Add(values : Float[]) ~ Nil { @rows->AddBack(FloatArrayRef->New(values)); }
  method : public : Column(c : Int) ~ Float[] {
    out := Float->New[@rows->Size()];
    each(r : out) { out[r] := @rows->Get(r)->Get()[c]; };
    return out;
  }
  method : public : GetCi(c : Int, level : Float) ~ Float[] {
    t := TTest->OneSample(Column(c), 0.0, level);        # the interval of the mean
    return t->IsValid() ? [t->GetCiLow(), t->GetCiHigh()] : [Float->NaN(), Float->NaN()];
  }
}
# per seed: split, fit, time, score, then reps->Add([auc, fit_ms]); five seeds give
#   | setting   | auc             | fit_ms          |
#   | all seeds | 0.9582 ± 0.0235 | 0.9266 ± 0.1862 |
```

For the hand-in, `Report` is a string builder over what already exists: a `ResultTable` has `ToMarkdown()`, and a `Figure`, a `Chart` and `TopicPlots->ReportSvg` all give an SVG string. Whether Microsoft Word imports an HTML page with inline SVG was not tested; the safe routes are a browser's print to PDF, or Markdown converted by an external tool, and PNG figures through `System.Plot`'s SDL backend (`@plot`) for a document editor that does not take SVG.

## Proposed APIs

Every block below is a proposal; none of these classes exists. Where an `implements` is proposed for a class on `master`, the methods it needs are named, and an adapter class written in user code works today (the pipeline below was compiled with adapters).

### Interfaces

Flat, non-generic, no inheritance (the language limits of C10). `ScoreModel` already exists and stays the binary-classifier interface; a class implements it and `Classifier` together.

```ruby
# proposed: bundle System.ML (ml_data.obs)
interface Transformer {
  method : virtual : public : Fit(X : Float[,]) ~ Bool;
  method : virtual : public : Transform(X : Float[,]) ~ Float[,];
  method : virtual : public : IsFitted() ~ Bool;
  method : virtual : public : GetError() ~ String;
}
interface Classifier {                      # beside ScoreModel: class X implements ScoreModel, Classifier
  method : virtual : public : PredictClass(X : Float[,]) ~ Bool[];
  method : virtual : public : IsFitted() ~ Bool;
  method : virtual : public : GetError() ~ String;
}
interface Regressor {
  method : virtual : public : Fit(X : Float[,], y : Float[]) ~ Bool;
  method : virtual : public : PredictValues(X : Float[,]) ~ Float[];
  method : virtual : public : IsFitted() ~ Bool;
  method : virtual : public : GetError() ~ String;
}

# proposed: bundle System.NLP (nlp.obs), so TF_IDF and BertEmbedder (which links nlp) can implement them
interface TextTransformer {
  method : virtual : public : Fit(texts : String[]) ~ Bool;
  method : virtual : public : Transform(texts : String[]) ~ Float[,];

```

Who would implement what, and the exact additions each needs (all additive):

| Interface | Implementers | Additions needed |
|---|---|---|
| `Transformer` | `FeatureScaler`, `PCA` | `GetError()` on both (F3) |
| `Classifier` | `LogisticRegression`, `KernelSVM`, `EmbeddingClassifier`, the three tree classes | `PredictClass` on the trees (F5), `GetError()` on all but `EmbeddingClassifier` |
| `Regressor` | `LinearRegression`, `RidgeRegression`, `ElasticNet`, `RegressionTree`, `GradientBoostedTrees` | `Fit(X, y : Float[])` and `PredictValues` (the released `Float[,]` forms stay) |

With these, a pipeline and a fold-safe cross-validation are written once. This was compiled and run, with `ScalerStage` and `TfidfStage` as the adapters that stand in for the `implements` clauses:

```ruby
# compiled and run
class TextPipeline {
  @stage : TextTransformer;
  @model : ScoreModel;
  New(stage : TextTransformer, model : ScoreModel) { @stage := stage; @model := model; }
  method : public : Fit(texts : String[], y : Bool[]) ~ Bool {
    if(<>@stage->Fit(texts)) { return false; };       # fitted on these texts only: no leak across folds
    return @model->Fit(@stage->Transform(texts), y);
  }
  method : public : PredictScore(texts : String[]) ~ Float[] {
    return @model->PredictScore(@stage->Transform(texts));
  }
}
p := TextPipeline->New(TfidfStage->New(TF_IDF->New()), LogisticRegression->New(0.5, 300));
p->Fit(texts, y);
ci := Metrics->Bootstrap(BalancedAccuracyMetric->New(), p->PredictScore(texts), y, 50, 7);
```

`CrossValidation->Evaluate(ScoreModel, X, y, k, seed, ...)` already fits a scaler inside each fold (its `standardize` argument); a vectorizer needs the same treatment, which is what `TextPipeline` gives, and the reason it is worth having before the study that computes IDF on all reviews and then cross-validates.

## Cookbook: how to add a new X

Each recipe says what a user can do without editing a library, and what a library change needs. Verified code is marked.

### A metric

Three kinds.

- **A resampleable metric over scores** (works with `Metrics->Bootstrap`): implement `ScoreMetric`. Return a negative number when the sample cannot support it. Compiled:

```ruby
class BalancedAccuracyMetric implements ScoreMetric {
  New() {}
  method : public : Compute(scores : Float[], actuals : Bool[]) ~ Float {
    tp := 0; fn := 0; tn := 0; fp := 0;
    each(i : scores) {
      if(actuals[i]) { if(scores[i] > 0.5) { tp += 1; } else { fn += 1; }; }
      else { if(scores[i] > 0.5) { fp += 1; } else { tn += 1; }; };
    };
    if(tp + fn = 0 | tn + fp = 0) { return -1.0; };
    return (tp->As(Float) / (tp + fn)->As(Float) + tn->As(Float) / (tn + fp)->As(Float)) / 2.0;
  }
}
ci := Metrics->Bootstrap(BalancedAccuracyMetric->New(), scores, actuals, 1000, 42);
```

- **A column in a sweep table:** today, a `Trial` cannot add columns (F12). With step 5 implement `MetricTrial` and return one number per column; before it, build the `ResultTable` yourself (`AddColumn`, `AddRow`), as `topic_lab.obs` does.
- **A library metric:** add a static `function` to `Metrics` that returns `0.0..1.0` or `-1.0` per C1 and name the failure value in `@return`; add a golden test against an independent script.

### A tokenizer

- **For topic modeling:** nothing to add to the library. `TokenDictionary->AddDocuments(Vector<Vector<String>>)` and `ToCorpus` take any token lists, so write a function from `String` to `Vector<String>` (or wrap a `TopicTokenizer` with your own stopwords through `TopicStopwords->FromArray`).
- **For subword ids (BERT, GPT-2):** implement `SubwordTokenizer` (`Encode`, `EncodePair`, `IsLoaded`, `GetError`), as `WordPieceTokenizer` and `BpeTokenizer` do; `BertEmbedder->New(model_path, tokenizer, max_len, config)` takes the `WordPieceTokenizer` class today, not the interface, so a different encoder needs that constructor widened.
- **For TF-IDF:** not possible without editing `TF_IDF` (its `Terms` calls `Tokenizer->WordTokenize`); the proposal is `TextTokenizer` plus `TF_IDF->SetTokenizer`.

### A layer (`System.ML.Cnn`)

Closed by design: the layers are native. A user cannot add one; a contributor adds one in these places, in this order:

1. a layer class with `Forward`, `Backward`, parameters and gradients in `core/lib/matrix/cnn.h`;
2. a new `kind` case in `ml_cnn_add` in `core/lib/matrix/cnn_api.h` (today 0 conv, 1 max pool, 2 ReLU, 3 flatten, 4 dense, 5 dropout);
3. an `AddX(...) ~ Bool` wrapper in `ml_cnn.obs` that calls the private `AddLayer(kind, a, b, c, d, rate)`, with the doc comment's failure value named;
4. a finite-difference check in `programs/regression/ml_cnn_gradcheck.obs` (it runs on the float64 reference model) and a parity fixture from `tools/ml/cnn_parity.py` for `ml_cnn_parity.obs`;
5. the CNN section of `docs/AI.md`, the API index, and the rebuilt native library on every platform (the header-only `cnn.h` needs no new build file).

For `DenseNetwork` the same limit applies to `DenseNetwork->Activation`, an enum handled in `Activate` and `ApplyDerivative`.

### A coherence measure (`System.NLP.Topics`)

`TopicMetrics->UMass`, `CNpmi` and `CV` are static functions of `Vector<TopicTerms>` plus a corpus or token windows, and `TopicTerms` has public getters (`GetWords`, `GetIds`, `GetWeights`). So a user writes `function : MyCoherence(topics : Vector<TopicTerms>, texts : Vector<Vector<String>>) ~ Float[]` with one value per topic, and uses it beside the library's (the example's `Coherence(m, d, docs, "c_v")` helper is exactly this wrapper). There is no interface, so a sweep cannot take a measure as a parameter; the proposed one is `TopicCoherence { Score(topics, texts) ~ Float[] }` and a `MetricTrial` that calls it. A library measure goes next to `UMass` in `nlp_topics_metrics.obs` with a reference value from `programs/regression/nlp_topics_reference.py` (Gensim).

### A distribution or test (`System.Stats`)

Add a `function` to `Dist` (CDF, survival function, quantile, NaN for arguments outside the domain), then a test class that returns a result object with `IsValid()`, `GetError()` and `ToString()`, as `TTest` does. Add the case to `tools/stats/gen_stats_reference.py` so the expected numbers come from scipy, then a `programs/regression/stats_<topic>.obs` with `# EXTRA_LIBS: stats,gen_collect` that exits non-zero on a mismatch. A user can write a test without editing the library: every `Dist` function and `Stats` function is public and takes plain `Float`s.

### A chart (`System.Plot`)

A user adds a plot type without editing the library only by drawing onto a `PlotScene` (`Line`, `Polyline`, `Polygon`, `Rect`, `Circle`, `Text`), the way `TopicPlots` does, and handing the SVG string to `Report->AddFigure`. A library chart is a method on `Axes` that adds an `Artist` and draws it in `Axes->Draw`, with a golden SVG under `programs/regression/plot_golden/`.

### A dataset loader

Return the shapes of C4: `String[]` texts and `Bool[]` labels from a `CsvTable` through `Labels->Column` and `Labels->ToBinary`; a `Vector<String>` from `BsonReader->ExtractStrings(field)`; images through `ImageDataset->AddDirectory` or `AddPixels(Byte[], class)`. A new format reader follows `BsonReader`: it never ends the program, returns `Nil` and a position-bearing `GetError()` on bad input, and checks every length against the bytes that remain (the fuzz lesson of [NEGATIVE_AND_FUZZ_TESTING_2026_11.md](NEGATIVE_AND_FUZZ_TESTING_2026_11.md)).

## Short names

The compiler resolves a library's generic arguments by short class name, so two classes with one short name in two libraries can swap silently. Every class, interface and enum in `core/compiler/lib_src` on `master` plus the eight new or changed sources of the four branches was scanned for duplicate short names, and the new names were also compared with the API index `tools/lsp/server/objk_apis.json` (632 names). Result:

- No new top-level class duplicates an existing one: not `Stats`, `Dist`, `Design`, `Correlation`, `OLS`, `TTest`, `Lda`, `TopicTerms`, `TopicCorpus`, `CnnModel`, `Augmentation`, `ImageDataset`, `ImageSubset`, `CnnTrainer`, `TrainingHistory`, `CnnEvaluation`, `BertEmbedder`, `SpellChecker`, `TextFeatures`. The nested enums `Padding`, `Initializer`, `Pooling`, `Layers` are only referred to as `Class->Enum`.
- `Proxy` (private) is now defined by `System.ML.Cnn` as well as by `ml_core`, `cipher`, `diags`, `lame`, `odbc`, `onnx`, `opencv`, `sdl2` and `sdl_gl`. Each is private to its bundle and the pattern predates the review; it is listed so the check below can allow it.
- `TreeNode` is defined by `gen_collect` and by `ml_tree`: an existing collision, unrelated to the new libraries.
- Short names that are generic and so likelier to collide in the next library: `Sample`, `Split`, `Prediction`, `Figure`, `Chart`, `Design`, `Stats`. The names proposed here (`Transformer`, `Classifier`, `Regressor`, `TextTransformer`, `TextTokenizer`, `MetricTrial`, `Replicates`, `Compare`, `ResultTables`, `Report`) are all absent from the index. `Result` and `Task` are taken by other libraries, which is why nothing here is called that.

A CI check that fails on a new duplicate (step 11) makes this review unnecessary the next time.
